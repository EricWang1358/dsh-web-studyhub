# Generation reliability corrections

Updated for the September 30 single-review requirement. The original provider transcripts were not replayed; failures and current review receipts were inspected read-only.

- Every part has an author/self-check call followed by **one independent review call**. Passing, locally valid cards are checkpointed; failed candidates are omitted with specific reasons. There is no second audit or refill loop to reach the requested count, and no automatic content repair; the only automatic repair is the one citation repair described under *Grounding quotes* below. Explicit `draft.repair` remains a separate requested operation.
- Unattributed concerns and unusable review protocols cannot grant acceptance. A review reply that is cut off, not JSON, has wrong IDs or lacks a complete per-card check is asked again, at most twice (`REVIEW_REASKS`): the first re-ask names what was wrong, the second carries the exact format, and a truncated reply keeps the complete checks parsed so far so that only the cards still without one are asked for (the payload is unchanged, a `reask` field is appended, so the provider's prompt cache still applies). Every re-ask is a model call of the job (`kind: review`, `retry: n`, its tokens counted). Only after the re-asks does the part fail, with a typed error (`code: 'review-protocol'`, `attempts`); the part keeps its authored candidates and the automatic fill rounds review them again (below). The publish path keeps its single re-ask. Author self-checks are diagnostic; they do not replace independent approval. Requested-kind mismatches are attributed to individual cards so passing peers survive.
- Author JSON recovery extracts only complete objects from the `cards` array. Literal control characters use the existing lossless JSON-string parser; broken/truncated objects are discarded. If no cards can be recovered, one corrective author JSON retry is allowed. Recovered text must still pass structural, citation, local and independent editorial checks. This is not arbitrary JSON repair or recovery of unreviewed work as approved cards.
- Planning requires an `answerability` declaration: `mode` (`recall`, `discrimination`, `application`), `requiredContextAvailable`, `answerOnlyInSourceList`, and `criteriaWouldRevealAnswer`. Missing/infeasible declarations receive the existing single corrective plan retry. Foundational recall is valid: self-containment does not require the answer to be derivable from the stem.
- `generate.constraints` accepts boolean `topicNoAnswer`, `hintNoAnswer`, `oneTargetPerStem`, and `optionsSameAxis`. These travel through planning, writing, review and continuation. Topic/hint lint checks sufficiently distinctive complete answers or correct options after case, Unicode and punctuation normalization, excluding terms already in the stem. It does not detect all synonyms or implication-based leaks. One-target and same-axis requirements still need semantic review.
- A single stable draft ID and requested title were already used across parts. Existing cross-part prompt/objective deduplication now also ignores punctuation. Semantic paraphrases are not guaranteed to be caught. Reviewers are explicitly told they assess an assigned subset, not whole-course coverage.
- `job.wait.draft.draftVersion` exposes the current saved version. `draft.get {id}` returns the full current draft and version for review before publication. Publication retains stale-version protection; do not guess versions or bypass it with a `latest` token.

The total job budget and per-call timeout remain bounded. A normal `generate` keeps approved draft checkpoints when interrupted. Authorized `supplement` finalizes its approved checkpoint at the scheduler's total deadline without new model calls: unchanged independent receipts are required, and version, citation, target, duplicate and atomic cancellation checks still apply. User cancellation blocks this finalization. Unchecked or modified candidates remain rejected; partial output is reported as partial.

Current accepted-card summaries are separate from candidate-review notes and omitted-candidate reasons. Pending checkpoints do not report unreviewed candidates as final editorial rejections. Both original generation and supplementation collect phase output in the plugin; only the final task notice is sent to the parent.

Regression coverage includes the one-review call cap, stable card IDs/receipts, partial and malformed author output, literal controls, protocol failures, local leaks, per-card kind mismatch, planning feasibility, requested title preservation, total-budget publication without model calls, cancellation while workers are stopping, target archival and changed receipts.

## Grounding quotes in a big selection

A generated question cites `{ sourceId, quote }`; the quote must be on the cited page. A 36-page MinerU selection used to lose most of its questions to this check (“the quoted source text could not be found”) although the quotes were real. What changed, in `lib/quote-match.js`, `lib/batch.js`, `lib/assessment-quality.js` and `lib/generation.js`:

- **One tolerant comparison** for the plan, the author, the repair and publishing. The key keeps only letters and digits (after NFKC and lower case), so line-end hyphenation, markdown (`**`, `#`, `|`, `$…$`, `\_`), HTML tables and entities, typographic quotes, dashes, ligatures, soft hyphens and emoji bullets no longer matter, while wording, numbers and order still do. An elided quote (`…`, `...`, `[...]`) must have each piece (6+ letters) on the page, in order. A quote may run over the end of its page into the neighbouring page. An invented or altered quote is still rejected.
- **Pages**: every slice of a long source counts as one page (a later slice used to be unreachable). A citation that names a wrong or garbled page id but whose quote is verbatim on another page of the same group is pointed at that page without a model call.
- **Split rule for a big selection** (comment in `lib/batch.js`): by page ranges. A group is a run of whole consecutive pages of at most 60,000 characters that is asked for at most 10 questions (`MAX_PLAN_TARGETS`), so a planning call has few quotes to ground and a stubborn quote cannot sink a dozen. A part (at most 5 questions) is written from, and checked against, only the pages its own targets cite plus the neighbour a quote runs into.
- **One retry, not a loop**: the plan keeps its single corrective round, which now names the full quote that was not found and the page ids that may be quoted. If targets still cannot be grounded, the verified targets are kept (the lost ones are recorded) instead of failing the whole group. After the author call, cards whose quotes are not on their pages get one citation repair: the model is given the exact quotes that were not found and the allowed page ids and returns citations only. Cards that are still wrong are dropped with their reason, as before.
- **Failed parts are run again**: after the first pass, at most `fillRounds` rounds run the parts that kept no question again: a part whose review failed is reviewed again from its retained candidates (no plan, answer or author call), a part with no usable output is written again from its plan, a part whose planning failed is planned again by itself. A stop, a spent time budget or a refused key ends it. After the rounds the part stays failed with its last true reason (`Part 8: Review protocol failed after 9 attempts: ...`).
- **Plans are kept**: `editorial.partPlans[]` = per part `{ part, sourceIds, targets: [{ targetId, objective, sourceId, quote?, status: kept|failed|omitted, reason? }], status, reason?, attempts }` (at most 400 targets in all, quotes at most 200 characters; lib/plan-record.js), failed parts included; a continuation appends its parts after the earlier ones.
- **One description of a failure**: lib/generation-failure.js names the cause (`review-protocol`, `quote`, `plan`, `quality`, `quota`, `credential`, `budget`, `cancelled`, `no-reply`, `rate-limit`, `timeout`, `unavailable`, else unknown); ui/generation-status.js `describeFailure` says it in plain words (`{ code, title, cause, retried, hint }`) for the draft banner, the generation record list and the console's failed calls.
- **Reporting**: the draft carries `editorial.partReport` (`total`, `passed`, `partial`, `failed`, `reasons: { <code>: n }`, per part `attempts` when it ran more than once, `citationsRepaired`) and the job carries the same as `job.partReport` with a one-sentence `summary` in the job's language (for example “5 个部分的引用在资料里找不到”). The draft page and the job card show it; `job.wait` of a short draft says to top it up with `generate { resumeDraftId, draftVersion }`, which keeps the passing questions and writes only the missing ones; what a draft still lacks is read as sections, not as a count: `coverage.get { draftId }` and `generate { resumeDraftId, draftVersion, coverage: { sectionIds? } }` (docs/coverage.md).
