# Generation reliability corrections

Based on the September 28 report of three 12-question jobs. The report is user-provided evidence; the original model transcripts were not replayed.

- A part now checkpoints its independently approved, locally valid, unchanged cards **before** repairing rejected cards. Serialized draft writes keep optimistic version checks. A repair error or cancellation retains this checkpoint.
- One repair round remains the limit. Only repair candidates receive a fresh independent review; unchanged approved text retains its original checks and fingerprints. Unattributed initial concerns block early acceptance. Unattributed repair concerns reject that repair subset. There is no extra model review merely because rejected cards were removed.
- Author JSON recovery extracts only complete, individually parseable objects from the `cards` array. Broken/truncated objects are discarded. If no cards can be recovered, one corrective JSON retry is allowed. Recovered text must still pass structural, citation, local and independent editorial checks. This is not arbitrary JSON repair or recovery of unreviewed work as approved cards.
- Planning requires an `answerability` declaration: `mode` (`recall`, `discrimination`, `application`), `requiredContextAvailable`, `answerOnlyInSourceList`, and `criteriaWouldRevealAnswer`. Missing/infeasible declarations receive the existing single corrective plan retry. Foundational recall is valid: self-containment does not require the answer to be derivable from the stem.
- `generate.constraints` accepts boolean `topicNoAnswer`, `hintNoAnswer`, `oneTargetPerStem`, and `optionsSameAxis`. These travel through planning, writing, repair, review and continuation. Topic/hint lint checks sufficiently distinctive complete answers or correct options after case, Unicode and punctuation normalization, excluding terms already in the stem. It does not detect all synonyms or implication-based leaks. One-target and same-axis requirements still need semantic review. Prior findings accompany the independent repair review.
- A single stable draft ID and requested title were already used across parts. Existing cross-part prompt/objective deduplication now also ignores punctuation. Semantic paraphrases are not guaranteed to be caught. Reviewers are explicitly told they assess an assigned subset, not whole-course coverage.
- `job.wait.draft.draftVersion` exposes the current saved version. `draft.get {id}` returns the full current draft and version for review before publication. Publication retains stale-version protection; do not guess versions or bypass it with a `latest` token.

The total job budget and per-call timeout remain bounded. Checkpoint writes precede additional model work and do not use the model cancellation signal. No model call or quality gate is skipped to fill a requested count; partial output is reported as partial.

Regression coverage includes repair failure after an early checkpoint, stable card IDs and receipts, malformed/truncated author output, literal topic/hint leaks, infeasible planning versus legitimate recall, requested title preservation, current draft version discovery, and independent rejection of repaired text.
