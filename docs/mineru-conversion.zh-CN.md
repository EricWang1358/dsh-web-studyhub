# 用 MinerU 转换 PDF（在这台电脑上）

[English](mineru-conversion.md)

StudyHub 可以替你运行 MinerU，把 PDF 转成按页的文字。适合扫描版 PDF、公式或表格很多的书、中文教材，以及超过 200 页的书。你不需要安装桌面客户端、敲命令、拖文件，也不需要输入页码范围。

MinerU **在这台电脑上**运行：不上传任何内容，也不需要令牌。StudyHub 用一个按钮替你装好它。

MinerU 转换属于「StudyHub · 音频」组件。这个组件关闭时，只有「高级」里的手动路线可用。

## 一键安装

打开「设置 › PDF 转换（MinerU）」，点「一键安装」，设置就这一步。还没装好时，在导入窗口里选好 PDF 后，同一张卡片也会直接出现在那里，不用离开窗口去设置页。

安装分六步，一步做完才做下一步。卡片上会显示正在做哪一步（“第 2/6 步：准备 Python”）、进度条、这一步最后输出的一行，以及六个步骤的列表：

1. **准备安装工具**：StudyHub 下载固定版本的 `uv`（一个小巧的 Python 包管理工具），并校验 sha256。
2. **准备 Python**：`uv` 把它自己的 Python 3.12 下载到安装文件夹里。电脑上已有的 Python 默认不用，除非你在「更多」里选它。
3. **安装 MinerU**：`mineru>=4.0,<5` 基础包（Windows 上不装 PyTorch）。
4. **下载模型**：所选档位的模型。
5. **启用本机服务**：用这个档位启动本机服务。
6. **检查能不能用**：服务必须回答“可以用这个档位解析”。

- 不需要管理员权限，不需要事先装任何东西，也不改任何系统设置。
- 所有东西都放在一个文件夹里：程序、Python、模型和 MinerU 自己的设置（`MINERU_HOME`）。不会写到 `~/.mineru`。
- 下载约 1.3 GB，占用约 4 GB，约 10–30 分钟（都是估算，取决于网络和电脑）。
- 可以离开这个页面：安装也会显示在「任务」里。安装时请不要关闭 StudyHub。
- 「取消」会保留已下载的部分；之后点「继续安装」从停下的那一步接着装，已完成的步骤会跳过。

## 安装位置（默认不在系统盘）

默认文件夹是除系统盘以外、剩余空间最大的那块固定磁盘上的 `X:\StudyHub\MinerU`，例如 `D:\StudyHub\MinerU`。文件夹下面的提示会说明原因（“默认装在剩余空间最大的非系统盘（D:，剩余 118 GB），不占用 C 盘”）。

- 电脑只有系统盘时，提示会说明，并装在系统盘上。
- 「选择位置」会列出每块磁盘：将要使用的文件夹和剩余空间。推荐的那块有「推荐」标记，系统盘标「系统盘」，空间不够的标「空间不够」。点一块磁盘立即生效。
- 「其他文件夹…」：宿主有文件夹选择器时打开它；没有时，直接输入完整路径，再点「使用这个位置」。
- 文件夹里已经有别的文件时不会动它们：StudyHub 会在里面新建一个 `StudyHub-MinerU` 文件夹来装。
- 文件夹不能写入、磁盘剩余空间不够（会写明数字）、或路径超过 80 个字符（Windows 上路径太长，Python 深层的包会加载失败）时，按钮不可用，并说明原因。路径里有中文或特殊字符时会提醒：个别组件可能加载失败。
- macOS 和 Linux 上装在 DSH 主目录下 StudyHub 的数据文件夹里。

文件夹以外只写一个小文件：`<DSH 主目录>/study/mineru-install.json`（安装状态，小于 10 KB）。

## 下载源

有两种下载源，「自动」会选其中一种：

| 下载的内容 | 国内镜像（国内直连） | 海外官方源（需海外网络） |
|---|---|---|
| 安装工具（`uv` 安装包） | 清华 PyPI 镜像 `pypi.tuna.tsinghua.edu.cn` | `pypi.org` |
| Python 3.12 | npmmirror `registry.npmmirror.com` | GitHub Releases |
| Python 包 | 清华 PyPI 镜像 | `pypi.org` |
| 模型 | 魔搭 ModelScope（`--source modelscope`） | Hugging Face（`--source huggingface`） |

- 「自动」只在卡片规划安装时，向两组地址各发几次不带身份信息的 HEAD 请求（每次 3 秒）。海外那组没有响应就选国内镜像；国内那组没有响应就选海外官方源；都通时选更快的一组，差不多快时选国内镜像。下载源旁边的标记会说明选了哪个、为什么。
- 也可以在「更多 › 下载源」里自己选。「修复」和换档位会沿用这次安装的下载源。
- 同一个下载源连续两次网络失败后，修复按钮会变成「换下载源重试」。

## 状态说明

卡片始终用一句话说明 MinerU 现在的状态：

| 状态 | 意思 | 怎么做 |
|---|---|---|
| **检测中** | StudyHub 正在读取状态。 | 不用做什么。 |
| **未安装** | 这台电脑上还没有可用的 MinerU。 | 点「一键安装」。 |
| **安装中** | “第 n/6 步”和这一步的名字。 | 等它完成，或点「取消」。 |
| **已安装 · 服务未启动** | MinerU 已装好，本机服务没在运行（例如电脑重启之后）。 | 不用管：开始解析时会自动启动。也可以点「启动服务」。 |
| **可以用了** | MinerU 的版本、档位和安装位置。 | 开始解析。 |
| **出错** | 原因，以及唯一的一个修复按钮。 | 点它（见下文）。 |

「重新检测」会再读一次状态。卡片打开且 MinerU 已安装时，每 30 秒也会再读一次。

## 服务与重启（自动启动）

MinerU 靠一个在后台运行的本机服务来解析。电脑重启后它会停，关闭 StudyHub 后也可能停。

- 解析时发现服务停了，会先启动它：卡片上写着“正在启动本机 MinerU 服务（第一次约 1 分钟）”，然后再开始解析。这一步在本机完成，不花 token。
- 服务启动不了时，这次解析会失败并说明原因；点「接着做」会再试一次。
- 「更多 › 停止服务」可以停掉它（运行时会占用内存）；有 MinerU 解析正在进行时不能停。

## 换档位

- `basic`（默认）：只用 CPU，模型约 0.8 GB，每页约 1.6 秒（估算）。适合以文字、公式、表格为主的书。
- `standard`：版面理解更好，模型约 2 GB，每页约 2.5 秒（估算），建议 16 GB 内存（卡片会显示这台电脑的内存）。

可以在安装前到「更多 › 模型档位」里选；装好后也可以点「换成 {档位} 档」：只有下载模型、启用本机服务和检查这三步真正做事。

速度是在一台只用 CPU 的笔记本上量过一次的，始终标明是估算。

## 卸载与移动

- 「更多 › 卸载」会先确认。它先停止本机服务，再删除 StudyHub 在文件夹里创建的内容：`tools`、`python`、`venv`、`home`、`cache`、`tmp` 和标记文件 `.studyhub-mineru.json`，然后删除这个文件夹和安装时新建的上级文件夹（都只在它们已经为空时）。不是 StudyHub 创建的文件不会动，已经转换好的资料也不受影响。有 MinerU 解析正在进行时不能卸载。
- 「更多 › 安装到其他位置…」会装到新文件夹（模型校验通过时直接复制），新位置通过检查后才删除旧的那一份；失败时旧的仍然可用。
- StudyHub 只会在带有自己标记文件的文件夹里删除东西，从不递归删除整个文件夹。

## 出错怎么办

每种失败都会写明停在哪里、原因，以及一个按钮：

| 问题 | 按钮 | 做什么 |
|---|---|---|
| 网络或校验失败 | 「重试」 | 从停下的那一步接着装，已下载的部分不会重下。 |
| 同一个下载源连续两次网络失败 | 「换下载源重试」 | 换成另一个下载源再装。 |
| 已取消，或安装时 StudyHub 被关闭 | 「继续安装」 | 从停下的那一步接着装。 |
| 空间不够、没有写入权限、文件夹已被占用、路径不能用或太长 | 「换位置」 | 打开磁盘列表。 |
| 安装 MinerU、下载模型或检查没有通过 | 「修复」 | 重新检查每一步，只补装缺少的部分。 |
| 本机服务没能启动 | 「重新启动服务」 | 先停止再启动。 |
| 另一份 MinerU 占用了同一个端口 | 「停止另一份 MinerU 并重试」 | 停掉那一份的服务，再启动这一份。 |
| 缺少微软 VC++ 运行库 | 「下载 VC++ 运行库」 | 打开微软官方安装包（`aka.ms/vs/17/release/vc_redist.x64.exe`），装好后点「重试」。 |
| 读不出状态 | 「重新检测」 | 再读一次。 |

「更多」里还有安装日志（最近 200 行）和将要运行的命令。

## 自己装过 MinerU

设置了 `MINERU_BIN`，或者搜索路径上有 `mineru` 时，StudyHub 会用它，并显示「可以用了 · 你自己安装的」。StudyHub 只调用它，不改它的设置。两份都有时优先用 StudyHub 装的那一份，「更多」里会列出另一份。两个服务抢同一个端口时，出错卡片会提供停掉另一份的按钮。

## 不再有云端

MinerU 云端解析（MinerU 令牌、上传 PDF）在 3.5.5 版移除了：它的入口已经失效。旧的云端记录仍会显示在解析历史里，但不能接着做：重新选择这份 PDF，在本机解析即可。要求云端解析的请求会被拒绝，并说明该怎么做。

旧版本保存的令牌仍在 `<DSH 主目录>/study/mineru.json`。现在没有任何东西会读它，可以手动删除这个文件。环境变量 `MINERU_API_KEY` 也会被忽略。

## 转换一份 PDF

1. 打开「添加资料」，把 PDF 放进「文件」标签。如果它读不出文字（扫描件），或超过 8 MB，这一行会写明原因，转换面板就在它下面，文件已经在这台电脑上读好：直接做第 3 步。想主动转换一份 PDF（公式多、中文教材），就打开折叠的「PDF 解析」，点「选择 PDF 解析…」。
2. 文件只在这台电脑上读取；StudyHub 显示页数、大小、分段方式和估算时间。
3. 解析工具默认是 MinerU；在「解析工具」里改选 Marker 就用它。MinerU 还没装好时，安装卡片就在这里：点「一键安装」，等到「可以用了」。
4. 点「开始本地解析」。窗口会关闭，转换作为一个任务在后台运行。点之前不会运行任何东西。
5. 在「资料」页查看进度。结束时「信箱」里会收到一封信（你自己停止的不会）。

结果按转换文档导入：一页一份资料，按标题分章节，引用方式和手动拖入的 MinerU 文件完全一样。StudyHub 保留文字和图片说明，图片本身不导入。

想自己手动转换，打开「高级：桌面客户端和命令行」，再把结果拖进「添加资料」。StudyHub 能读哪些格式，见[大教材](large-documents.zh-CN.md)。

## 查看转换进度

转换和音频导入在同一个任务列表里，卡片显示在「资料」页。

- **按钮。**
  - 「停止（已解析好的段落会保留）」。
  - 「接着做（不重复已完成的段落）」。服务停了的话，会先启动服务。
  - 「知道了」：移除卡片，并删除它的临时文件。
- **进度。** 正在做的这一段（页码、已经用了多久、预计多久）、已完成的段和各自的用时，以及下一段大约多少页。一段运行时没有更细的进度，这不代表卡住了。
- **剩余时间。** 第一段完成之前不显示；之后说“约”。各段速度一致时给一个数，速度还不稳定时给一个范围（“预计还需约 15 分钟 到 40 分钟”）。
- **段很多时。** 超过 8 段的卡片显示一句汇总，例如「第 13 段 · 已完成 12 段」，并有「展开各段」开关；展开后的列表在卡片内换行。
- **运行环境。** 卡片和历史里的每一行都能显示「运行环境」，在转换开始时以只读方式记下：mineru 版本；档位及其含义；该档位的模型文件夹，用工具自己的命名（例如 `MinerU-4_models_onnx`）；只有 `mineru server status` 或 `mineru config show` 报告了设备才显示设备；分段方式；本机服务是否在运行。进行中的卡片还会写明模型放在哪里；历史记录里从不显示这个位置。
- **服务状态如实显示。**
  - 开始前的只读检查之后、每完成一段之后，显示“运行中”。
  - 某一段发现服务已停时，显示“已停止”；点「接着做」会先启动它。
  - 应用重启之后显示“无法确认”，直到你接着做。

### 一段正在运行时

`mineru parse --wait` 在结束之前什么也不输出，所以一段很长的解析可能好几分钟看不出动静。扫描版 PDF 的第一段尤其如此：要先加载模型，每一页还要做文字识别；电脑慢，就按比例更久。

因此一段运行期间，StudyHub 询问的是**服务**，从不碰解析本身，而且只用只读命令，一次一个：

- `mineru server status --json` 报告工作进程和解析服务的健康状态；它说有任务在忙时，再用 `mineru list parses --status pending|parsing --json`，按档位和页码范围对上这一段。
- 每 20 秒问一次，第一次在 5 秒后，只在一段运行期间问。
- 任何一次询问失败都只算“未知”，绝不算“卡住了”。

卡片上会显示下面其中一种，并带最后一次收到服务状态的时间：

- 「排队中」
- 「转换中」
- 「服务正在启动」
- 「转换中（服务还没有报告这一段）」
- 「无响应（已 3 分钟没有新状态）」，分钟数按实际
- 「服务已停止」
- 「未知（读不到服务的状态）」

只有两种情况会显示「无响应」：服务连续三次回答都说没有在解析也没有排队，并且已经两分钟没有任何动静；或者解析服务自己报告不健康。服务正忙于别的解析、或询问失败，都不会得出这个结论。

遇到「无响应」：先再等一会儿；一直没变化，就点「停止」，再选同一个 PDF。已完成的段会直接复用，只重做这一段。StudyHub 自己从不停止任何东西。

### 转换出错时

- **重启。** 每一段的状态保存在 DSH 主目录（`study/tmp/pdf-convert/…`），不在你的学习库里。重启后，被中断的转换显示为可以接着做的失败任务。
- **取消。** 取消的转换会删掉临时文件，但保留每段已完成的结果（很小，按文件哈希存放），所以再次转换同一个 PDF 时不会重复解析这些段。未完成的任务和保留的段 7 天后自动清除。
- **一段失败**或超时，会对半拆开重试（20 → 10 → 5 页），小一点的能做完就继续往下。拆到最小仍不行，任务会停下并说明原因；「接着做」只重试那一段。
- **有密码保护的 PDF** 读不了：先另存一份无密码的。

## 解析历史

每次转换都会留下一条记录，关掉任务卡片、重启应用后仍然在。在「添加资料」折叠的「PDF 解析」里点「解析历史」即可打开；「资料」页正在进行的卡片下方也会显示。

- **一行里有：**
  - 文件名、大小和页数，以及解析工具（MinerU 加档位，或 Marker；旧记录可能是云端）；
  - 状态：「进行中」「已完成」「没有完成」「已取消」或「被中断」；
  - 什么时候结束、用了多久（“3 分钟前 · 用时 4 分 20 秒”）；还在进行或被中断的，显示开始时间；
  - 结果：导入后的标题和页数。
- **导入了才算「已完成」。** 只有文档真的导入了，才算「已完成」；导入这一步失败的算「没有完成」，阶段是“保存为资料”。重启或崩溃时被打断的转换是「被中断」：没有结束时间，也没有用时，因为没人量过。
- **一行上能做什么：**
  - 打开已导入的资料；
  - 「接着做」失败或被中断的转换：缓存还在时只重做没完成的段，仍是同一条记录，并记下尝试次数（旧的云端记录不能接着做）；
  - 查看进行中转换的进度；
  - 「删除记录」，或「清空历史」（会先确认）。

  删除记录或清空历史**从不删除已导入的资料**。
- **存在哪里：**
  - 每次转换一个很小的文件，放在 `<学习库>/conversion-history/`，和学习库里其他任务记录 `audio-batches/` 放在一起。
  - 不在 DSH 主目录里会被清理的 `study/tmp`，也不在学习库导出的状态和备份里（任务记录本来就不在其中）。
- **记录里有什么：** 文件名和大小、页数、解析工具和档位、时间、状态、一句直白的原因和出错的阶段、已导入文档的 id 和标题、运行环境、书的各段（页码、状态和实测用时），以及这台电脑的速度。**不含文档内容、文件夹或临时路径。**
- **保留多久：** 最近 50 条，以及 90 天内的所有记录，取较多的一边；写入新记录时清理更旧的。

## 一本书是怎么转换的

1. **规划。** 不会离开电脑：读一遍 PDF 数页数。默认的方式会说明分段随这台电脑的速度调整；固定分段（测试和预览用的接口）会列出各段。
2. **一次一段。** StudyHub 运行 `mineru parse --tier <档位> --pages a-b --wait <秒> --json -o <文件> --force`。
   - 一定带 `--pages`，因为命令行默认只解析前 10 页。
   - 会检查 Markdown 里的 `<!-- page N of TOTAL -->` 分页标记：数量等于这一段的页数、都在这一段内、TOTAL 等于 PDF 页数，然后读成同一种页面结构。
3. **合并。**
   - 各段的页放回整本书里的位置（`page_idx + 起始页 − 1`）。
   - 图片名按段加前缀，避免重名；阅读顺序不变。
   - 整本书保持**原来的页数**；缺了哪一段，会明确说出缺哪几页。
4. **导入。** 走普通的文档导入，作为转换文档保存。

### 分段怎么定大小

StudyHub 不会事先把书切好，而是一次决定一段，按这台电脑实际的速度来。

- **大小。**
  - 最先几段是 **10、20、20 页**，这样第一个进度、第一个实测速度和第一个估算都来得快。
  - 之后每一段按最近几段量到的速度定大小，让它大约做 **75 秒**，**最少 5 页，最多 50 页**。第一段要加载模型，若它每页比后面慢得多，就不算进速度里。
  - 电脑慢或是扫描版的书会一直是小段，进度条大约每分钟动一次；快的电脑会增长到 50 页。最后一段包下剩下的页，所以结尾不会剩孤零零的几页。
- **重试。** 一段失败或超时，会对半拆开重试（20 → 10 → 5 页）；之后的段会比失败的那段小。服务已停、找不到命令、或你自己点了停止，都不会靠拆段来“解决”。
- **已转换的页，不管当初怎么分段，都不会再转换一次。**
  - 每段的结果按文件哈希、档位和覆盖的页码保存，连同用了几秒，所以恢复出来的段仍能说明这台电脑的速度。
  - 接着做或再次转换同一个文件时，从缓存里按页码读出这些范围，只规划剩下的部分。读不出来的缓存范围会重新转换；和更长的已完成范围重叠的会被忽略。
  - 任务文件夹里的结果文件按页码命名（`local-11-30.result.json`），而不是按顺序编号。
- **交给命令的等待时间**随电脑而变：
  - 至少 120 秒；
  - 每页 8 秒，或实测每页秒数的 3 倍，取较大的；
  - 一次运行的第一段再加 180 秒，用来加载模型。

  还没测过任何一段时，对这台电脑一无所知，所以第一段不会按猜测掐断：是否还在运行由存活状态和「停止」决定，只留一个 12 小时的防失控上限。

## 开发说明

- **安装**在 `lib/mineru-install.js`（各步骤、规划、`mineruEnv`、`effectiveMineru`），建立在共用引擎 `lib/tool-install.js` 上（文件夹、标记文件、状态、取消、卸载），另有 `lib/install-drives.js`、`lib/install-sources.js` 和 `lib/uv-bootstrap.js`。对应的操作是 `mineru.install.plan|start|status|cancel|uninstall` 和 `mineru.local.status|start|stop`。助手不能安装、卸载或停止服务：这些只在设置页里由你点。
- **任务控制台**里，安装默认是一行 `local-install`；打开运行时开关 `mineruInstall` 后是一个 `mineru-install` 任务。
- **测试**不联网：本地索引提供 `uv` 安装包，`tests/helpers/fake-uv.mjs` 代替 `uv`，`tests/helpers/fake-mineru-cli.mjs` 代替 `mineru` 和 `mineru-kit`。
- **测试和预览用的接口。**
  - `limits.windowPages` 可以恢复旧行为：每段固定这么多页，事先定好，不对半拆分。清单里的 `plan` 会写明任务用的是哪种：`{kind: 'adaptive', firstPages, rampPages, targetSeconds, minPages, maxPages}` 或 `{kind: 'fixed', windowPages}`。
  - `limits.livenessMs: 0` 可以关掉对服务的询问。
  - 各个数字在 `lib/mineru-local.js` 的 `LOCAL`（`livenessMs`、`livenessFirstMs`、`silentMs`、`idleProbes` 以及分段相关的数值）和 `lib/mineru-install.js` 的 `MINERU_INSTALL` 里。
- **还没有在真实安装上验证过**（量过之前都是估算或假设）：下载量和占用空间；`MINERU_HOME` 是否把模型和服务状态都留在安装文件夹里；`mineru-kit models download|verify` 的参数；`config set` 的键名；npmmirror 的 Python 镜像和清华的 `uv` 安装包能否配合固定版本的 `uv` 使用；全新的 Windows 是否需要 VC++ 运行库。
- **没有对真实命令行验证过：**
  - 这些只读命令在命令行解析的同时运行是否安全；
  - 除 `workers.parse_running`、`parse_queue_length`、`parse_server.local.healthy/starting`、`parses[].tier/page_range/status`（来自最初的一次调查）以外的字段名。
