# 用 MinerU 转换 PDF（云端或本地）

[English](mineru-conversion.md)

StudyHub 可以自己调用 MinerU，把 PDF 转成按页的文字（扫描件、公式、表格和中文都支持）。你不用装桌面客户端、不用手动拖文件，也不用自己写页码范围。

| | 本地 `mineru` | 云端（你自己的 MinerU 令牌） |
|---|---|---|
| 费用 | 免费 | **目前**免费，MinerU 的规则可能变化 |
| 是否离开你的电脑 | 不离开 | **PDF 会上传到 MinerU 的云端**（首次使用前 StudyHub 会明说并确认一次） |
| 需要 | 装好 `mineru`（`uv tool install "mineru>=4.0,<5"`）并下载模型 | 在 <https://mineru.net/apiManage/docs> 创建令牌，粘贴一次到**设置 → MinerU 云端解析** |
| 大书 | 每 50 页一个页段（`--pages a-b`），不切 PDF | 每段最多 200 页、180 MB；PDF 有章节书签时按章节切 |
| 进度 | 已完成的段数（「第 3/9 段」），一个页段里不假装有百分比 | MinerU 报告的已解析页数 ÷ 全书页数 |

**添加资料 → 用 MinerU 解析**会同时显示两种方式。本地可用时优先本地；否则设了令牌就优先云端；两者都没设好，同一个入口会带你完成设置。设置好并点「开始」之前，不会上传、也不会启动任何东西。桌面客户端和 `mineru parse --pages` 命令行仍保留在**高级**里（结果走普通的导入）。

## 一本书会经历什么

1. **规划**（不离开电脑）：读一遍 PDF 数页数，告诉你这本书会分**几段**处理。
2. **云端**，逐段、一次一段：切分（pdf-lib；本来就够小的 PDF 不重写）→ 申请上传地址 → 上传 → 每隔几秒查询 → 下载 → 保存这一段的 `content_list.json`。某段文件超过 180 MB 就对半再切，直到够小；单独一页就超限则给出明确错误。
   **本地**，逐个页段：`mineru parse --tier <档位> --pages a-b --wait <秒> --json -o <文件> --force`。一定带 `--pages`（命令行默认只解析前 10 页）。会检查 Markdown 里的 `<!-- page N of TOTAL -->` 分页标记（数量等于页段页数、都在页段内、TOTAL 等于 PDF 页数），再读成同一种页模型。
3. **合并**：各段的页按位置放回整本书（`page_idx + 起始页 − 1`），图片名按段加前缀避免重名，阅读顺序不变，整本书保持**原来的页数**（缺了哪一段会明确说出缺哪几页）。
4. **导入**：走普通的文档导入，作为转换文档：一页一份资料、按标题分章节，引用方式和手动拖入的 MinerU 文件完全一样。

它和音频导入在同一个任务列表里：真实进度、**停止**、**接着做**（已完成的段不会再上传或再解析）、**知道了**（移除卡片并删除临时文件），结束时信箱里有一封信。

## 出错了怎么办

- 每一段的状态保存在 DSH 主目录（`study/tmp/pdf-convert/…`），不在你的学习库里。重启后，被中断的转换会显示为可接着做的失败任务。
- 取消的转换会删掉临时文件，但保留每段已完成的结果（很小，按文件哈希存放），所以再导入同一个 PDF 不会重复解析这些段。7 天后自动忘记。
- 遇到限流会等一会儿再继续；短暂的网络问题会逐渐拉长间隔重试；排队太久会提示「比平时慢，不是失败」。令牌无效或过期会立刻停下并指向设置；本地服务停了会点名，并有「重新启动本地服务」按钮。
- 令牌保存在 `<DSH 主目录>/study/mineru.json`（或环境变量 `MINERU_API_KEY`），不在学习库、导出、备份或快照里，也不会出现在任何日志中。设置页只显示末四位。

## 解析历史

每次转换（云端或本地）都会留下一条记录，关掉任务卡片、重启应用后仍然在。入口在**添加资料 →「用 MinerU 解析」→ 解析历史**（旁边也有「解析历史」链接），以及**资料**页正在进行的卡片下面。

- **一行里有**：文件名、大小和页数、方式（云端，或本地加档位）、状态（进行中 / 已完成 / 没有完成 / 已取消 / 被中断）、什么时候结束和用了多久（「3 分钟前 · 用时 4 分 20 秒」）、结果（「已导入为「…」· 共 448 页」）。**只有文档真的导入了才算「已完成」**；导入这一步失败的算「没有完成」，阶段是「保存」。重启或崩溃时被打断的转换是**被中断**：没有结束时间，也没有用时，因为没人量过。
- **一行上能做什么**：打开已导入的资料（直接跳过去）；**接着做**失败或被中断的转换（缓存还在时只重做没完成的段；仍是同一条记录，并记下尝试次数）；查看进行中的转换（滚动到它的卡片）；**删除记录**；**清空历史**（会先确认）。删除记录或清空历史**从不删除已导入的资料**。
- **存在哪里**：每次转换一个很小的文件，在 `<学习库>/conversion-history/`（和学习库里其他任务记录 `audio-batches/` 放在一起），不在会被清理的 DSH 主目录 `study/tmp`，也不在学习库导出的状态和备份里（任务记录本来就不在其中）。记录里有文件名和大小、页数、方式和档位、时间、状态、一句大白话的原因和出错的阶段、已导入文档的编号和标题、运行环境（见下）、书的各段及其页码和状态；**没有文档内容、令牌、文件夹或临时路径**。
- **保留多久**：最近 50 条，以及 90 天内的所有记录，取多的那个；写入新记录时清理更旧的。

## 是什么在干活（运行环境）

任务卡片和历史里的每一行都能显示「运行环境」：转换开始时（只读）记下，随记录保存。

- **本地**：mineru 版本、档位及其含义（`standard`：版面理解更好，稍慢；`basic`：速度较快）、该档位正在用的模型文件夹（用真实工具的命名，例如 `MinerU-4_models_onnx` 或 `MinerU2.5-Pro-…-GGUF`）、模型放在哪（文件夹是指向别的盘的链接时会说明实际位置）、**只有 `mineru server status` 或 `mineru config show` 报告了设备才显示设备**（否则不贴 GPU/CPU 标签）、怎么按页处理（「每次 50 页，一段做完才前进」）、本地服务是否在运行。
- **云端**：MinerU、模型版本（`vlm`）和识别语言、用的是你保存的令牌（不会显示）、每段的上限（200 页 / 180 MB）和这本书的大小。
- **服务状态是诚实的，不靠轮询**：开始前的只读检查之后、每完成一段之后显示「运行中」；某一段发现服务已停时显示「已停止」（并带现有的「重新启动本地服务并接着做」按钮）；应用重启之后是「无法确认」，直到你接着做。页段运行期间不会向命令行询问任何东西，**转换也从不自己启动、停止或改动服务**。
- 超过 8 段的卡片显示「第 3/12 段 · 已完成 2 段」和「展开各段」开关；展开后的列表在卡片内换行，不会跑出边缘。

## 设置本地 mineru

StudyHub 只用只读命令检测（`mineru --version`、`mineru config get …`、`mineru server status`），报告一种状态：没装 / 需要模型 / 服务没运行 / 可用。它不会替你安装任何东西。点**启动本地服务**才会运行 `mineru server start`。**下载模型并启用本地解析**会先显示大小（`basic` 约 800 MB，`standard` 约 1.2 GB），你确认后才下载，可以取消，完成后设好档位和 `managed` 模式并启动服务。界面里的速度（`basic` 约每页 1.6 秒，`standard` 约每页 2.5 秒）是在一台只用 CPU 的笔记本上量过一次的，永远标明是估算。

## 用真实令牌检查云端路线

`MINERU_API_KEY=<令牌> node scripts/mineru-live-check.mjs` 用一个生成的两页小 PDF 做一次真实往返，并逐条报告 StudyHub 对 API 的假设；加 `--check-only` 只检查令牌。没有设置这个环境变量时它什么也不做。
