# 用 MinerU 转换 PDF（云端或本地）

[English](mineru-conversion.md)

StudyHub 可以替你运行 MinerU，把 PDF 转成按页的文字。扫描版 PDF、公式和表格多的书、中文教材，以及超过 200 页的书，都适合这样处理。你不用装桌面客户端，不用手动拖文件，也不用自己写页码范围。

MinerU 解析属于「StudyHub · 音频转写」组件。这个组件关闭时，只能用「高级」里的手动方式。

## 选择解析方式

| | 本地 `mineru` | 云端（你自己的 MinerU 令牌） |
|---|---|---|
| 费用 | 使用本机资源 | 按 MinerU 当前账户规则 |
| 什么会离开你的电脑 | 什么都不会 | **PDF 会上传到 MinerU 的云端**。首次使用前 StudyHub 会明说，并请你确认一次 |
| 需要什么 | 装好 `mineru`（`uv tool install "mineru>=4.0,<5"`）并下载模型 | 在 [mineru.net](https://mineru.net/apiManage/docs)（国内可用）创建令牌，在「设置 › PDF 转换（MinerU）」粘贴一次 |
| 大书怎么切 | 每段 5–50 页，按这台电脑实测的速度定大小；不切 PDF 文件本身（`--pages a-b`） | 每段最多 200 页、180 MB；PDF 有章节书签时按章节切 |
| 进度 | 已完成的段数（“第 3/9 段”）；一段内部不编造百分比 | MinerU 报告的已解析页数 / 全书页数 |

开始解析时，StudyHub 按这个顺序决定默认用哪种方式：

1. 本地已就绪，就用本地；
2. 否则设了令牌，就用云端；
3. 两者都没准备好，就带你设置云端。

开始前可以自己换。只有设置好某种方式并点了它的开始按钮，才会上传或启动任何东西。

## 转换一份 PDF

1. 打开「添加资料」，在「文件」标签里“扫描件、公式多，或超过 200 页的 PDF？”旁边点「用 MinerU 解析」。如果某个 PDF 刚因为太大没能导入，它下方的「大教材建议」卡片也能直接转换这个文件。
2. 点「选择 PDF」。文件只在这台电脑上读取；StudyHub 显示页数、大小和分段方式，例如“这本书会分 3 段处理”。
3. 在「用哪种方式解析」里选「本地 mineru」或「用 MinerU 云端解析」。
4. 第一次用云端时，勾选「我知道文档会上传到 MinerU 的云端，同意用云端解析」。只问一次，之后可以在设置里撤回。
5. 点「开始本地解析」或「开始云端解析」。窗口会关闭，转换作为一个任务在后台运行。
6. 在「资料」页查看进度。结束时「信箱」里会收到一封信（你自己停止的不会）。

结果按转换文档导入：一页一份资料，按标题分章节，引用方式和手动拖入的 MinerU 文件完全一样，不用再拖文件。StudyHub 保留文字和图片说明，图片本身不导入。

想自己手动转换，打开「高级：桌面客户端和命令行」，再把结果拖进「添加资料」。StudyHub 能读哪些格式，见[大教材](large-documents.zh-CN.md)。

## 设置云端解析

1. 打开「设置 › PDF 转换（MinerU）」，其中的分区叫「MinerU 云端解析」。
2. 在「云端（MinerU 令牌）」下打开 MinerU 的 API 管理页，创建一个令牌。账户、地区和收费要求以 MinerU 当前说明为准。
3. 粘贴令牌，点「保存并验证」。验证只发一次不含文档的请求。

验证结果会说明：令牌可用、无效或已过期，或者连不上 MinerU、MinerU 暂时不可用。

令牌放在哪里：

- 保存在 `<DSH 主目录>/study/mineru.json`（DeepSeek Harness，即 DSH 的主目录）；文件里没有时，读取环境变量 `MINERU_API_KEY`。
- 不进学习库、导出、备份或快照，也不出现在任何日志里。
- 设置页只显示末四位；「清除已保存的令牌」可以删掉它。
- 不要把令牌贴到对话里。

## 设置本地 mineru

StudyHub 不会替你安装 `mineru`。

1. 在终端运行 `uv tool install "mineru>=4.0,<5"`（需要先装好 uv）。
2. 打开「设置 › PDF 转换（MinerU）」，在「本地（mineru 命令行）」下点「重新检测」。StudyHub 会报告一种状态：没装、需要模型、服务没运行，或可用。
3. 服务没运行时，点「启动本地服务」。StudyHub 这时才会运行 `mineru server start`。
4. 缺模型时，在「选一个档位」里选档位，再点「下载模型并启用本地解析」。
   - 先显示大小：`basic` 约 800 MB，`standard` 约 1.2 GB。
   - 点「确认下载」后才开始下载，随时可以取消。
   - 下载完成后，StudyHub 设好档位和 `managed` 模式，并启动服务。

两个档位：

- `basic` 更快，适合以文字为主的书。
- `standard` 版面理解更好，稍慢。

界面里的速度（`basic` 每页约 1.6 秒，`standard` 约 2.5 秒）是在一台只用 CPU 的笔记本上量过一次的，始终标明是估算。

StudyHub 只用只读命令检测本地 `mineru`：`mineru --version`、`mineru config get …` 和 `mineru server status`。

## 查看转换进度

转换和音频导入在同一个任务列表里，卡片显示在「资料」页。

- **按钮。**
  - 「停止（已解析好的段落会保留）」。
  - 「接着做（不重复已完成的段落）」：已完成的段不会再上传或再解析。
  - 「知道了」：移除卡片，并删除它的临时文件。
- **进度。** 云端：已解析页数 / 全书页数。本地：正在做的这一段（页码、已经用了多久、预计多久）、已完成的段和各自的用时，以及下一段大约多少页。本地一段运行时没有更细的进度，这不代表卡住了。
- **剩余时间。** 第一段完成之前不显示；之后说“约”。各段速度一致时给一个数，速度还不稳定时给一个范围（“预计还需约 15 分钟 到 40 分钟”）。
- **段很多时。** 超过 8 段的卡片显示一句汇总，例如「第 13 段 · 已完成 12 段」，并有「展开各段」开关；展开后的列表在卡片内换行。
- **运行环境。** 卡片和历史里的每一行都能显示「运行环境」，在转换开始时以只读方式记下：
  - 本地：mineru 版本；档位及其含义；该档位的模型文件夹，用工具自己的命名（例如 `MinerU-4_models_onnx`）。进行中的卡片还会写明模型放在哪里（文件夹是指向别的盘的链接时，会说明实际位置）；历史记录里从不显示这个位置。
  - 本地（续）：只有 `mineru server status` 或 `mineru config show` 报告了设备才显示设备，否则不贴 GPU 或 CPU 标签；分段方式；本地服务是否在运行。
  - 云端：MinerU、模型版本（`vlm`）和识别语言；使用你保存的令牌（不会显示）；每段的上限（200 页 / 180 MB）；这本书的大小。
- **服务状态如实显示。**
  - 开始前的只读检查之后、每完成一段之后，显示“运行中”。
  - 某一段发现服务已停时，显示“已停止”，并提供「重新启动本地服务并接着做」。
  - 应用重启之后显示“无法确认”，直到你接着做。
  - 转换从不自己启动、停止或改动服务。

### 本地一段正在运行时

`mineru parse --wait` 在结束之前什么也不输出，所以一段很长的解析可能好几分钟看不出动静。扫描版 PDF 的第一段尤其如此：要先加载模型，每一页还要做文字识别；电脑慢，就按比例更久。

因此一段运行期间，StudyHub 询问的是**服务**，从不碰解析本身，而且只用只读命令，一次一个：

- `mineru server status --json` 报告工作进程和解析服务的健康状态；它说有任务在忙时，再用 `mineru list parses --status pending|parsing --json`，按档位和页码范围对上这一段。
- 每 20 秒问一次，第一次在 5 秒后，只在一段运行期间问。
- 任何一次询问失败都只算“未知”，绝不算“卡住了”。

卡片上会显示下面其中一种，并带最后一次收到服务状态的时间：

- 「排队中」
- 「转换中」
- 「服务正在启动」
- 「转换中（服务还没有报告这一段）」
- 「无响应（已 3 分钟没有新状态）」，分钟数按实际
- 「服务已停止」
- 「未知（读不到服务的状态）」

只有两种情况会显示「无响应」：服务连续三次回答都说没有在解析也没有排队，并且已经两分钟没有任何动静；或者解析服务自己报告不健康。服务正忙于别的解析、或询问失败，都不会得出这个结论。

遇到「无响应」：先再等一会儿；一直没变化，就点「停止」，再选同一个 PDF。已完成的段会直接复用，只重做这一段。StudyHub 自己从不停止任何东西。

## 出错了怎么办

- **重启。** 每一段的状态保存在 DSH 主目录（`study/tmp/pdf-convert/…`），不在你的学习库里。重启后，被中断的转换显示为可以接着做的失败任务。
- **取消。** 取消的转换会删掉临时文件，但保留每段已完成的结果（很小，按文件哈希存放），所以再次转换同一个 PDF 时不会重复解析这些段。未完成的任务和保留的段 7 天后自动清除。
- **云端。**
  - 遇到限流会等一会儿再继续；短暂的网络问题会逐渐拉长间隔重试。
  - 排队太久会提示“比平时慢”，而不是报失败。
  - 令牌无效或过期会立刻停下，并指向设置（「去设置里换一个令牌」）。
- **本地。**
  - 一段失败或超时，会对半拆开重试（20 → 10 → 5 页），小一点的能做完就继续往下。
  - 拆到最小仍不行，任务会停下并说明原因；「接着做」只重试那一段。
  - 服务停了会点名，并提供「重新启动本地服务并接着做」。
- **PDF 本身。**
  - 有密码保护的 PDF 没法拆分和上传：先另存一份无密码的。
  - 云端单独一页就超过大小上限时没法再拆小：先压缩这一页的图片，或改用桌面客户端。

## 解析历史

每次转换（云端或本地）都会留下一条记录，关掉任务卡片、重启应用后仍然在。在「添加资料」里点「用 MinerU 解析」旁边的「解析历史」即可打开；「资料」页正在进行的卡片下方也会显示。

- **一行里有：**
  - 文件名、大小和页数，以及解析方式（云端，或本地加档位）；
  - 状态：「进行中」「已完成」「没有完成」「已取消」或「被中断」；
  - 什么时候结束、用了多久（“3 分钟前 · 用时 4 分 20 秒”）；还在进行或被中断的，显示开始时间；
  - 结果：导入后的标题和页数。
- **导入了才算「已完成」。** 只有文档真的导入了，才算「已完成」；导入这一步失败的算「没有完成」，阶段是“保存为资料”。重启或崩溃时被打断的转换是「被中断」：没有结束时间，也没有用时，因为没人量过。
- **一行上能做什么：**
  - 打开已导入的资料；
  - 「接着做」失败或被中断的转换：缓存还在时只重做没完成的段，仍是同一条记录，并记下尝试次数；
  - 查看进行中转换的进度；
  - 「删除记录」，或「清空历史」（会先确认）。

  删除记录或清空历史**从不删除已导入的资料**。
- **存在哪里：**
  - 每次转换一个很小的文件，放在 `<学习库>/conversion-history/`，和学习库里其他任务记录 `audio-batches/` 放在一起。
  - 不在 DSH 主目录里会被清理的 `study/tmp`，也不在学习库导出的状态和备份里（任务记录本来就不在其中）。
- **记录里有什么：** 文件名和大小、页数、解析方式和档位、时间、状态、一句直白的原因和出错的阶段、已导入文档的 id 和标题、运行环境、书的各段（页码、状态和实测用时），本地转换还有这台电脑的速度。**不含文档内容、令牌、文件夹或临时路径。**
- **保留多久：** 最近 50 条，以及 90 天内的所有记录，取较多的一边；写入新记录时清理更旧的。

## 一本书是怎么转换的

1. **规划。** 不会离开电脑：读一遍 PDF 数页数。云端和固定分段的本地方式会告诉你这本书分几段处理；默认的本地方式会说明分段随这台电脑的速度调整。
2. **云端，一次一段：**
   1. 用 pdf-lib 切出这一段；本来就够小的 PDF 不会重写。
   2. 申请上传地址，然后上传。
   3. 每隔几秒查询一次，完成后下载结果。
   4. 保存这一段的 `content_list.json`。

   某段文件超过 180 MB 就对半再切，直到够小；单独一页就超限时，给出明确的错误。
3. **本地，一次一段。** StudyHub 运行 `mineru parse --tier <档位> --pages a-b --wait <秒> --json -o <文件> --force`。
   - 一定带 `--pages`，因为命令行默认只解析前 10 页。
   - 会检查 Markdown 里的 `<!-- page N of TOTAL -->` 分页标记：数量等于这一段的页数、都在这一段内、TOTAL 等于 PDF 页数，然后读成同一种页面结构。
4. **合并。**
   - 各段的页放回整本书里的位置（`page_idx + 起始页 − 1`）。
   - 图片名按段加前缀，避免重名；阅读顺序不变。
   - 整本书保持**原来的页数**；缺了哪一段，会明确说出缺哪几页。
5. **导入。** 走普通的文档导入，作为转换文档保存。

### 本地分段怎么定大小

本地方式不会事先把书切好，而是一次决定一段，按这台电脑实际的速度来。

- **大小。**
  - 最先几段是 **10、20、20 页**，这样第一个进度、第一个实测速度和第一个估算都来得快。
  - 之后每一段按最近几段量到的速度定大小，让它大约做 **75 秒**，**最少 5 页，最多 50 页**。第一段要加载模型，若它每页比后面慢得多，就不算进速度里。
  - 电脑慢或是扫描版的书会一直是小段，进度条大约每分钟动一次；快的电脑会增长到 50 页。最后一段包下剩下的页，所以结尾不会剩孤零零的几页。
- **重试。** 一段失败或超时，会对半拆开重试（20 → 10 → 5 页）；之后的段会比失败的那段小。服务已停、找不到命令、或你自己点了停止，都不会靠拆段来“解决”。
- **已转换的页，不管当初怎么分段，都不会再转换一次。**
  - 每段的结果按文件哈希、档位和覆盖的页码保存，连同用了几秒，所以恢复出来的段仍能说明这台电脑的速度。
  - 接着做或再次转换同一个文件时，从缓存里按页码读出这些范围，只规划剩下的部分。读不出来的缓存范围会重新转换；和更长的已完成范围重叠的会被忽略。
  - 任务文件夹里的结果文件按页码命名（`local-11-30.result.json`），而不是按顺序编号。
- **交给命令的等待时间**随电脑而变：
  - 至少 120 秒；
  - 每页 8 秒，或实测每页秒数的 3 倍，取较大的；
  - 一次运行的第一段再加 180 秒，用来加载模型。

  还没测过任何一段时，对这台电脑一无所知，所以第一段不会按猜测掐断：是否还在运行由存活状态和「停止」决定，只留一个 12 小时的防失控上限。

## 开发说明

- **测试和预览用的接口。**
  - `limits.windowPages` 可以恢复旧行为：每段固定这么多页，事先定好，不对半拆分。清单里的 `plan` 会写明任务用的是哪种：`{kind: 'adaptive', firstPages, rampPages, targetSeconds, minPages, maxPages}` 或 `{kind: 'fixed', windowPages}`。
  - `limits.livenessMs: 0` 可以关掉对服务的询问。
  - 各个数字都在 `lib/mineru-local.js` 的 `LOCAL` 里（`livenessMs`、`livenessFirstMs`、`silentMs`、`idleProbes` 以及分段相关的数值）。
- **没有对真实命令行验证过：**
  - 这些只读命令在命令行解析的同时运行是否安全；
  - 除 `workers.parse_running`、`parse_queue_length`、`parse_server.local.healthy/starting`、`parses[].tier/page_range/status`（来自最初的一次调查）以外的字段名。
- **用真实令牌检查云端路线。** `MINERU_API_KEY=<令牌> node scripts/mineru-live-check.mjs` 用一个生成的两页小 PDF 做一次真实往返，逐条报告 StudyHub 对 API 的假设；加 `--check-only` 只检查令牌。没有设置这个环境变量时，它什么也不做。
