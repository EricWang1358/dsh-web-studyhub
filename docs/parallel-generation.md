# 批次并行生成

一个题组先按原有 60,000 字符限制划分资料块，每个资料块统一规划该块全部题目的考点（含混合题型）。资料块之间预留已规划考点，所有规划完成后才开始出题。每批最多 5 题，最多 3 个批次同时执行；批次内部仍依次完成作者、自查、独立审阅与必要修复。

分配给某批的考点会随请求传给作者，其他批次考点列为已覆盖目标。汇总按原批次顺序进行，检查相同题干或考点的重复并报告删去项。文字相似但不完全相同的重复仍依赖模型规划和审阅识别。

各批有独立阶段上下文和通信句柄，补充要求广播到当前可通信的子代理，逐条返回实际投递凭证，并保留给后续模型调用。一个阶段结束只清理自身句柄，不影响其他批次。执行记录显示批次及阶段，题组顶部显示并行状态。

每完成一个批次，就把当前合格结果串行写入同一草稿；慢批次或失败批次不阻挡已通过题目的保存。写入使用草稿版本校验，用户修改会导致后台保存冲突，删除后不会自动重建。运行期间不能发布该草稿；结束后或重启后可以审阅已有成果。最终结果沿用同一个草稿 ID。

同一资料库的不同题组仍排队，以使该资料库最多运行 3 个批次，后续题组规划也能排除前面已保存的草稿考点。不同资料库有各自的队列。失败批次记录原因，成功批次不会因此重跑；本次未增加自动无限重试。

运行队列和未完成的模型任务仍在内存中：重启不能续跑它们，但已保存的草稿可恢复。旧进程中的现有任务不会自动变为并行，需要队列结束后重启后端。

验证使用可控延迟模型适配器：3 个批次确实重叠，一个慢批次未结束时其他批次已产生保存回调，4 批完成后合并 20 题，阶段上下文未串批。真实模型的吞吐和限流行为仍需运行验证。
