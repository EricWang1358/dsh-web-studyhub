# 音频导入：把录音转成中英对照逐字稿

把一段课堂录音变成中英对照逐字稿，存进「资料」，之后可以阅读、搜索和引用。StudyHub 会先转写，再校对识别错的术语，然后逐段翻译，最后存为一份资料。这里不出题；要出题，照常去「创建题组」。

## 准备什么

- **一个转写服务的密钥**，任选其一即可：

  | 服务商 | 费用与网络 | 用来做什么 | 单次请求或单个文件上限 |
  | --- | --- | --- | --- |
  | 硅基流动 SenseVoice | 以服务商当前规则为准 | 只做转写 | 50 MB、1 小时；更大的音频会切片 |
  | Groq | 以服务商当前规则为准 | 转写（Whisper）；校对和翻译走 Gemini 时也会用到它 | 25 MB；更大的音频会切片 |
  | Google Gemini（AI Studio）免费密钥 | 以服务商当前规则为准 | 转写、校对、翻译；「课堂实录」只支持它 | 1 小时；更长的录音会分段 |
  | Google Gemini 付费密钥（可选） | 按服务商计费 | 排在最后；勾选「只用付费密钥」时只用它 | 1 小时 |

- **一个做校对和翻译的模型。** 默认用 DSH 会话当前的模型。硅基流动做不了这两步，所以只配硅基流动时，需要有对话模型，或者另配 Gemini 或 Groq 密钥。
- **ffmpeg（可选）。** 只有 OGG、Opus、FLAC、WebM、AAC、AIFF 需要交给硅基流动或 Groq 切分、转换时才用到。MP3、WAV 和普通 M4A 都不需要。详见[为硅基流动和 Groq 切分音频](#为硅基流动和-groq-切分音频)。

## 配置转写服务

1. 打开「设置 › 音频转写」。每个服务商一张卡片，写着三步和对应链接。标着「推荐」的排在第一：中文界面是硅基流动 SenseVoice，英文界面是 Groq。
2. 按卡片上的步骤创建密钥并复制。

   | 服务商 | 在哪里创建密钥 |
   | --- | --- |
   | 硅基流动 SenseVoice | 在 [cloud.siliconflow.cn](https://cloud.siliconflow.cn) 用手机号注册并登录，再打开 [API 密钥页](https://cloud.siliconflow.cn/account/ak) |
   | Groq | [Groq 控制台 › API Keys](https://console.groq.com/keys) |
   | Google Gemini | [AI Studio › Get API key](https://aistudio.google.com/apikey)；这个项目不要开通计费 |

3. 把密钥粘贴到卡片里，点「保存并验证」。显示「可用：密钥有效，网络也连得上」就配好了。验证只向服务商查询模型列表，不会发送音频。

以后可以点「验证」重新检查已保存的密钥，点「清除已保存的密钥」删掉它。卡片上只显示「已保存」和密钥末四位。

还没配置任何服务时，「音频转写」页会用推荐服务商的步骤和密钥框代替拖放区，标题是「转写服务还没配置 · 约 2 分钟」。配好之前不会上传任何文件。字幕文件不需要转写，这时仍可以导入。

**Gemini 免费与付费密钥。** 免费密钥必须来自没有开通计费的 Google Cloud 项目：项目一旦开通计费，就没有免费额度了。付费密钥是可选的，填在「设置 › 音频转写 › 高级」的「Gemini 付费密钥（可选）」里，必须来自另一个已开通计费并充值的项目。

**密钥存在哪里。** 密钥只写进 DSH 用户目录（`~/.dsh`，设置了 `DSH_HOME` 时用它）下的 `study/audio.json`。这是明文文件，不加密。密钥不会进入学习库、备份、面板快照、任务记录或对话。文件里没有某个密钥时，会读取环境变量 `GEMINI_FREE_API_KEY`、`GEMINI_PAID_API_KEY`、`GROQ_API_KEY`、`SILICONFLOW_API_KEY`。不要把密钥贴到对话里。

## 导入录音

1. 打开左侧的「音频转写」。在「资料」页「添加资料」里选「音频 / 录音」，打开的是同一张表单。
2. 选一个或多个文件，不需要手输路径：
   - 拖到拖放区，或点它选择；
   - 展开「从工作区里找」，按文件名搜索后点选；
   - 点「在对话里用 @ 选文件」：它会把提示词预填进对话输入框，但不发送。用 DSH 输入框的 @ 选好文件再发送；选择框没弹出时，再按一次 @；
   - 展开「粘贴文件路径（高级）」，填绝对路径，带不带引号都行。
   放进「添加资料」「文件」标签里的录音和字幕文件会被带到这张表单里；在那里不会导入，也不会发送任何内容。
3. 等每个文件下方的检查结果（见[预检](#预检)）。检查只在本地读文件，不发送任何内容。
4. 可选，都在默认折叠的「更多设置」里：「逐字稿名称」「这段音频讲什么」「术语表」（逗号或换行分隔），以及不能交给免费服务的录音要勾的「只用付费密钥」（见[隐私](#隐私)）。课程就是「添加资料」顶部那一行（「归入…」，旁边有「更改」）；在「音频转写」页上，「更多设置」里会另外问课程。课程里已有的题组名和题目主题词会自动并进你的术语表，帮助转写和校对。「只用付费密钥」的默认值在「设置 › 音频转写」里修改。
5. 点「开始」。按钮会写明它要做什么：长录音写明时长、分几段、几次请求（例如「开始（约 95 分钟，分 2 段，2 次请求）」），几个录音写明它们会合成**一份**逐字稿（「开始（3 个录音合成 1 份逐字稿）」）。超过单次请求长度的录音由这一下无损分段，没有第二个按钮。之后可以先做别的；完成后，逐字稿会出现在「资料」页的「今天」分组里，卡片下面有「用它出题」。

「开始」上方会显示校对和翻译大约要用多少 token，详见 [token 用量与估算](token-usage.md)。录音是中文还是英文，转写之后才知道，所以这个范围同时涵盖英文和中文讲课；字幕文件的语言和长度是已知的，它的估算是准确的。字幕文件要等这个估算和你的一次点击：把它放进来不会启动任何模型。

### 支持的文件与上限

- **格式**：MP3、WAV、M4A、AAC、OGG、FLAC、OPUS、WEBM、AIFF（也接受 `.aif`）。
- **大小**：每个文件至多 512 MB。
- **时长**：能读出时长的格式（MP3、WAV、M4A）至多 8 小时；其他格式由服务商判断。
- **按内容识别格式**：只看文件内容，不看扩展名。改名成 `.mp3` 的 WAV 会按 WAV 处理，并给出提示。
- **会被拒绝的文件**：能识别的音频不到一半的 MP3。超过 1 小时的压缩编码 WAV（非 PCM），以及超过 1 小时又无法在本地切分的 M4A（例如分片格式 MP4），会提示先另存为 MP3。

### 预检

每个文件加入后马上检查一次，点「开始导入」时再查一次。所有文件都通过之前，不会向服务商发送任何内容。

| 文件下方的提示 | 意思 | 怎么做 |
| --- | --- | --- |
| 「约 N 分钟 · M 次转写请求」 | 可以导入 | 不用处理 |
| 「将无损分成 K 段转写（占用 M 次请求）」 | 一次请求放不下 | 不用处理：点「开始」就接受多出来的请求，按钮上写明了它们 |
| 一条错误说明 | 这个文件不能导入 | 点「跳过此文件继续」（多个文件时）或「换一个文件」 |
| 「等待「…」处理」或「因「…」未通过预检尚未开始」 | 要先处理另一个文件 | 先处理那个文件 |

排在第一的是硅基流动或 Groq 时，请求次数已算上它们的文件大小限制所需的切片。

### 多个文件合成一份逐字稿

一次选多个文件时，会按列表顺序合成一份逐字稿。拖动文件或用箭头按钮可以调整顺序。文件逐个处理，成稿里每个文件有一个小标题（`## 1. lecture-a.mp3`）。默认名称是第一个文件名加上其余文件的个数。

开始处理时，如果某个文件没通过检查，其余文件会等它，不会被取消。卡片上会出现「跳过此文件继续」和「修复后继续」。内容与前面某个文件相同的文件不会再发给服务商，直接复用前一个的结果。

### 字幕文件

从 B 站等网站下载的带时间戳字幕（SRT、VTT、JSON、TXT，至多 8 MB）跳过转写，直接校对和翻译，每段前面保留开始时间。字幕文件要单独导入，一次一个，不和音频混在一起。导入字幕不需要转写服务，只需要能做校对和翻译的模型。


预检按「每次请求最长」的当前设置判断录音能否切分；该值在「设置 › 音频转写 › 高级 › 专家选项」调整，范围为 5–59 分钟。提示显示实际选择的时限。
## 查看进度

任务卡片显示在「音频转写」页和「资料」页顶部，上面有：

- 当前步骤和第几段、「录音时长」和「已用」。前者是录音本身的长度，后者才是处理花的时间；
- 一条总进度条：转写占 25%，校对占 30%，翻译占 45%，每一步里按已完成的段数计。这些比例是估计；
- 某一段真正做完后，按实际速度给出「本步骤预计还需约 N 分钟」；
- 单个长请求进行时，进度条上有一格在流动，并写明不是卡住了：谁也无法知道单个请求做到了哪里；
- 「并行 N」：同时处理几个校对或翻译窗口；被限流时写成「并行 4（已因限流从 6 降到 4）」；
- 「正在执行 N 个任务」，列出每个请求的运行方式、已等待时间和输入大小；「查看历史任务」默认只列最近 5 条，其余用「再显示 N 条」展开，页面里没有嵌套滚动；每条一行（「校对 6/31 · 已完成 · 14 秒」），所有行相同的说明（运行方式、结果由插件直接回收）只在列表顶部说一次；推理强度只在「要求」和「实际」不同时才写；展开「详情」可看到输入大小、用量和答案开头；
- 校对或翻译交给 DSH 子代理时，有「查看子代理」，**只有当前 DSH 能打开那个子代理时才显示**，不会点了才告诉你不能用；子代理在 DSH 里的名字是「Study ＜编号＞ · 音频校对 · 文件名 · 1/31」；
- 提示，例如换了服务商，或去掉了某个转写选项。

随时可以点「停止（已转写的部分会保留）」。

信箱按实际处理顺序通知：

1. 「录音文件已转录成功」
2. 「录音文件已校对润色」；有窗口校对失败、保留了原转写时，是「录音校对部分未完成」
3. 「录音文件已翻译成功」
4. 全部保存后是「录音处理完成」，否则是「录音处理未完成」

续做时，已经保存过的步骤不会再通知一次。多个文件合成的导入只在最后通知一次。点通知会打开保存好的逐字稿；还没保存时打开「音频转写」页。通知保存在学习库里。

## 核对逐字稿

在卡片上点「打开逐字稿」，或在「资料」里打开它。录音原文总在前面，标签跟随导入时的界面语言。中文界面下的成稿是这样：

```
================================================================================
《lecture.mp3》全量中英对照逐字稿
Full Bilingual Transcript: <英文标题>
================================================================================

【第一部分：<中文标题>】
[Part 1: <English title>]

【英文原句】
<校对后的英文段落，空行分隔>

【中文对照】
<对应的中文段落，空行分隔>

---

【第二部分：……】
```

- **英文界面**：标题行是 `Full Bilingual Transcript: lecture.mp3`，每部分只有英文标题，标签是 `[English original]` 和 `[Chinese translation]`。
- **中文录音**：转写结果以中文为主时，改为译成英文，标签变成【中文原文】和【英文对照】（英文界面是 `[Chinese original]` 和 `[English translation]`）。
- **很长的逐字稿**：超过约 40 万字符时，在部分之间拆成多份资料，编号顺延。

**校对结果。** 资料视图里有一个折叠区「校对改动 N 处 · 未改动的存疑处 M 处」，先列出每处改动及其理由和上下文，再列出没有改动的存疑处。点「让模型复核这 N 处」，文本模型会结合所在段落和译文再判断一次：

- 能确定的，直接改进正稿，译文里的同一处一起改，每一份都改；
- 判定原文无误的，从列表里移除；
- 仍拿不准的，继续留在列表里。

每处只复核一次。不提供说话人区分和逐词时间戳。

## 停止、续做与重新导入

每段转写、每个校对窗口、每个翻译部分和标题，做完就立即保存。

- **接着做。** 失败、停止或 DSH 重启后，任务卡会重新出现，上面有「接着做（不重复付费）」。它按当前设置、用已保存的部分完成原来提交的内容。不用重新选文件，卡片上写着已保存了多少（「已保存：转写 3/3 · 校对 2/5」）。
- **上传的文件**会保留到导入成功或你删除这个任务（「知道了」只是归档，文件仍然保留；删除任务才会清理这份工作副本）。从工作区或路径选的文件直接读原文件，不复制，所以它必须还在、内容没变；否则请当作新录音重新导入，免得把旧进度接到别的录音上。
- **校对出错。** 某个窗口失败时保留原转写，其余继续。连续两个窗口出现同样的错误时任务会停下，免得每个窗口都白白消耗额度。
- **通知。** 点「接着做」后，旧的「录音处理未完成」通知会撤掉；再失败会有新的通知。
- **旧版失败任务。** 旧版本没有保存任务记录，这类任务显示「重新选择原录音继续」。请选同一份录音（文件名相同），并核对课程和术语表：旧的提交参数没有保存，所以不提供一键续做。内容和设置相同的已存部分仍会复用。新任务开始后，旧通知才移除。

**再次导入时会重做什么：**

| 改了什么 | 重做什么 |
| --- | --- |
| 什么都没改（内容和设置相同），即使文件名不同 | 不重做，直接复用已有资料。两份同时开始时，后一份等前一份做完 |
| 术语表、「这段音频讲什么」、课程、推理档位，或校对与翻译用的模型 | 重做校对、翻译和标题，转写结果复用；另存为一份新资料，与旧的并存 |
| 只改了转写模型、「转写风格」，或改变了切分点的「每次请求最长」 | 「资料」里还有之前的逐字稿时不重做，直接复用它。删掉那份资料后再导入，或同时改了上一行的设置时，连转写一起重做 |

已保存的旧逐字稿不会被自动改写，不需要的可以在「资料」里自行移除。

## 服务商顺序与降级

转写按以下顺序尝试已配置密钥的服务商：

1. Gemini 免费密钥
2. 硅基流动 SenseVoice
3. Groq
4. Gemini 付费密钥

校对、翻译和标题默认用 DSH 的对话模型（见[校对和翻译用哪个模型](#校对和翻译用哪个模型)）。改走 Gemini 时，顺序是 Gemini 免费 → Groq → Gemini 付费。硅基流动从不处理文本。

请求遇到问题时这样处理：

| 情况 | StudyHub 的做法 |
| --- | --- |
| 每分钟限流 | 按服务商给的时间等待（没给就等 20 秒），最多等两次、每次不超过 65 秒，然后交给下一个服务商 |
| 每日额度用完 | 交给下一个。处理这份录音期间，Gemini 免费密钥搁置 6 小时；硅基流动和 Groq 按它们给的时间搁置，最短 1 分钟、最长 6 小时 |
| 密钥被拒（401 或 403）、Gemini 密钥无效或所在地区不支持 | 这份录音余下的部分不再用这个服务商，交给下一个，卡片上写明原因 |
| 硅基流动或 Groq 处理不了这段音频（没有 ffmpeg 而文件太大、模型不存在、参数被拒） | 交给下一个 |
| 超时 | 重试一次，不会更多：每次都可能消耗额度。之后，如果这一个或下一个是硅基流动或 Groq，就交给下一个；否则这一步失败 |
| 服务端或网络错误 | 分别隔 1.5 秒和 5 秒重试两次，之后同超时 |
| 付费余额用完（HTTP 402） | 任务停止并提示充值，不会退回免费服务 |
| 最后一个服务商也失败 | 这一步失败，已保存的部分留给「接着做」 |

### 隐私

- 上传录音前，请按账户套餐和所在地区核对 [Google 当前 Gemini 条款](https://ai.google.dev/gemini-api/terms)中的数据使用规则。
- Groq 和硅基流动有各自的数据政策。
- 勾选「只用付费密钥」后，这次导入会跳过 Gemini 免费密钥、硅基流动和 Groq。
- 涉及敏感内容的录音，提交前请自行确认各服务商的现行条款。

### 硅基流动 SenseVoice

- 模型是 `FunAudioLLM/SenseVoiceSmall`；可用地区和费用以硅基流动当前的账户规则为准。
- 只做转写。它不接受术语表、转写风格和语言设置，只返回纯文本，所以更依赖后面的校对。由它转写时，卡片上会有提示。
- 单个文件至多 50 MB、1 小时。更大的音频会切片（见下文）；用 ffmpeg 切时每片约 22 分钟。

### Groq

- 默认转写模型是 `whisper-large-v3`，文本模型是 `openai/gpt-oss-120b`，都可以在「专家选项」里改。只配 Groq、不配任何 Gemini 密钥也能用。
- Whisper 没有「整理」风格，也不接受自定义词表。术语表只能作为提示发送，最多 300 个字符，超出时在词条边界截断，所以更依赖后面的校对。
- Groq 公布的免费档（2026-09-29 查阅，可能变动）：
  - Whisper：每分钟 20 次、每天 2000 次，每小时 7200 秒音频、每天 28800 秒音频（约 8 小时录音）；
  - `gpt-oss-120b`：每分钟 30 次、每天 1000 次，每分钟 8000 token、每天 20 万 token。一小时讲座的校对加翻译大约要几万 token。
- 当前限额以 Groq 控制台和响应头为准。

### 为硅基流动和 Groq 切分音频

Gemini 每次请求可以发一小时，硅基流动每个文件限 50 MB，Groq 限 25 MB。所以较大的音频会切成几片分别发送，文字再拼起来：

- **WAV**：先转成 16 kHz 单声道（一小时约 115 MB），再在说话的停顿处切。
- **MP3**：在帧边界切，不重新编码。
- **M4A**：不超过上限就整个发送。超过时，装了 ffmpeg 就用它切；没装就重新封装成几个较小的 M4A，不重新编码。结构读不懂的 M4A 才需要 ffmpeg。
- **OGG、Opus、FLAC、WebM**：不超过上限就整个发送，超过时用 ffmpeg 切。
- **AAC、AIFF**：两家都不能直接读，所以总是需要 ffmpeg。

用 ffmpeg 时，先把录音解码一遍，找出最安静的位置，再在发送时逐片生成 16 kHz 单声道 16 位 FLAC（Groq 每片约 11 分钟）。临时文件用完即删；进程意外中断留下的，超过一天后会在下次切片时清掉。StudyHub 优先用环境变量 `FFMPEG_PATH` 指定的 ffmpeg，没有就用 PATH 里的 `ffmpeg`。没有 ffmpeg 时，这类音频会带着“需要 ffmpeg”的说明交给下一个服务商。

限流等待之后，从第一片没传完的接着传，不会重传前面的。

## 处理流程

1. **读取与分段。** 免费额度按请求次数计，所以请求越少越好。不超过「每次请求最长」（默认 59 分钟）的录音整段发送。更长的 MP3、WAV、M4A 按最少的段数平均切开，不重新编码，也不需要 ffmpeg：
   - MP3 在帧边界切；
   - M4A 无损重新封装；
   - 16 位 PCM 的 WAV 把每个切点挪到前后 30 秒内最安静的 200 毫秒，避免把一句话切断。

   其他格式整段发送。
2. **转写。** 走 Gemini（`gemini-3.5-transcribe`）时：
   - 「转写风格」默认是「整理」，去掉口头禅和重复并自动分段；「逐字」保留每个字。
   - 最多 100 个词条作为自定义词表：先放你的术语表，再放课程的题组名和题目主题词。
   - 12 MB 以内的音频直接内联发送；更大的经 Files API 上传，每把密钥各传一份，用完即删。
   - Google 以 HTTP 400 拒绝时，按固定顺序改用更朴素的请求重试：先换另一种发送音频的方式，再依次去掉词表、转写风格和语言设置，最后不带任何转写选项。哪一种成功，后面的段落就沿用它，卡片上写明去掉了什么。全部被拒时，错误信息会写明是第几段、Google 指出的是哪个字段。密钥无效、余额用完或网络不通都不属于参数问题，不会这样重试。
3. **校对。** 转写稿按约 6000 字符一个窗口校对。模型不重写转写稿，只返回疑似识别错误的清单（中文里多是同音字词），每条都原样引用前后文。一处修改必须同时满足以下条件才会生效：
   - 模型的把握为高（high）；把握为中、低或无效的都列入存疑处；
   - 引用的上下文能在转写稿里逐字找到，且其中只出现一次错词；
   - 拉丁字母的词按完整单词匹配（`patient` 不会改到 `patients`），中文错词至少 2 个字；
   - 改动很小，不跨行。

   最近 30 处已确认的修正会提示给后面的窗口，让同样的错误改得一致；前面的窗口不会因此回头重查。回复不是有效 JSON 时会再要一次，仍失败就保留这个窗口的原转写。
4. **翻译。** 校对后的文字按约 3500 字符分成若干部分，每部分有中英文标题和逐段译文。每一段都必须带着编号返回，不符合时会再要一次；仍失败时任务停止，已保存的部分保留。原文部分就是校对后的转写稿本身，不由模型改写。译成中文时，关键术语在每部分第一次出现时写成“中文（English）”。
5. **标题与保存。** 根据各部分标题写一个英文总标题，失败时用文件名代替。成稿的样子见[核对逐字稿](#核对逐字稿)。

校对或翻译请求被 Gemini 以 HTTP 400 拒绝时，会先去掉推理设置重试，再去掉 JSON 模式重试。校对仍失败时，这个窗口保留原转写；翻译仍失败时，任务停止并写明是第几部分。

### 等待时间

- Gemini 转写请求等待 3 分钟加音频每秒 0.6 秒，最少 5 分钟、最多 30 分钟。13.7 分钟的一段约等 11 分钟，47.8 分钟的一段等 30 分钟。
- 上传按每秒 100 KB 的慢速估算，最少 2 分钟、最多 40 分钟。
- 硅基流动和 Groq 的每一片按长度等待 2 到 10 分钟；Gemini 和 Groq 的文本请求等待 4 分钟。
- Node 自带的 fetch 最多等 5 分钟且不能修改，所以这些请求走 `node:https`，自行控制期限，同样支持 `NODE_USE_ENV_PROXY`。
- 超时后只重试一次：请求可能已经执行并消耗了额度。

Google 转写总是超时，可以把「每次请求最长」调小。已经转写好的段落有缓存，不会重复转写。

### 校对和翻译用哪个模型

在「设置 › 音频转写 › 高级 › 专家选项」的「校对与翻译用哪个模型」里选择：

- 「自动（有对话模型就用它，否则用 Gemini）」：默认。
- 「Gemini（同样先免费后付费）」：Gemini 免费 → Groq → Gemini 付费。
- 「对话当前使用的模型」。

由 DSH 模型处理时，每个请求都是一次性的 DSH 子代理，不带任何工具：不能执行命令、不能写文件，也不能再委派。结果由 StudyHub 直接回收、检查并保存，不会回流到主对话。「查看子代理」打开真实的子会话。宿主不支持子代理时，改为直接调用模型，任务历史里会写明。DSH 模型的用量不计入 Gemini 请求次数，卡片上会注明。「课堂实录」的实时翻译遵循同一个设置。

## 排队与并发

- **转写按顺序排队，校对和翻译流水线并行。** 同一个 DSH 宿主内，转写按到达顺序排队（默认一次转写一个录音，跨学习库共用）；一个录音转写完，转写名额立刻让给下一个录音，它的校对和翻译继续进行。所以第 2 个文件的转写会和第 1 个文件的校对、翻译同时发生。单文件导入、多文件导入里的每个文件、「课堂实录」的「校对后保存」都在这条队列里。等待中的卡片显示「排队中」。字幕导入和存疑处复核不排这条队。
- **校对和翻译用滑动窗口池。** 同时处理的校对（或翻译）窗口数默认 3 个，可在「专家选项」里改成 1 到 6 个；一批录音共用这个数。任何一个窗口做完，下一个窗口立刻补上，最慢的一个窗口不会再让其余位置空着。结果仍按原文顺序合并。每个窗口开工时，使用「此刻已完成的窗口」的修正和部分标题作为前文（同时开工的窗口互相看不到对方的修正，后开工的窗口看到的比分波时更多）。所有校对完成后才开始翻译。每个窗口做完立即保存。取消或致命错误会停下所有在跑的窗口，重试时复用已完成的窗口。
- **遇到限流自动降速。** 模型回复「请求太频繁」「并发太多」（429、子代理上限）时，本次处理剩下的部分自动降低并行数，被拒的窗口稍等片刻再试，不算失败；稳定后再逐步回升到设置的数。卡片上显示「并行 4（已因限流从 6 降到 4）」。
- **转写的并行数**可在「专家选项」里改成 1 到 3 个，默认 1 个，免费额度和每分钟限流有限，一般不需要调大。
- **并发的影响。** 并发不会增加请求次数，但更容易触发每分钟限流。修改只对下一次处理或「接着做」生效，不会打断进行中的录音。
- **排队中的任务**可以直接停止，它不占名额，卡片上仍有「接着做」。
- **内容相同的文件**（哪怕改了名）不会同时转写：后来的等前一个做完，再复用它保存的资料，不重复花钱。

## 用量控制台

「音频转写」页底部的折叠栏「用量与额度」（「今日 N 次请求」）里是「用量控制台」。配置了服务商、并且记录到至少一次请求后才会出现。只有展开时每 15 秒刷新一次，窗口隐藏时暂停。查看它不会调用服务商。

它按当前配置的密钥显示：

- 今日模型请求次数、已转写的音频分钟数、输入与输出 token、限流与其他失败次数；
- 每个服务商（Gemini Free、SiliconFlow、Groq、Gemini Paid）的模型及每日请求额度；
- 近 7 日趋势；
- 「校对与翻译的推理强度」（见[校对与翻译的推理强度](#校对与翻译的推理强度)）；
- 「设置 Gemini 免费每日上限」。

**统计范围。** 从这项记录启用起，本插件发往 Gemini `generateContent`、Groq 转写与对话、硅基流动转写的每一次 HTTP 请求，包括失败和重试。验证密钥、文件上传、复用已保存的结果、「课堂实录」的实时音频流以及 DSH 模型的 token 都不计入。控制台不认识的模型接口、或用了不属于任何已配置密钥的请求，也会被记下并显示为「其他」，不会丢失。录音从已保存的转写继续时，任务卡写明「复用已保存的转写」，所以 0 次请求是可以解释的。「今日」和近 7 日按**你所在时区的日期**；Gemini 免费额度仍按 Google 的额度日（太平洋时间每天 0 点重置），控制台在额度旁写明，并换算成你的本地时间。

**剩余额度：**

- 硅基流动和 Groq：取自最近一次响应的限流响应头，过期后显示为未知。
- Gemini 免费：在「设置 Gemini 免费每日上限」里填入 AI Studio 显示的各模型每日请求数（RPD），控制台减去本插件的请求次数。这是估计值：同一 Google 项目里其他应用或密钥的调用不在本地记录中。被限流和没发到 Google 的请求不扣减。填 0 表示未知。
- 未知额度显示为未知，不会显示为零。付费余额请到服务商控制台查看。

**任务卡片上的次数。** 卡片列出这份录音自己的请求：

- Gemini 免费和付费请求，含之前的所有尝试，另有一行「其中本次」；
- 硅基流动和 Groq 各占一行。

复用已保存的结果时，「本次」可以是 0，累计仍包含当初的转写。以前没有记录的，按已保存的转写段数补记，每段一次。卡片还会显示「若全部走付费密钥」转写大约要花多少，以及实际走付费密钥的那部分的估算。校对和翻译只记次数与 token，不折算金额。实际费用以服务商控制台为准。

## 校对与翻译的推理强度

「设置 › 音频转写 › 高级」里的「校对与翻译的推理强度」有两个下拉框（校正、翻译），在用量控制台里是同一个控件；从下一次处理起生效。

- **选项是当前模型自己的档位**，用模型自己的名字显示（例如 Off、Low、High、Max），再加一个「模型默认」。每个下拉框旁显示近 7 日该档位的平均耗时（样本，不是准确率）。
- **保存的是相对强度**（最低、低、中、高、最高，或模型默认），不是某个模型的档位名。换模型后，同样的倾向会对应到新模型上**最接近**的档位（离得一样近时取更强的），并在下拉框下面写明，例如「当前模型没有「中」，已用「High」」；模型没有任何可调档位时写明「「高」不起作用，按模型默认运行」。不会再悄悄回到默认。
- 任务历史里，只有「要求的」和「实际的」不一样时，才用一句话说明（「推理强度：要求「中」，当前模型没有，已用「High」」）。
- 「课堂实录」的「上下文校正推理强度」是同一个控件，同一套映射。

档位如何传给模型：

- DSH 模型按其模型目录支持的档位执行（上面的最接近映射）；
- Gemini 3 系列用 `thinkingLevel`，Gemini 2.5 系列用 `thinkingBudget`（只有低、中、高三种：最低按低，最高按高）；
- Groq 的 GPT OSS 模型用 `reasoning_effort`（同上）。

改了档位后，再次导入同一录音会重做校对和翻译，转写结果复用，已保存的资料不会被改写。

## 连不上 Google 时

任务失败并显示「连不上 Google 服务」时，先检查服务状态、网络和代理。Node 不会自动采用桌面的系统代理。使用 Node 22.21+ 或 24.5+ 时，可以按 [Node 官方代理说明](https://nodejs.org/learn/http/enterprise-network-configuration)从同一终端设置环境变量并启动 DSH 网页版：

```powershell
$env:NODE_USE_ENV_PROXY = "1"
$env:HTTPS_PROXY = "http://127.0.0.1:7890"
$env:NO_PROXY = "localhost,127.0.0.1"
npx @deepseek-ai/dsh web
```

把地址换成你自己的代理。提示「当前网络所在地区不支持 Gemini API」（Google 原文是“Location is not supported”）时，需要换到 Gemini 支持地区的网络。其他服务商的可用地区以各自当前说明为准。

## 验证边界

- **伪造服务。** 自动化测试用本地伪造的 Gemini、硅基流动和 Groq 服务，覆盖切分、服务商顺序、限流等待、上传与删除、参数降级、校对修正的安全规则、成稿格式、断点续做和密钥不外泄。它们证明代码按预期处理这些响应，不证明真实的转写质量、当前额度或服务商的实际行为。
- **真实 ffmpeg。** 用 ffmpeg 切片的部分用真实 ffmpeg 测过：M4A、Ogg Vorbis、Opus、WebM、FLAC、AAC、AIFF 各一段一分钟带停顿的录音，每一片都能重新解码，加起来和原来一样长，切点落在停顿里，临时文件删干净。没有 ffmpeg 的机器上这些测试会自动跳过。M4A 无损切分用一段真实的 AAC 录音测过。
- **真实接口。** 请求字段依据 2026-09-29 查阅的 Gemini 和 Groq 文档：Gemini 用 `generateContent`（没有采用新的 Interactions API），Groq 用 `/openai/v1/audio/transcriptions` 和 `/openai/v1/chat/completions`。没有用真实密钥调用过。Groq 文本模型是否支持 JSON 模式和 `reasoning_effort` 尚未验证。Google 接口变化时，只需改 `lib/gemini.js`。
- **DSH 子代理。** 在本地 DSH 0.2.0-rc.2（隔离的 DSH_HOME、假模型）里验证过：校对作为 DSH 子代理运行，点「查看子代理」打开那个子代理的会话，标题是「Study ＜编号＞ · 音频校对 · 文件名 · n/N」。从面板发起的任务，其子代理挂在 DSH 为面板临时创建的协调会话下，**不在 DSH 左侧会话列表里**，只能从任务卡（或打开某个子代理后的子代理切换器）进入。
- **@ 选文件。** 没能验证点「在对话里用 @ 选文件」后 DSH 会不会自动弹出文件选择；不弹时手动再按一次 @。
- **进度比例。** 25% / 30% / 45% 是经验权重，各步实际耗时随录音和模型而变，所以总百分比是估计；「本步骤预计还需」才是按实际速度算的。
- **术语。** 转写稿里仍可能有校对没发现、或把握不大没改的错词，请对照每份逐字稿里的存疑处核对。

## 开发者参考

### 对话动作

对话里的智能体通过 `study_audio` 工具使用音频功能：

- `audio.import {path | uploadId | files:[{path | uploadId}], title?, subject?, terms?, course?, courses?, paidOnly?}` 启动后台任务。对话里的 path 可以带引号、带 @，也可以是相对工作区的路径。`files` 按给定顺序合成一份逐字稿。任务结束时会通知对话资料已保存，不会触发出题。
- `audio.retry {jobId}` 继续失败或已取消的任务，只在学习者要求时使用。
- `audio.settings.get` 只返回各密钥是否已配置和末四位。不在对话里索取或接收密钥；保存和验证密钥（`audio.settings.set`、`audio.test`）只在面板里进行。
- 另外还有 `audio.subtitles.import`、`audio.corrections.review`、`results`、`result.get`、`jobs`、`job.wait`（最多等 60 秒）、`job.cancel`，以及 `live.list`、`live.get`、`live.save`。

面板用 `audio.upload.start`、`audio.upload.chunk`（每块 3 MB）、`audio.upload.finish`、`audio.upload.cancel` 上传文件，用 `audio.preflight` 预检，用 `audio.usage` 读取用量控制台，用 `job.archive` 收起已结束的任务卡（「知道了」把任务放进「任务」页的「已归档」，只读保留；`job.delete` 才会永久删除）。「从工作区里找」只搜索当前会话的工作区，最多 6 层，最新的排前面；跳过隐藏文件夹、`node_modules`、`dist`、`build`、Python 环境和 StudyHub 自己的数据文件夹。回到面板的只有文件名、大小和日期。

### 文件存放位置

| 内容 | 位置 |
| --- | --- |
| 密钥 | DSH 用户目录（`~/.dsh` 或 `DSH_HOME`）下的 `study/audio.json`，明文 |
| 用量记录 | 同一目录下的 `study/audio-usage/YYYY-MM-DD.jsonl`。保留 31 天，不含密钥（只有一个短哈希）和请求、返回正文。读取时按 16 KiB 流式处理，汇总成按日、按模型的计数 |
| 面板上传的文件 | `<学习库>/audio-uploads/`。没提交的上传在取消或离开页面时删除；超过 24 小时没人认领的，在下次上传时清理 |
| 任务清单和上传文件的副本 | `<学习库>/audio-batches/` |
| 检查点 | `<学习库>/audio-cache/<录音>/`：原始转写段（各自记着是哪个服务商转写的）、校对窗口、翻译部分、标题，以及 `usage.json`（这份录音的请求累计） |

原始转写检查点按转写模型、风格、语言和切分点区分，与术语表无关。校对和翻译的检查点还取决于文本模型、推理档位、「这段音频讲什么」和词表。旧版保存的「多录音并发」设置会被忽略（转写并行数单独设置，默认 1）。
