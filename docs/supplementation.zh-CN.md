# 向已有题组补题

想把资料里还没覆盖的考点补进一个已有的题组，直接在主对话里说。例如：“把这周讲义里期中题组还没覆盖的概念补进去。”

agent 会启动一个后台任务：根据资料出题，交给独立审核，再把通过的题并入这个题组。你要求补入指定题组，就等于允许保存，中间步骤不会再逐一请你确认。

## 开始前

- **可用的模型**：出题和审核都用出题所用的模型，按服务商计费。
- **目标题组**：必须是未归档的普通题组。斩题组、「为你定制」这类系统题组不能补题。
- **资料**：说明从哪些资料出题，所选资料合计最多 600,000 字符。装了检索扩展时，选得更多也可以：StudyHub 会先按侧重点挑出相关页面，详见[大教材](large-documents.zh-CN.md)。
- **题型**：案例分析题以外的题型都可以。

## 请求补题

1. 在主对话里说明目标题组、所用资料和缺了什么。
2. agent 先对照资料和题组里已有的题，再决定补哪些考点、补几道（每次 1–30 道）。
3. 在「学习库」页顶部的任务卡上查看进度，点「停止」可以取消。

任务结束后，主对话会收到一条通知，写明实际新增的题数和题组现有总数。

## 看懂结果

任务卡标题（后面跟着题组名称）说明任务进行到哪一步：

| 标题 | 含义 |
| --- | --- |
| 「补题排队中」 | 正在等前一个任务结束。 |
| 「正在审核并补入题组」 | 正在出题、审核或并入。 |
| 「已补入 N 题 · 共 M 题」 | 请求的题全部通过并已并入。 |
| 「部分补入 N 题 · 共 M 题」 | 部分题已并入，其余未通过或没有生成。 |
| 「补题未完成」 | 没有题并入，任务卡上会写明原因。 |
| 「正在停止补题」 | 你点了「停止」或运行时限已到，任务正在收尾。 |
| 「补题已取消」 | 你停止了任务。 |

只有真正存进题组的题才算已补入。生成了或审核通过但没有保存的题，不会报告为已补入。

## 题组会怎样变化

- 通过审核的题直接并入原题组，不会另建题组。
- 原有题目的 ID、复习进度和作答历史都保持不变。
- 全部补入后，任务用过的中间草稿会自动删除。
- 有题没补进去时，这些题留在一份草稿里，并记下每道题未通过的原因。可以在任务卡上点「打开草稿」查看。

## 限制与失败

- **每批只审一轮**：每批题只做一轮独立审核，保留通过的题，剔除未通过的题并记录原因。不会为了凑够数量反复修题或重新出题。
- **运行时限**：默认 20 分钟，排队时间不算在内，可以在「设置 › 出题偏好」的「运行时限（分钟）」里修改。时间用完时，已经保存、审核过且之后没有改动的题仍会并入。这一步不再调用模型，通知里会写明还差几道。
- **停止优先**：你停止任务后，不会再并入任何题，时限到了也一样。
- **改动会阻止发布**：任务期间题组归档或修改、题目有改动时，受影响的题不会并入。
- **不自动重跑**：因题组已移除或归档、版本冲突、取消或审核失败而结束的任务不会自动重跑，也不会改补到别的题组。未完成的部分留在可以继续的草稿里。
- **零通过不改题组**：一道题都没通过时任务失败，题组保持原样。

## 其他补题方式

- **从一段原文补题**：在资料阅读器里选中文字，用「补充到现有题组」。
- **先出草稿再决定**：「创建题组」里的「用资料出题」只生成草稿，检查后由你决定何时发布。

## 给 agent 和开发者

通过 `study_workspace` 调用 `supplement`：

```json
{"action":"supplement","payload_json":"{\"deckId\":\"目标题组的完整 ID\",\"sourceIds\":[\"资料 ID\"],\"count\":5,\"kind\":\"flashcard\",\"focus\":\"与已有题目比较后确认缺失的课堂考点\"}"}
```

| 字段 | 说明 |
| --- | --- |
| `deckId` | 必填。已有、未归档普通题组的完整 ID。 |
| `sourceIds` | 必填。出题所用的资料。 |
| `count` | 1–30。 |
| `kind` | `quiz`、`multi`、`flashcard`、`open`、`cloze` 或 `mixed`。不接受 `case`。 |
| `focus`、`language`、`difficulty`、`constraints` | 可选，含义同 `generate`。 |
| `resumeDraftId`、`draftVersion` | 从草稿继续未完成的补题。草稿的目标必须与 `deckId` 一致，`draftVersion` 必须是当前版本。 |

按证据决定补什么：

- 先比较老师讲授的概念与目标题组的实际题目，再选择缺口、题数和前置关系。用 `source.coverage` 和 `card.search`，并指定确切范围。
- `source.coverage` 的直接引用数只能帮助定位证据，不能代替语义上的覆盖判断。
- 题组标题里的数字不是要补的题数。
- 需要前置关系时，用 `capture.requiredBy` 或 `card.link` 保存明确的关联，不要凭空编造。

任务行为：

- 用户要求补入指定题组，就已授权本地生成、审核和发布，不要再问是否发布。
- 生成和审核阶段的 JSON 由插件直接回收，不注入主对话。
- `generate` 仍然只生成草稿，不会自动发布。
- 最终回执包含 `publication.deckId`、`added`、`total` 和 `remainingDraftId`。只报告实际保存的新增数；排队中或审核通过不等于已补入。
- `job.wait {jobId?, timeoutSeconds?}` 可以为完成已授权的请求做一次有界等待，最多 60 秒，不需要用户额外说“等”。超时后交回控制，最终通知会给出结果。不要循环轮询，也不要重复入队。
