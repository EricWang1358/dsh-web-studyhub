## 已确认与设计选择

**用户明确确认：** 起点接近零基础；首版采用“先接入外部实操与成果验收”。学习者在自己的环境操作，插件提供任务、接收成果并按标准审阅。首版不内置运行环境，不把提交物审阅称为运行复现。

**继承的用户偏好：** 快速发布、不逐题等待审阅；课堂最近内容优先、每轮最多十道新题；手动继续；帮助与补前置由用户触发；少按钮；题组合并需确认。已选择系统学习时，发布后返回系统任务，不强开课堂轮次。

**本次设计建议：** 新增可选系统学习模式、独立课程知识点台账、逐维度证据。八步依次是范围核对、前置诊断、整体案例、示范理解、主动回忆、迁移验证、外部实操、综合与延迟验收。第 4–7 步按单元循环，不是八个必须切换的页面，也不是按五份 PDF 顺序刷题。

**产品起始参数，不是科学定律或用户逐项决定：** 系统每轮最多五个任务，局部补前置最多三个台阶，入门诊断默认最多五个检查；延迟提取至少相隔 24 小时。参数需版本化，并根据试点调整。延迟间隔按该知识点最近相关学习/讲解/提示/练习计算，换题不清零观察记录。

## 最容易误实现的边界

- 知识点清单独立于已有题目；没有题的核心点也在范围内。只有 JSON 或原始材料未核对时仍能学习，但完整性状态必须保留“待核对”。实际五份 PDF/JSON 本次不可得，不能写成已经审计。
- 每个核心点按所需维度逐项验收。平均高分、SM-2 间隔、自评、implicit 前置加分、看图和生成笔记均不能替代独立证据。综合实验按目标分别判定。
- 独立回忆、陌生迁移和实操是不同证据。旧记录保留为 legacy/supporting，不能事后补造任务族、提示状态或实操结论。
- 模型判分发现实质误通过尚未修复时，受影响路径只能给辅助反馈。必须修复并复核原失败及独立样本，才能恢复有效验收。
- 课程范围更新不自动打断旧会话；旧版结果不直接计新范围。当前任务撤销/实质修改时保留回答，转过期状态并提供新入口。
- 会话和返回栈必须持久化；UI 与 DSH 工具走同一服务。模型请求在事务外，结果写回核对版本，重复请求不重复发放证据。

当前实现证据的完整表在计划 Problem Frame。尤其不要沿用早期 handoff 的单文件库或不支持 PDF 的旧假设：当前 `lib/store.js` 是 v2 manifest/shards。扩展需处理归一化、分片白名单、dirty hints、导出恢复与原子迁移；计划选择首次启用时备份并迁移 v3，旧客户端拒读。

`references/library-schema.md` 的 Markdown 目录布局是另一套旧 study-library 参考，不是本插件原生库。`lib/coach.js` 的题干关键词分类不能证明迁移；`lib/skeleton.js` 的卡片图和数量上限不能证明材料覆盖；默认 JSON 发布路径为 quick publish。上述事实已反映到相关文档。
