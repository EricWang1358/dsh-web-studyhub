# StudyHub 的说话方式

界面里的每一句话都在回答学习者的两个问题：刚才发生了什么，接下来我该做什么。这份手册写给要改界面文字的人：错误、空状态、提示、设置步骤、状态词、回执、横幅和提示条。它不改功能名和按钮名，只管句子。

整体的语气：平实、温和，不卖萌，不说教。像一个靠谱的学长：事情是什么样就说什么样，然后给一个下一步，不开玩笑，不吓人。

下面八条是产品负责人批准的规则。每条后面的例子，没有标「示例」的都来自产品里真实改过的句子；标了「示例」的是为了说明规则写的，产品里没有这句话。

## 八条规则

### 1. 先说发生了什么，再给一个下一步

学习者读一遍就该知道两件事：现在是什么情况，下一步点哪里。只给一个下一步。原因不明就直说不明。

- 之前：出了点问题，请重试。
- 之后：这次没有成功，也没有拿到具体原因。可以再试一次。
- 之前：已重新检查，目前还没有连上。
- 之后：已重新检查，还没有读到可用的模型。在 DSH 里配好后，再点一次「重新检查」。

这一条也管空状态和被挡住的操作：空状态说出这里是什么、什么时候会有内容（暂无消息 → 信箱是空的）；按钮点不了，就在旁边写原因和解除的办法（请先归档这份资料，再永久删除 → 这份资料需要先归档，才能永久删除）。

### 2. 不空口说「稍后」「暂时」

没有理由、没有出路的「稍后再试」不要写。要么写出等多久，要么写出能点的东西，要么说明真正的原因。

- 之前：另一个操作还在进行，请稍后重试。
- 之后：上一个操作还没结束，这次点击没有生效。等它结束后再点一次。
- 之前：稍后再试。（后台服务没有回应）
- 之后：后台服务这次没有回应。等一两分钟再试一次。

不要承诺页面做不到的事：写「会自动重试」之前，先确认代码真的会重试。

- 之前：学习插件暂时没有连上，稍等一下会自动重试。
- 之后：StudyHub 暂时没有连上。点「重试」再试一次。

### 3. 说清做了什么、凭什么，方便你核对

数字、状态和结果都说出依据。状态词会出现在很多页面，写之前查一下它在什么条件下显示，别让它在不对的时候说话。

- 示例：已备好 3 道变式 → 照你刚错的那道出了 3 道变式
- 之前：正在生成…（顶栏。PDF 转换、转写、翻译、建索引在后台跑的时候也会显示）
- 之后：后台处理中（悬停会列出是哪几类任务）
- 之前：今天已经清空（其实是这个范围里一道题也没有）
- 之后：这里还没有可以学的题

### 4. 按钮用具体的动词；有代价的操作写明代价

按钮上写它要做的事。会丢东西、不能撤销的操作，在点之前就把代价写出来。

- 之前：请手动复制 ／ 剪贴板不让用
- 之后：需要手动复制 ／ 浏览器没让复制，点「打开全文」
- 之前：请先归档这份资料，再永久删除。
- 之后：这份资料需要先归档，才能永久删除。（删除对话框里已经写明「无法撤销」）

### 5. 用「你」，不用「您」；不命令、不责怪

不用「请勿」「必须」。陈述事实，把选择留给学习者。

- 之前：必须填写，才能生成。
- 之后：填写主题后才能生成。
- 示例：请勿重复导入 → 这份已经导入过了

### 6. 不卖萌、不凑数

不用「哎呀」「啦」；感叹号只留给真正的好消息；不用「暂无」这种凑数的词。界面里也不出现开发和运维的词（宿主、插件、渲染、拉取、缓存），主聊天窗口只叫「主会话」。例外：DSH 自己界面的名字照原样引用，比如「DSH 插件管理器」，因为学习者要照着它去找。

- 之前：暂无卡片
- 之后：这一列没有卡片
- 之前：学习工作台渲染出错
- 之后：学习工作台没能显示
- 之前：在对话输入框的模型选择器里选
- 之后：用主会话输入框里的模型选择器

### 7. 语气跟着你的状态走

久没学也不内疚施压，只说事实和下一步。产品里已有的做法：逾期只说「已逾期 N 天」。

- 示例：又断了一天，快补上！ → 今天有 12 题到期
- 示例：你已经 5 天没学了 → 上次学习是 5 天前，今天有 12 题到期

### 8. 说行为，不评价你

说你做了什么、结果是什么，不评价你这个人。

- 示例：你好像很吃力 → 这章最近 10 题错了 6 道
- 示例：你太粗心了 → 这 3 道都是最后一步算错了

## 词汇表

这些词在整个界面里只有一个意思。新文案沿用，不要换同义词。

| 词 | 意思 |
| --- | --- |
| 主会话 | DSH 里和你对话的主聊天窗口。界面句子里它只有这一个名字。「在新对话中打开」是真的新开一个对话，不是主会话。 |
| 学习库 | 你电脑上的一个文件夹，资料、题库和复习记录都保存在里面。 |
| 题组 | 一组题。 |
| 草稿 | 只指待发布的题组。你自己输入框里写的字、备好等你练的变式都不叫草稿。 |
| 归档 | 把资料或题组收起来，不再参与练习，可以恢复。永久删除之前必须先归档。 |
| 斩 | 把一道题收进「斩题组」：不再参与复习，作答历史和复习进度保留，随时可以恢复到原题组。 |
| 删除 | 永久删除，无法撤销。先归档，再删除。 |
| 为你定制 | 系统自动建的题组，放着根据你的错题和反馈改写的定制题。 |

不要改名的功能和按钮：创建题组、错题与待巩固、发给主会话、复习全书、斩、归档、为你定制。

## 写新文案前的检查清单

- [ ] 说了发生了什么吗？说了唯一的下一步吗？（规则 1）
- [ ] 有没有「稍后」「暂时」？有，就换成原因、出口或直接的陈述；它承诺的事（自动重试、保存、保留），页面真的会做吗？（规则 2）
- [ ] 数字和状态词说了依据吗？它在所有会显示它的场合都是真的吗？去代码里查它的触发条件。（规则 3）
- [ ] 按钮是具体的动词吗？有代价的操作写明代价了吗？被挡住的操作写了原因和解除的办法吗？（规则 4）
- [ ] 有没有「您」「请勿」「必须」？（规则 5）
- [ ] 有没有「哎呀」「啦」「暂无」，有没有宿主、插件、渲染、拉取、缓存这些词？主聊天窗口叫「主会话」了吗？「草稿」只用在待发布的题组上吗？（规则 6）
- [ ] 会不会让久没学的人内疚？（规则 7）
- [ ] 说的是行为，不是对人的评价吗？（规则 8）
- [ ] 保留了所有 `{0}` `{1}` 占位符吗？
- [ ] 英文对照改了吗：中文原文是每个 `ui/locales/en*.json` 里的键，都要同步，用旧文案的测试也要改到新文案。
- [ ] 窄屏放得下吗？状态词和按钮上的字要短，长句放进悬停说明。
