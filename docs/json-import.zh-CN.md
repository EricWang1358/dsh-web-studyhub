# 导入 JSON 题组

手里已有的题，或让其他 AI 按资料出的题，都可以写成 JSON 题组导入 StudyHub。导入后先存为草稿，你检查一遍，点一下就能发布并开始练习。导入本身不调用模型审核题目。

## 选择导入入口

| 入口 | 接受的内容 | 结果 |
| --- | --- | --- |
| 「创建题组」页的「导入 JSON 题组」 | 粘贴的 JSON，或 1 个不超过 2 MB 的 `.json` / `.txt` 文件 | 确认建议的标题和课程后存为草稿 |
| 「添加资料」对话框 | 1 个或多个 `.json` 题组文件，每个不超过 2 MB | 每个文件存为一份草稿，使用建议的标题；课程用对话框里选的，没选时用建议的课程 |
| 主对话 | 电脑上的文件或文件夹，一次最多 50 个文件 | 直接发布，见[在主对话中导入文件](#在主对话中导入文件) |

在「添加资料」对话框里，文档转换工具（MinerU、Docling）输出的 JSON 会按文档导入，字幕 JSON 会按字幕导入，不会当成题组。

## 在「创建题组」页导入

1. 打开「创建题组」，选「导入 JSON 题组」。
2. 在「01 / 各题型 JSON 提示词」里选「题型」，或选「混合题型（一次复制全部）」。
3. 点「复制提示词」，粘贴给其他 AI，并在后面附上你的资料和出题要求。混合题型的提示词默认要求 10 题、每种题型 2 题，你另有要求时以你的为准。
4. 在「02 / 导入题组」里，把 AI 的回复粘贴到「JSON 内容」，或把文件拖到「把 JSON 题组文件拖到这里」区域；也可以点「读取 JSON / TXT 文件」选择文件。
5. 点「检查并建议归类」。StudyHub 检查 JSON，并给出「短标题」和「所属课程」的建议，可以直接修改。
6. 点「确认并导入草稿」，草稿随即打开。

想自己写 JSON，可以展开「查看 JSON 格式示例」，参考当前题型的示例。

`.txt` 文件里也必须是 JSON。不是 JSON 的题目，例如刷题软件里的题、错题记录或截图，请改用「在对话里录题」。这个选项只在对话可用时出现。

### 建议归类这一步做什么

- 有可用模型时，「检查并建议归类」会调用一次模型，建议标题、课程和可并入的题组。字段上方显示「AI 建议，请确认或修改」。
- 发给模型的内容包括：题组标题和目录、最多 8 道样题（考点、学习目标和题干开头）、你的课程名，以及最近最多 30 个题组的标题和考点。StudyHub 只采用这三项建议，不改动题目内容。
- 没有可用模型时，StudyHub 建议沿用原标题和当前课程；题组的 `folder` 与你的某门课程同名时，改用它作课程。同时显示「初步整理建议，请确认或修改」。
- JSON 里写了 `course` 时，以它为准，不采用模型建议的课程。
- 模型在同一课程里找到考点相同的未归档题组时，会出现勾选项「发布时并入建议的同知识点题组（保留全部题和记录）」。改了课程后，这个勾选项会消失。

## 编写 JSON

### 题组字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | 是 | 非空文字 |
| `folder` | 否 | 文字。目录只用来分组显示题组 |
| `course` | 否 | 不超过 200 字的文字。会作为建议的课程，优先于模型的建议 |
| `cards` | 是 | 题目列表，至少 1 题，不限总数；同一题组可以混合题型 |

### 题目字段

| 字段 | 适用题型 | 说明 |
| --- | --- | --- |
| `kind` | 全部 | `quiz` 单选、`multi` 多选、`flashcard` 闪卡、`open` 开放问答、`cloze` 填空 |
| `topic`、`objective`、`prompt`、`answer`、`hint`、`explanation`、`misconception` | 全部 | 非空文字 |
| `options` | `quiz`、`multi` | 3–6 个选项，每项含 `id`、`text`、`correct`（`true` 或 `false`）和 `explanation`。单选恰好 1 个正确项；多选至少 1 个正确项、至少 1 个错误项 |
| `rubric` | `open` | 评分标准，文字 |
| `cloze` | `cloze` | `{"text": "...", "answers": [...]}`。`text` 是显示给你的句子，每个空写成 `{{id}}`；每个答案含 `id`、`value`，可选 `accept` 列出其他可接受的写法。每个空对应一个答案，每个答案也要对应一个空 |
| `citations` | 可选 | 关联学习库里已有的资料，见[关联原始资料](#关联原始资料) |

下面是一个单选题组，取自 `ui/json-prompts.js` 的内置示例：

```json
{
  "title": "二分查找练习",
  "folder": "算法",
  "cards": [
    {
      "kind": "quiz",
      "topic": "二分查找",
      "objective": "解释二分查找的输入条件",
      "prompt": "哪种序列可以直接用于二分查找？",
      "answer": "升序序列",
      "hint": "考虑每次排除一半范围的依据。",
      "explanation": "只有有序序列才能通过比较中间值排除一半搜索范围。",
      "misconception": "误以为任意序列都能直接二分查找。",
      "options": [
        { "id": "a", "text": "升序序列", "correct": true, "explanation": "升序关系允许排除一半搜索范围。" },
        { "id": "b", "text": "随机乱序序列", "correct": false, "explanation": "乱序无法根据中间值排除半区。" },
        { "id": "c", "text": "没有顺序保证的序列", "correct": false, "explanation": "没有顺序保证就不能确定目标所在半区。" }
      ]
    }
  ]
}
```

### 接受什么、丢弃什么

- 内容最多 500,000 字符，文件须为 UTF-8 编码。
- 可以带 UTF-8 BOM，也可以用 Markdown 代码围栏（```` ``` ```` 或 ```` ```json ````）包住整个 JSON。
- 只保留上面两张表里的字段，其他字段一律丢弃。
- 每道题导入后都会分配新 ID。外部的 ID、复习进度、暂停状态和前置关联都不会带过来。

## 导入时怎样检查

**无法安全读取时，整份导入会被拒绝**：

- JSON 有语法错误，或顶层不是对象；
- 缺少 `cards` 或它是空的，或某道题不是对象；
- 缺少 `title` 或它是空的；
- 某道题没有 `kind`，或不是上面五种之一；
- 字段类型不对，例如该写文字的地方写了数字，或 `folder` 不是文字；
- `course` 超过 200 字。

**结构损坏的题会留在草稿里等你修**：

- 缺少的文字字段留空；
- 格式不对的 `options` 变成空列表；
- 格式不对的 `cloze` 保留文字，答案清空；
- 不是文字的 `rubric` 留空。

每道题的原始 JSON 还会另存在一份导入资料里。

**其他问题只标记，不拒绝。** 草稿会列出这些问题，发布后题目上也保留标记。例如：

- 必填字段是空的；
- 同一题组里两道题的学习目标或题干相同；
- 提示和答案一样；
- 选项不符合上面的规则，或两个选项的 `id` 或内容重复；
- 开放问答没有评分标准；
- 填空的空和答案对不上。

选项长短差得太多、可能暗示答案时，草稿也会提醒。

## 发布并开始练习

草稿在「草稿与发布」页打开。

- 「保存并校验」保存修改并重新检查。
- 选择题可以增加选项（最多 6 个），也可以点「删除这个选项」。单选题选定一个正确项后，其他选项会自动取消。
- 「保存并发布」一次发布全部题目，不等待模型审核，随后开始一轮最多 10 道新题。没有可开始的新题时，会提示题组已发布并回到学习库。
- 如果勾选了并入，发布时题目会并入建议的题组，原题和记录都保留。
- 有问题的题带着标记发布。练习时遇到无法判分的题，可以点「跳过此题，不计成绩」，不记录成绩，也不改变复习进度。

另有一条逐题审核的发布路径，但不是导入的默认方式，见[把草稿发布到已有题组](main-session-queries.zh-CN.md#把草稿发布到已有题组)。

## 关联原始资料

原始资料已在学习库里时，题目可以带引用：

```json
"citations": [{ "quote": "资料中的逐字原文，至少 12 个字", "sourceTitle": "资料标题（可选）" }]
```

- `quote` 必须从资料逐字摘录，至少 12 个字符。
- 标题或原文有重复时，补上 `sourceTitle`，或资料在本地的 `sourceId`。
- 只有学习库里恰好 1 份资料匹配时才会关联；其他 JSON 导入资料不参与匹配。
- 匹配不上的引用会跳过，草稿里会显示跳过的条数。

引用能证明什么：

- 引文匹配只说明这段原文存在，不说明答案已经核实。
- 导入的题会保留导入标记，题目不会被当作自身的证据。
- 导入和默认发布都不调用模型审核。发布成功也不代表资料已经全部覆盖。

## 在主对话中导入文件

在主对话里，可以让 StudyHub 导入电脑上的 JSON 题组文件。助手会调用 `deck.import`，它和面板里的导入有几点不同：

- 路径必须是绝对路径。给文件夹时，导入其中全部 `.json` 文件，按文件名排序；单个文件可以是 `.json` 或 `.txt`。
- 一次最多 50 个文件，每个不超过 500,000 字符。
- 文件可以是上面的题组对象，也可以只是一个题目数组；没有标题时用文件名。
- 题目**直接发布**，不经过草稿。
- `into` 指定目标题组，只能用于单个文件；没有指定时，标题、目录和课程都相同的未归档题组会接收这些题。
- 题干（填空题看 `cloze.text`）已在目标题组里的题会跳过，同一文件里重复的题也会跳过。比较时忽略大小写、空格和标点。
- 结果按文件列出新增和跳过的题数、题组总题数和最多 5 条提醒；失败的文件会列出原因。

调用时传入的 `folder` 和 `course` 优先于文件里的值。

## 主对话与开发者参考

| 调用 | 作用 |
| --- | --- |
| `draft.import.propose {text}` | 检查 JSON，返回 `originalTitle`、`title`、`course`、`mergeTargetId` 和 `method`（`ai` 或 `rules`），不写入任何数据 |
| `draft.import {text, title?, course?, mergeTargetId?}` | 在同一事务中保存导入资料和新草稿 |
| `draft.publish.quick {id, draftVersion, mergeTargetId?}` | 「保存并发布」在保存草稿后调用；只做结构检查，发布全部题目 |
| `draft.publish` / `draft.publish.start` | 逐题审核后发布，后者作为后台任务运行 |
| `deck.import {path \| paths \| text, folder?, course?, into?}` | 从磁盘导入文件并直接发布，规则见上一节 |

各题型的完整示例在 `ui/json-prompts.js`。主对话如何调用这些操作，见[在主对话中查询资料与题组](main-session-queries.zh-CN.md)。

## 规划：系统学习的覆盖审计

这一节是规划，尚未实现。

- 五个 JSON 只能证明五组题已保存，不能证明五份 PDF 的核心内容都进了题库。
- 拟新增的课程台账会在显式关联原始资料后，核对资料片段、必学知识点和学习任务之间的对应关系。
- 没有原始资料时仍可学习，覆盖范围显示为待核对。
- 这项审计不会阻塞快速发布，不要求逐题人工审核，也不会自动合并题组。
- 目前导入只保留上面列出的字段，`knowledgePointId`、范围版本等扩展字段都会丢弃。今后支持这些字段，需要明确的兼容协议或独立的映射，不能以为写进 JSON 就会生效。
