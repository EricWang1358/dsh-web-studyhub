# 后台任务与右栏

[English](generation-agents-sidebar.md) · 中文

StudyHub 把调用模型的工作放到后台运行，你可以一边做题或聊天，一边等结果。后台任务包括：

- 「用资料出题」「从资料补题」生成题组，以及草稿里的「交给后台修题」；
- 「帮我弄懂」「修题」、把问答出成新题，以及按评分标准批改开放题；
- 校正「课堂实录」中较早的句子。

本文说明在哪里查看这些任务、每种任务会保存什么，以及失败时怎么处理。

## 把题目放到聊天旁边

StudyHub 可以在三个地方打开：DSH 左侧栏的 StudyHub、会话里的 StudyHub 标签页，以及 DSH 右栏。

想边聊边做题时，点题目上方的「在右栏打开」。题目移到右栏，主区域回到聊天。只有本轮还没做完、且 DSH 提供右栏时才显示这个按钮。

StudyHub 的背景和弹窗只画在自己的面板里，不会挡住旁边的聊天。

## 查看出题任务

出题任务显示在「学习库」页。每张任务卡显示：

- 当前阶段，以及已保存题数和要求题数；
- 「停止」：停止生成，已保存的题留在草稿里；
- 「查看执行过程」：逐步列出状态（「启动中」「进行中」「收尾中」「已完成」或「失败」）、token 用量和耗时。点「查看后台助手」可打开这一步的 DSH 子代理会话；
- 「打开草稿」：任务结束且已有草稿时显示；
- 任务失败时，显示原因和处理办法；问题出在模型时，还有「去配置模型」。原始错误放在「技术详情」里。

在步骤列表末尾展开「生成方式、用量与技术详情」，可以看到每个阶段是「DSH 子代理」还是「直接模型调用」、推理程度和子代理会话 ID，以及整个任务的 token 用量。

同一个学习库的出题任务一次只运行一个，后提交的任务排队等前一个结束。StudyHub 开始记录步骤之前提交的任务没有步骤列表，新提交一次才能看到。

### 运行中追加要求

在主对话里请 StudyHub 给正在运行的任务追加一条要求。它会出现在「补充要求」下，并附一条说明：

- 「正在运行的后台助手已收到，后续步骤也会照做」：正在运行、支持双向通信的步骤都已收到。
- 「部分后台助手已收到，其余步骤会照做」：部分正在运行的步骤已收到，其余步骤从下一步开始照做。
- 「会在后续步骤中照做」：正在运行的步骤都没有收到，要求会加进之后的模型步骤。

出题步骤运行时不接收消息，所以要求从下一步开始生效。后台修题时，如果 DSH 支持双向通信，要求可以送到正在运行的步骤。已经完成的批次不会改变。每个任务最多追加 20 条要求，每条 1–4000 字。

## 出题任务怎么做

出题以资料的逐字原文为依据：

1. 每组资料先由模型提取知识点，并摘出支持它们的原句。每组只做一次。
2. 题目分批处理，默认每批最多 5 题。每批由模型先确定有依据的答案和必要情景，再出题并自查，最后由独立审阅逐题判定。
3. StudyHub 在本地核对引用，并绑定已验证的答案和出处，这一步不调用模型。

时间与并行：

- 默认最多 3 批同时进行，整个任务最长 20 分钟（不算排队时间）。
- 每个阶段最多等待 10 分钟。
- 到时后，已通过审阅的题保留在草稿里。

想调整新任务的分批方式，打开「设置 › 出题偏好」，在「生成安排」里设置「同时生成的批数」（1–6）、「每批题数」（1–5）和「运行时限（分钟）」（5–60），再点「保存出题偏好」。已经开始的任务、继续补题的草稿，沿用开始时的设置。服务商容易限流时，可以调低「同时生成的批数」。每批题数越少，核验过的题保存得越早，但调用次数越多。后台修题的时限固定为 20 分钟。

同一页还可以保存默认题型、题数（1–30）、语言、难度和侧重点。初始默认是单选测验、10 题、跟随界面语言、混合难度和空侧重点。新任务里的单次选择优先；任务启动后保存自己的设置快照。为没覆盖的部分补题沿用原草稿的内容与生成安排，不受后来修改的库默认值影响；旧草稿没有记录生成安排时使用 3 批、每批 5 题、20 分钟。恢复默认只改待保存的表单，保存这些偏好不会开始出题。

每批只做一轮独立审阅：

- 通过的题保留，未通过的候选题连同原因一起列出。
- 不会自动循环修题、复审，也不会为凑够题数而额外生成。
- 想修复未通过的题，到草稿里点「交给后台修题」。这是你单独发起的另一个任务。

模型审阅不能证明题目正确，发布前请对照资料检查。

## 在后台获得讲解和改题

以下操作会为当前题目启动后台助教：

| 操作 | 位置 | 保存什么 |
| --- | --- | --- |
| 「帮我弄懂」 | 题目工具栏 | 解答作为问答追加到这道题。选了「补前置知识」时，还可以关联或新建最多 3 道前置题。 |
| 「修题」 | 「更多」菜单 | 直接修改这道题。旧版本保留在题目的修订记录里，可以撤销。 |
| 「出前置题」 | 「更多」菜单 | 按你写下的知识点出一道新的闪卡，作为这道题的前置题或一道独立的新题。 |
| 「出成前置题」「出成独立题」 | 已保存的问答下方 | 用这条问答出一道新的闪卡。见[讲解追问](followup.zh-CN.md)。 |

这些任务的规则：

- 点「提交到后台」（或问答下方的按钮）后才启动后台助教。题目下方会显示它正在做什么；你可以继续做题或聊天，结果进「信箱」。
- 提交时就固定了所用模型，之后换模型不影响已经在跑的请求。
- 每个任务最长 8 分钟，超时不保存任何结果。
- 失败时，题目下方显示原因，并提供「重新提交」和「改一改再提交」。

保存之前，StudyHub 会先检查结果：

- 校验和保存在同一步完成。结果不合格就什么都不保存，不会留下半份解答或孤立的前置题。
- 校验拒收一份回复时，StudyHub 会附上原因，用同一个模型直接调用重试一次，仍不合格才判定失败。超时、手动停止或题目已改动的情况不重试。
- 基于旧版题目的结果不会保存，请针对新版题目重新发起。
- 新题放进同一个题组，因此属于该题组的课程。资料无法支持的知识会另存为一份明确标注的补充笔记，放在资料里。

### 连续向同一个助教提问

DSH 以本地子代理运行助教时，在同一道题上连续使用「帮我弄懂」，会沿用同一个助教和之前的问答：

- 前后紧挨着提交的请求按顺序处理，使用同一个子代理会话。
- 切换题目、题目或其资料有改动、换模型或换界面语言时，助教重新开始。重新开始时会带上这道题最近 3 条问答。
- 最多同时保留 4 个助教。每个助教空闲 2 分钟或完成 8 轮后释放；失败、超时或 StudyHub 关闭时也会释放。释放后才到达的输出一律丢弃。

## 校正课堂实录

「课堂实录」可以在后台校正较早的转写句子。所用模型由「设置 › 音频转写 › 高级 › 专家选项」中的「校对与翻译用哪个模型」决定：

- 「Gemini（同样先免费后付费）」：由 Gemini 校正。请确认 Gemini 当前的账户、地区和额度要求。
- 「对话当前使用的模型」：DSH 支持子代理时用子代理运行，否则直接调用同一个模型。
- 「自动（有对话模型就用它，否则用 Gemini）」：按上面两种之一处理。

每次校正最长 60 秒。如果校正期间相关句子有改动，这次结果不会合并，请重试。

## 选择模型

StudyHub 调用模型时按以下顺序选择：

1. 「设置 › 学习库与模型」中指定的「生成模型」；
2. 没有指定时，用会话里为下一条消息选好的模型，即使 DSH 还没用过它；
3. 都没有时，用 DSH 的默认模型。

同一设置里的「推理程度」作用于出题和后台助教。读取已保存会话的模型时，不会启动该会话的代理；内容未变的轮询也不会重放长会话。

## 处理失败的任务

- **错误和超时显示真实原因。** 即使学习库没有别的变化，失败状态也会及时显示。晚到的输出、基于旧版题目的结果，都不会覆盖较新的内容。
- **`NO_ADAPTER`** 表示运行任务的 DSH profile 里没有这个名字的服务商。常见情况是服务商只在 DSH 网页版配置过，桌面版没有；网页版能用，不代表桌面版也有。在该 profile 的 DSH「设置 › 模型」里添加服务商后重试。音频导入会从已保存的转写继续，已经转写过的部分不会重新转写。
- **永久性错误立即停止。** 音频校对和翻译遇到服务商缺失、密钥问题或额度用完时，会立即停止这一步，不重复请求，因为重复请求无法解决这类问题。StudyHub 保留检查点，也不会把这类错误当成格式问题反复纠正。
- **不换路线重做。** 子代理一旦启动，失败就结束任务，不会改用直接调用再做一遍。唯一的例外是上文后台助教的「拒收后重试一次」。
- **诊断更清楚。** DSH 没有报告子代理失败原因时，StudyHub 会在释放前从子代理已保存的会话里读出原因。错误信息更清楚，不代表服务商已经可用。

## 更新与重启 DSH

- **重启 DSH 前，先等后台任务完成或把它停掉。** StudyHub 的任务队列保存在内存中，重启会丢掉排队中和未完成的工作。刷新 StudyHub 页面不会重启这个队列。
- 应用内「一键升级到」新版本时，会先检查有没有正在运行的后台任务。如果有，会提供「停止任务并升级」，已完成的部分会保留。

## 开发说明

### StudyHub 如何使用 DSH 子代理

- **能力判断**（`lib/host-capabilities.js`）：DSH 提供官方 `spawn` provider 且支持 `toolFilter`、选定模型时支持 `agentOptions`，并且有运行中的父代理或下面的桌面协调代理时，这一步用子代理运行；否则直接调用模型，并在步骤里注明。本地结构检查和引用核对从不创建子代理。
- **插件自管的步骤**使用一次性子代理，`toolFilter: {allow: []}`。包括出题（含「从资料补题」）、发布审阅、按选区出题、翻译和音频步骤。结果 JSON 由插件直接回收，不会流进主对话。（`lib/generation-agent.js`）
- **草稿后台修题**：父代理正在运行，且 DSH 提供 `startContinuable`、`sendMessage`、`drainContinuableChildren`、`subagent/end` 事件以及父代理作用域里的 `send_message` 时，每个阶段以可持续子代理运行。子代理只能用 `send_message`，而且只能发给父代理。（`lib/generation-continuable.js`）
- **后台助教**使用 `toolFilter: {allow: []}`。子代理不能直接写学习库，由服务校验并保存它返回的 JSON。（`lib/assist.js`、`lib/assist-child.js`）
- **输出**只有子代理以 `completed` 结束时才算数。失败或中断的片段不会被当作最终答案，所有句柄在结束后释放。
- **桌面面板没有运行中的父代理时**：如果 DSH 提供 `agents.create`，且 StudyHub 能读到已保存会话的工作目录（来自会话头、`sessionPersistence.stat` 或 `sessionQuery.observeSession`），就新建一个空闲的协调代理，在它的子代理里运行实际工作。协调代理不接收模型任务，也不会恢复或驱动你的聊天。两者都用选定的模型，子代理返回后一起释放。
- **模型选择**（`lib/host.js`）读取与 DSH 输入框相同的 `modelSelection.next` 投影。对于尚未运行的已保存会话，通过 `sessionQuery.observeSession` 读取保存的投影后立即释放观察句柄，并按 revision 缓存结果。
- **诊断**：DSH 的进程内 driver 不一定填写 `SubagentResult.diagnostic`。这时 StudyHub 从子代理会话读取 `turn/end.reason.error.message`，读不到时保留 `stopReason`。
- **token 用量**：子代理的用量取自 DSH 对该子会话的用量记录，在这一步结束后读取。

### 桌面版与网页版的安装包

DSH 桌面版的 profile 可以安装一份独立的安装包副本，网页版 profile 则可以链接工作区。修改工作区不能证明桌面版已经更新。更新安装包、重启 DSH、验证运行中的功能是三个独立的步骤。DSH 0.2.0-rc.2 桌面版的插件管理器在已安装依赖更新后返回 `restart-required`。

### 尚未实现：出题阶段之间复用子代理

「帮我弄懂」助教的复用已经实现（见上文），出题阶段之间的复用还没有。DSH 0.2.0-rc.2 的 `SubagentRuntime.startContinuable` 和 `sendMessage` 让空闲的可持续子代理收到消息后开始下一轮，已卸载的直属子代理也可以从持久化会话恢复。一次性 `start` 的运行句柄没有这样的契约，保留句柄不等于复用。

设想按任务和角色复用：

- 同一批次的作者在审阅反馈到达后继续修题；
- 审阅始终独立，作者不审阅自己的输出；
- 不同批次并行执行，不能只按 job ID 共用一个代理。目前服务只向宿主传阶段和 job ID，还需要显式传入 part、角色、题目或资料版本；
- 课堂实录的历史校正仍保持有界的新任务，因为它的输入已经包含窗口、记忆和证据，长期历史反而容易带着旧的听写判断。

实现时需要：按会话、模型、角色、批次或题目版本确定键；同一子代理一次只处理一条消息；等待每一轮真实的完成事件，而不是把上一轮结束或消息回执当成新结果；保留现有的版本校验、取消、超时和晚到输出拒绝；空闲和作业结束时明确清理；桌面协调代理归整个作业所有。换模型、资料或题目版本变化、任务失败时应新建代理。

### 验证范围

以上行为用隔离的临时学习库、模拟模型适配器和本机官方 DSH SDK 验证，覆盖生命周期、路由、校验和保存。它们不能证明用户的鉴权、网络连通或真实模型质量。2026-09-30 的验证记录见下文「历史记录」。

## 历史记录

以下是 2026-09-30 前后（1.3.2 开发期间）的实现和验证记录，保留作开发参考。当前行为以上文为准。

### 侧栏遮挡与执行记录（初版）

- 原实现的 `Part 1/6 · Repairing flagged questions` 来自后台队列的阶段字符串：每批最多 5 题，作者调用后本地验证引用和结构，再调用编辑审阅，有问题则调用作者修复并复审。这些都是直接模型调用，没有 DSH 子会话。（之后出题改为每批只做一轮独立审阅，修题改由你单独发起。）
- 新实现沿用该质量流程：原生宿主有运行中的父代理和 `spawn` 能力时，每个模型阶段通过 `ctx.subagents.start` 创建有名称的子会话，跟随当前模型选择。
- 遮挡来自学习根元素的 `::before { position: fixed; inset: 0 }`，它画满了整个宿主窗口。修复后背景直接画在学习元素上，原生挂载增加独立的布局与绘制容器，弹窗也限制在该容器内。移到侧栏的同时恢复主区聊天。
- 初版验证：59 项自动测试通过。浏览器在 440px 宽的模拟侧栏中打开弹窗，确认遮罩没有超出侧栏、左侧按钮仍可点击；用模拟任务记录验证了阶段翻译和子代理 ID 的显示。

### 桌面端后台助教兼容

- 问题：桌面面板可以有已选模型和已保存会话，却没有运行中的父代理。旧助教把这当作完全不支持后台工作，报「当前宿主暂不支持后台助教」；实录历史校正还存在模型包装丢失 `spawnCorrection` 能力的问题。
- 修复后的行为见上文「在后台获得讲解和改题」和「开发说明」。原生助教改用 `toolFilter: {allow: []}`；旧的 `study_workspace` 允许列表测试改为这一契约，因为子代理自行写库会绕过超时和题目版本校验。语言包装和轻量包装都保留 `spawnCorrection` 能力。
- 接口依据：本机官方 `@deepseek-ai/dsh` 0.2.0-rc.1 中 `dsh-subagent/lib/types/types.d.ts` 的 capability、parent、signal、start/result/dispose 契约。没有把 Codex 自身的代理工具当成产品宿主接口。
- 冷会话的模型选择另外核对了桌面安装包 0.2.0-rc.2 的官方实现：输入框使用 `modelSelection.next`，尚待使用的选择不会被正在结束的旧模型请求覆盖。没有投影的兼容路径遵循同样的 pending/last-used 规则。
- 桌面发布：有进行中或排队中的出题任务时，不能只凭宿主通用的任务检查判断可以重启，因为插件另有内存任务队列。
