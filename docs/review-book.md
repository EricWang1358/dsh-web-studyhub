# Review book

[中文](review-book.zh-CN.md)

The **review book** (复习全书) is a book page per course, made from the [course outline](course-outline.md) and the explanations the review book task writes for each knowledge point. It is for reading and studying; questions appear in it as links that take you to practise them. This covers milestones M1 (reading), M2 (editing), M3 (Q&A in the book), M4 (explain while reading), M5 (answer cards of analysis questions), M6 (lookup pages and export) and M7 (the final week) of the [design](plans/review-book.md). Checked against the code on 2026-10-11.

## Open it

In the sidebar, under **Now and then**, select **Review book**: it opens the book of the current course when it is written, and otherwise the **Course outline** page, which says in one line what the review book is and offers **Generate outline** and **Write the review book**. In the book's header, a course without an exam date shows **Set the exam date to start the final week** (it opens the course settings), and a course whose exam is further away than the window says **The final week starts N days before the exam**.

On the **Course outline** page, once the review book is written, **Open the book page** sits next to the line about the learning order; an opened knowledge point has its own **Open the book page**, which opens the book at that point. **Back to the outline** returns.

## What the page shows

| Part | What it is |
| --- | --- |
| Contents (目录) | Every heading of the book: the outline's chapters, sections and knowledge points. **You are here** marks the heading on screen. Select a heading to go there. At wide widths it sits beside the text; at narrow widths it is folded under the title (**Contents**) and folds again after a jump. |
| Chapters | One per chapter of the outline. Only the chapters you open are drawn, so a big book stays light; the one you were reading opens by itself. |
| A knowledge point | Its explanation (in the sample papers, key points, explanation, example, extra beyond the materials, sources as footnotes) with **Practise 5** and **Questions and answers**, then **Questions of this point**: its questions as they are now, the first five as links and **N more** for the rest. A point without questions says **This point has no questions yet.** and offers **出题** (make questions). Without sample papers nothing about exams is shown. |
| Not placed (未归位) | Only when the outline was rebuilt and some of your own text has no knowledge point any more; each piece is headed with its old title and **no longer a point of the outline**. |

## The links

- **A question** (`studyhub://card/<deck>/<card>`) opens the practice page on that question, the same answering, grading and scheduling as everywhere. **Back to the review book** returns to the book at the heading and scroll position you left.
- **Practise 5** (`studyhub://practice?heading=<id>&n=5`) practises the first five of the point's questions in the order a practice round takes them (due, weak, new, then the rest); an unfinished round of exactly those questions goes on. A question answered well a moment ago is no longer due, weak or new, so it comes after the others.
- **Questions and answers** (`studyhub://qa?heading=<id>`) opens, under the point, what was asked about it: follow-ups kept on its questions, the reader's notes on passages inside its places, and question-and-answer cards. Each item is folded; open it for the answer, then go to the question or to the original passage.
- A footnote mark and the sources list open the reader at the quoted sentence.
- A link to a question that was deleted reads **This question was deleted**. Links only navigate; they never run anything. Any other link opens normally.

## Edit it

Above the book, **Preview** and **Source** switch how it is shown; the choice is remembered per course. **Source** shows the raw Markdown of ONE file in the Markdown editor; the file picker lists every file in reading order: each knowledge point's **explanation (generated)** and **my notes**, and 未归位. Any file can be edited.

- **Save** saves the file. A heading you type (`## …`) gets a stable id on save (written at the end of its line, hidden in the preview); an id is never given twice and never taken from the outline's headings. **Discard changes** goes back to the saved text. While there are unsaved changes the file picker is locked, so switching files never loses them.
- **Editing a generated file makes it yours** (**Changed by you**). When the explanations are written again, a file you changed is never written over: the new text waits under it in the preview as **New generated text**, with **Take it** and **Ignore** (an ignored text is not offered again; a newer one is). A file keeps up to three waiting suggestions, newest first, each with its own buttons, so one never pushes out another. A file you did not change follows the new explanations by itself. Your notes are never touched by the program.
- **The book was updated.** A save is checked against the version of the file you started from. When the same file was changed meanwhile (by the program or in another tab), your text is saved anyway and the other text waits as a suggestion (**The book was updated**, with **Take it** and **Ignore**); other files are not affected.
- **Back to the previous version** takes the file's previous text back, one version at a time; any write of the program can be undone this way. The last 20 versions of a course are kept (fewer when they are large), outside the library's materials; a portable backup carries them and a restore brings them back. Two copies of the app writing the same book at the same moment may lose a version from this history, never the book.
- The preview of an edited file still draws the question links, footnotes and 本节问答, and never renders HTML: tags stay visible as text. A heading you typed is in the contents and can be reached from it, and the way back after practice returns to it.

## Q&A in the book

A follow-up you get while practising (an answer to **追问** or **帮我弄懂**) stays on its question as before. To keep it in the book too, select **Add to the review book** under it, on the practice page or in a point's **Questions and answers**; it then reads **Added · Take back**, and selecting that takes it out of the book again (the question keeps it either way).

- It goes into the point's own **Q&A** file, shown after your notes: the question's link first (when nothing under the point links that question yet), the follow-up quoted under it. A question of no knowledge point goes to 未归位. The same follow-up is never added twice.
- Once in the book it is your text: edit it like any other file (**Source**, the file **· Q&A**); changing the question later does not change it. While the Q&A file is open in the editor, an add that lands meanwhile is merged into your save: neither is lost.
- **Add to the review book automatically** (a small switch beside the buttons on the practice page, and in **Settings › Practice**; off by default): when on, each new follow-up or 帮我弄懂 answer that arrives while the practice page is open is added by itself. What is already in the book stays; switching changes only the next Q&A. If an automatic add fails, a small notice says so and the button stays. Only Q&A made on the practice page are added automatically.

## Explain while reading, add a paragraph

In **Preview**, select some words of a knowledge point (its explanation or your notes): a small panel opens under them with **Explain** and a field **Let the AI write a paragraph…** (more detail, an example, a comparison table). Under each point's heading, **Add a paragraph here** opens the same field. Either starts a task you can follow, stop or retry on the **Tasks** page (no estimate, no confirmation); without a model the panel shows the shared model setup note, and reading and editing go on.

- The answer comes from the point's own materials (the same grounded rules as asking about a passage in the reader). Quotes are checked word for word in the materials and dropped when not found; what goes beyond the materials is listed apart under **Extra (beyond the materials)**. A point without materials is refused plainly.
- It is written as a NEW paragraph into the point's own notes, never over existing text, shown right after the paragraph that holds the words you selected (it follows that paragraph when the paragraph moves or changes a little; when the words are gone it moves to the end of the point, marked **Its place has changed**). **Add a paragraph here** puts it under the heading. Its first line says what it is about: **About: “…”**.
- It is yours from then on: edit it in **Source** like any text; the book's updates never change it. **Keep** marks it as kept, **Write again** asks the same again, **Delete** takes it out, and the field under it asks a follow-up whose answer goes right under it.
- Like the rest of the book it is a reference, never material for questions.
- While your notes are open in **Source**, a paragraph that lands meanwhile is carried into your save: neither is lost.
- Known limits: the page checks a task it started every 1.5 s, only while that task runs. The preview and development server has no background-task executor, so these tasks (and writing the review book) run only in the real host.

## Answer cards of analysis questions

For a case or analysis question (an open question with marks and marking criteria, 大题) the answer is not one paragraph but one checked **answer card** (答题卡). After the question is graded on the practice page, its reference answer shows as before with **Generate answer card** under it (a task you can follow on the **Tasks** page; no estimate, no confirmation; without a model the shared model setup note says where to set one up). There is ONE full version of the card, never a short one:

| Part | What it holds |
| --- | --- |
| Question type and signals | The type (risk scenario, availability, performance, capacity and RAID, domain decomposition, cloud migration and choice, or general analysis; a course may add its own) and the words of the stem that point to it, with the stem's own sentence. |
| Stem facts | Each fact the answer uses, with its quote from the question or the case. |
| Concepts | Name, the material it is defined in, and the definition in the material's own words. |
| Assumptions | What the stem does not say, stated explicitly (a number the answer needs is stated here, never invented). |
| Reasoning, conclusion | The type's solving steps with the formulas filled in, then the answer. |
| Why it meets the goal, cost and failure handling, how to verify | The justification an examiner looks for. |
| Pitfalls, marks map | Typical mistakes; for each marking point of the rubric, the sentence of the card that earns it. |

What the program checks: every quote and definition is looked up word for word in the stem, the case or the materials (spacing and case do not matter); one that is not found is marked **Not verified**, and so is an elided quote ("…") and one too short to prove anything. A converted material with HTML (a PDF's tables) is read as its visible words: tags out, a cell boundary as a space, entities decoded, so a definition in a table cell is found and shown in those words. Which marking points are covered is counted by the program, not by the model, and numbers that stand in neither the stem, the assumptions nor the concepts (and are not a computed result) are listed. An independent review then looks for claims the stem does not support, contradictions of the stem, a missing cost and invented numbers; when the checks or the review find something the card is written once more (two or three model calls in all). The card shows its state: **Checked** (every check passed), **Partly unchecked**, or **Changed since** when the question, its marks, its rubric or its reference answer was edited after the card was made. **Checked ≠ correct.**

- The card is kept beside the question (`answerCard`); the question's own answer, its review schedule and history are never changed. It comes with the reveal like the reference answer, never during a mock exam, and a question in an unsubmitted mock exam gets none until it is submitted.
- When the deck's materials are longer than the budget (24,000 characters), the model is given the passages that share the most terms with the question (its stem, topic, concepts and rubric) first, then the rest in reading order; the quotes are still checked against the whole materials.
- Known limits: a card repaired after the checks or the review is checked by the program again but not reviewed again; the number check is a heuristic (a level such as "RAID 5" the stem does not name may be listed, and an input written after a calculation may be missed); the question type is chosen by the model from a keyword guess, and a course's own types are set through `course.save {caseTypes}` (no page for it yet).
- **Add to the review book** under the card puts it into the course's book, in the point's Q&A file under the question's link (a case question of no point goes to 未归位), once; **Added · Take back** takes it out. In the book it is your text like any other.

## Lookup and export (your printable CP)

A book read front to back is hard to search in an open-book exam. So the book has **lookup pages**, made from the book every time (never kept or edited by hand), and they lead the export: from a question to the section, the definition and the steps.

- **Codes.** Every heading has a stable code, its id in capitals (`H12`), shown beside the heading on the page and in the margin of the export (`### 1.2 Title 〔H12〕`). A code is never renumbered: inserting, moving or removing sections changes the numbers (1.2 → 1.3), never the codes. The questions of a point are numbered by its code, `H12-Q1`, `H12-Q2`…; 未归位 is `U`.
- **Lookup** (the third view above the book, beside **Preview** and **Source**): **Contents** with the codes; **By question type**, the cheat-sheet table: for each question type that has an answer card in the book (and each type of the course's own), its signals in the stem, its steps and formulas, its most common mistakes and the cost an answer must state (a built-in type in the book's language, Chinese or English; a course's own type as it was written), where it is (codes and question numbers), above them the answer order every answer follows (stem facts → explicit assumptions → design or calculation → why it meets the goal → failure and cost → how to verify); **By concept**: the concepts of the answer cards, a bold term that starts a definition in your notes or the explanations (`**term**: …`, `**term** is …`, `**术语**是…`, or any bold term on a line that starts with 定义 / Definition) and any word you mark `[[term]]`, each with its codes; **Mistakes by point**: the follow-ups you put into the book (what you had to ask) and the pitfalls of the answer cards. Select a code to go to its heading. Without answer cards nothing about question types is shown.
- **Export** (in the header): one Markdown file, without or with the **answer key**. It starts with the book's title and the lookup pages, then the book in reading order (each point: the explanation, its questions when you choose them, your notes, its Q&A; 未归位 last; with the answer key, the key last). The program's marker comments are taken out (a heading's id becomes its Pandoc anchor `{#h12}` and its margin code; the content of Q&A, answer-card and AI blocks stays); **Which questions to print**: **Only the questions the book links** (the default: those of the Q&A files and the links you wrote yourself), **Also every point's own questions** (all of them, with their options, under each point; the most pages), or **No questions** (question links left out). A printed question link becomes the numbered question with its options (A., B., …) the first time it appears in its point; a link to a deleted question, **Practise 5** and **Questions and answers** are left out; a source keeps its words; footnotes are named per file, so they never collide. The answer key lists exactly the printed questions under the same numbers, and the estimate follows the choice: the answer (the right options, the blanks), the explanation, an answer card in full. The same book always gives the same bytes. **Export as files…** lists the folder form: one file per part (`000-front.md`, `001-h3.gen.md`, …) and `book.yaml` with their order; the app has no zip writer, so they are downloaded one by one, and `pandoc $(sed -n 's/^  - //p' book.yaml)` reads them as the same book.
- **Not printed.** Text between `<!-- sh:noprint -->` and `<!-- /sh:noprint -->` (written in **Source**) is left out of the export and of its estimate; the page still shows it. A marker never closed is ignored (its text is printed).
- **Pages.** The dialog shows an estimate of the A4 pages of each choice by a fixed rule (about 40 Chinese characters or 80 other characters a line, 45 lines a page, a blank line half a line): an estimate, not a measurement. **Page limit** (empty by default) is saved as `settings.book.pageLimit`; once set, a quiet line in the header says **Export about N pages / limit M** (the book without the answer key) and how far over it is.
- Known limits (accepted): the concept rule reads only bold terms at the start of a line, bold terms of a 定义 / Definition line and `[[term]]`; `course.book.open` carries the course's question-type catalogue (`caseTypes`, a few kB) on every open; with a page limit set, the header's line runs the whole export again (estimate only) after each change of the book, which costs more on a very large book. The header's estimate is of the default choice (linked questions, no answer key).

## The final week (期末一周)

When a course has an exam date (**Course settings**) and a review book, the program plans its last days over the book's points: no model call, the same answer every time for the same book, answers and marks, and every day says in one line why it holds what it holds.

- **Learn days, then look-over days.** The days from today to the day before the exam: the last two study days (one to three; all of them when fewer remain) are **look-over days** (翻看): no new questions, every point once, those with the most mistakes first, then the weakest; the very last full day also has a **mock paper**. The days before are **study days**: read a point, then **Practise 5** (its next five questions). The exam is today: one look-over day without a mock. With no exam date there is no plan; the book works as before.
- **Which points first.** A point weighs 1 + the sample papers that tested it (the outline's 样卷考过); without sample papers every point weighs the same. Its weakness comes from its questions (a weak one counts most, then new, learning, familiar; a due one more). The most important points (weight × weakness) are learnt first; each day carries about the same minutes (reading its text, about 300 characters a minute, and its five questions), within the day in reading order. A point is learnt once: when at least five of its questions (or all, when it has fewer) were answered on one day, or, for a point without questions, when it is marked **Read it**. When there are more points than time, the days carry more than the minutes of a day (**Settings › Practice › Final week: minutes a day**: 60, 90, 120, 180 by default, or 240) and say so (**More points than time: …**): nothing is left out. Made again tomorrow, the plan keeps what was done on the day it was done and spreads the rest from today; after doing exactly today's points, the next days are the same as planned.
- **On the home.** Under **What to do first today**, a **Final week · course** card for each active course (a parked course is left out) whose exam is within 21 days (**Settings › Practice › When the final week begins**, 7–60 days), with today's kind of day, its reason, its points (**Read** opens the book at the point, **Practise 5**, on a look-over day **Look over**), **Look over the book** and **Make a mock paper from these points**. A course other than the current one is made current before its book opens (the book page shows the current course's book).
- **In the book.** **Today's points** in the header opens the same day under it. The fourth view, **Look over** (翻看), lists every point in the plan's look-over order; each shows its **mistakes** first (what you asked and put into the book, the answer cards' pitfalls, what you had explained with 弄懂), its **Explanation** folded (drawn only when opened), **Looked over** (kept per course: the progress survives a reload) and **Into the mock paper**.
- **Mock paper.** **Make a mock paper from these points** (the points picked in Look over, else today's, else the whole book) first says how many questions those points have, how many single or multiple choice questions can go in and what is left out by kind (the mock exam takes single and multiple choice only), with the number of questions (1–50, at most 20 by default) and the time limit (the course's writing time, else 30 minutes); **Start the mock paper** starts the ordinary mock exam over them, due and weak questions first. The exam page, its timer, its submission and its report are the same as always; its way back is the book.
- Known limits (accepted): days off are only an argument of the operation (`daysOff`, no page for them); the reading speed is a fixed rule; a point is learnt by its answers of one day, so answering five of its questions in a mock exam counts too; opening another course's plan from the home makes that course the current one; in Look over with **Today's points** open there are two mock-paper buttons with different scopes (today's points, and the points picked or the view's); the look-over order is fixed for the day (a point looked over stays where it is, greyed); the plan of a day is kept until the library or the book changes, so a question that falls due later that day moves a point only after the next change.

## Where it is kept

The book is one hidden record of the library (`provenance: 'course-book-doc'`) holding Markdown files: for each knowledge point a generated file (the program's) and your own file (empty in M1), a manifest (the outline's tree with a stable id per heading) and a file for text without a point; the final week's **Read it** and **Looked over** marks are a day per point in the same record (`bookDoc.marks`), never a file. It is a reference, never material: it is not in the materials list, the pickers or the search, not in the retrieval index, not counted in the assistant's library context, and a request that names it as material is refused. Questions keep citing the original materials.

Opening the page makes the files the first time (no model call) and brings the generated ones up to date with the explanations. The list of a point's questions is not kept in a file: it is read live each time, so new or deleted questions change no file, and an open that changes nothing writes nothing to the library. Your own files are never changed by this. When the outline is rebuilt, each knowledge point keeps its files and heading id if a new point holds the same materials (else one of the same title); what cannot be mapped goes to Not placed; nothing is deleted.

## Rolling back

Upgrade only. An older release (3.3.0 and before) does not know this record: it keeps it as it is, but may list it as a Markdown material named **复习全书 · course** whose text is one line, **复习全书（由 StudyHub 3.4 以上管理，请勿删除）** (the review book, managed by StudyHub 3.4 or later; do not delete). Deleting that entry in an older release deletes the book's files. The version history (the `book-history` folder of the library) is ignored by older releases. A question's answer card (`answerCard`) is kept as it is by an older release, which shows only the reference answer. The export writes nothing; an older release forgets the page limit (`settings.book.pageLimit`) the next time it saves the settings, and drops the `mistakes` of a course's own question types when it saves the course. The final week writes only its marks (`bookDoc.marks`, kept as they are by an older release) and an optional `settings.book.crunchWindowDays` (forgotten by an older release when it saves the settings); its mock paper is an ordinary exam run.

## For developers

- `course.book.open {course?}` (lib/course-book-files.js) answers `{ status, course, revision, title, language, notes, papers, nodes, unplaced, missing, changed }`; `nodes` are `{ hid, key, title, number, depth, leaf, gen, mine, questions: [{ deckId, cardId, prompt }], questionTotal, children }` (`questions` read live, at most 200), `missing` the questions the files link that are gone. It looks at the library first and writes the record only when a file changes; it is never in the snapshot.
- `course.book.save {course?, file, text, version}`, `course.book.suggestion {course?, file, action: 'accept' | 'ignore', version}`, `course.book.revert {course?, file}` (lib/course-book-edit.js): one writer queue (per library folder, first come first served), one store transaction each; they answer the book like `course.book.open` plus `write` ('saved', 'merged', 'unchanged', 'accepted', 'ignored', 'reverted') and `history` ({ file: versions kept }). The history is lib/course-book-history.js: `book-history/<hash of the course>.json` under the library folder, written through a temporary file and a rename after the book's own write.
- `book.qa.add {course?, deckId?, cardId, followupId}`, `book.qa.remove {course?, followupId}`, `book.qa.list {course?}` (lib/course-book-qa.js; the block is lib/course-book-qa-text.js: `<!-- sh:qa card=… fid=… -->` … `<!-- /sh:qa -->`), in the writer queue like the saves. The queue is one per library folder, joined at the call before anything is read, so the book's writes are served in the order they were made. `book.qa.list` reads every file of the books each time a question opens (a known limit: fine at today's sizes, an index if books grow very large). The automatic adds are made by the practice page itself (ui/review/QuestionRun.jsx), so an answer that arrives while the 讲解 section is folded away is still added. `settings.book.set {patch: {qaToBook: 'manual' | 'auto'}}` (lib/book-settings.js, `settings.book`).
- `generation.courseBook.explain {course?, heading, words?, instruction?, mode: 'explain' | 'write' | 'here' | 'follow', after?, replace?, language?}` starts the Job `course-book-ai` (lib/contexts/generation/book-ai/: one model call, the reader's grounded prompt from lib/ask-prompt.js); its block is written by the materials context's `book.aiWrite` in the book's writer queue (lib/course-book-writer.js) with history. Refusals: course-book-ai-no-book, course-book-ai-no-point, course-book-ai-no-materials, course-book-ai-no-request. The block format and its placement are lib/course-book-ai-text.js (`<!-- sh:ai id=… at=… state=new|kept mode=… ask=… -->`). `course.book.block {course?, file, id, action: 'keep' | 'delete'}`.
- `generation.answerCard.build {cardId, deckId?, again?, language?}` starts the Job `case-answer-card` (lib/contexts/generation/answer-card/: write, review, one repair; steps booked under `case`); the card is saved by the bank context's `card.answerCard.set`, refused (`answer-card-stale`) when the question changed since the task began. Refusals: answer-card-no-card, answer-card-not-case, answer-card-in-exam, answer-card-exists, answer-card-running. The card format, the checks, the three states and the Markdown are lib/answer-card.js (`renderAnswerCard` is deterministic); the question-type catalogue is lib/case-types.js (`course.save {caseTypes}` adds a course's own). `book.qa.add {cardId, deckId?, answerCard: true}` / `book.qa.remove {cardId, answerCard: true}` write the block `<!-- sh:card card=… -->` … `<!-- /sh:card -->`; `book.qa.list` also answers `answerCardIds`.
- lib/course-book-links.js (browser-safe): the three question links (`parseBookLink`), heading ids on the heading line (`## Title <!-- sh:id h3 -->`, `assignHeadingIds`: given once, never reused), `bookIndex` (the heading tree with the question links under each heading), `stitchBook` (files in order, footnotes named per file), `plainBook`.
- `course.book.export {course?, form?: 'single' | 'folder', answerKey?: boolean, estimateOnly?: boolean}` (lib/course-book-export-op.js, read only: the book as `course.book.open` would give it, nothing written) answers `{ status, course, form, title, language, filename, text | files + manifest, questions, estimate: { pages, book, withAnswers, columns, rows } }`; the Markdown is lib/course-book-export.js `exportBook` (pure, browser-safe, deterministic), the lookup lib/course-book-lookup.js `bookLookup(book, { caseTypes, answerCards })` and `renderLookup` (codes: `codeOf`). `course.book.open` also answers `answerCards` (a summary of the answer cards of the book's questions) and `caseTypes` (the course's catalogue, `own: true` on its own types), from lib/course-book-cards.js. A question type may carry `mistakes` (lib/case-types.js). `settings.book.set {patch: {pageLimit: 1–2000 | null}}`.
- `book.crunch {course?, date?, minutesPerDay?, daysOff?, reviewDays?}` (lib/course-book-crunch.js, read only) answers `{ status: 'ok' | 'far' | 'past' | 'no-exam' | 'no-book' | 'no-course', course, examDate, daysLeft, window, revision, plan, points }`; the plan is lib/crunch-plan.js `crunchPlan` (pure, browser-safe, deterministic: `days: [{ date, offset, mode: 'learn' | 'flip' | 'off', mock, points, done, minutes, reason: { code, … } }]`, `today`, `order: { learn, flip }`, `merged`, `unlearned`); `points` are `{ id, key, code, title, tested, weakness, questions, weak, due, fresh, size, pitfalls, done, seen }`, the 易错点 from lib/book-flip.js `pointMistakes(book)`. `book.crunch {all: true, date?}` answers the active courses whose exam is within the window (`settings.book.set {patch: {crunchWindowDays: 1–60 | null}}`, default 21) with today's day and its points. The minutes a day are `settings.book.crunchMinutes` (15–960, default 180; an op's `minutesPerDay` wins).
