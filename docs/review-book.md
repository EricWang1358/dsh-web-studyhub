# Review book

[中文](review-book.zh-CN.md)

The **review book** (复习全书) is a book page per course, made from the [course outline](course-outline.md) and the explanations the review book task writes for each knowledge point. It is for reading and studying; questions appear in it as links that take you to practise them. This covers milestones M1 (reading), M2 (editing), M3 (Q&A in the book), M4 (explain while reading), M5 (answer cards of analysis questions), M6 (lookup pages and export) and M7 (the final week) of the [design](plans/review-book.md). Checked against the code on 2026-10-16.

## Open it

In the sidebar, under **Now and then**, select **Review book**: it opens the book of the current course when it is written, and otherwise the **Course outline** page, which says in one line what the review book is and offers **Generate outline** and **Write the review book**.

The book opens where you were: the point and the place in it (the heading and how far down the window it was) are kept in this browser per library and course, written when you change point, every half second at most while you scroll and when the page is hidden, so a reload or the next day comes back there (without the browser's storage, private or full, the place still lasts until the page is reloaded, so the way back from practice lands there). A link that names a point (**Open the book page** of a point on the outline, **Read** on the home's final-week card, the way back from practice) wins over the kept place; with neither, the book opens at its first point. Only the way back from practice puts the focus on the point's heading. The book always opens on the reading surface: a view (editor, look over, lookup) is never remembered (an earlier version's remembered **Look over** opens once, then is forgotten).

The header scrolls away with the page: a quiet **Back to the outline**, the title **Review book · course** (with more than one course the course name is the home's course switcher; hover it: it changes the current course of the whole app), a status line only while the book is being written (**Updating the review book… See progress**), and the one-off notices (**Switched to the course X**, notes that moved). When the page comes back into view (the window regains the focus, the tab becomes visible, or the focus comes back from the main chat's box), it asks the book's revision (`course.book.revision`, one number) and reads the book again only when it changed, keeping the heading you are reading where it is on screen: what the main chat wrote shows up in place. Never while the editor is open.

On the **Course outline** page, once the review book is written, **Open the book page** sits next to the line about the learning order; an opened knowledge point has its own **Open the book page**, which opens the book at that point. **Back to the outline** returns.

## How the explanations are made

**Write the review book** is a quality workflow, not one prompt (details and call counts: [course outline](course-outline.md#the-review-book-explanation-layer)):

1. **Inventory**: every page range of every material is read in parallel; the model lists each term, definition, concept, formula, step, rule, example, claim and warning with its page and a quote, checked word for word.
2. **Outline**: the items are grouped into knowledge points in learning order; every item is in exactly one point (else in **Other / not placed**).
3. **Checklist**: each point gets the items it must cover (by the **Explanation depth**; a stressed or exam-tested item always).
4. **Write**: each point in its own call (a big one in passes of whole pages), all in parallel, freely, explaining every checklist term at first use, with transitions and **（资料以外）** for what the materials do not say.
5. **Cite**: every cite is found word for word in the point's own pages, or dropped.
6. **Review**: an independent call checks the text against the checklist and the pages.
7. **Judge**: an item is covered only when the writer claimed it, its name is in the text and the reviewer did not flag it.
8. **Repair**: only the flagged parts, at most twice, each time reviewed again.
9. **Short points** stay marked **Short: N concept(s) missing**, never shown complete; the task ends partial and **Fill the gaps** or the next update mends only those.
10. **Glossary** (生词与概念): made by the program from the covered items, alphabetical, in **Lookup**, each entry linking to its point.

**Coverage** is measured against that inventory at three levels, shown on top of the book's contents and on the outline page: **materials and pages** read, **knowledge points** complete (every must item covered, nothing unsupported), and **concepts** covered. Never against a length or a template.

## Reading

There is one reading surface and no mode switch on the page. By default it shows **one knowledge point at a time**, under its chapter and section path, with **Previous knowledge point / Next knowledge point** at its bottom (with the neighbour's title; on the first point the first card is off and looks it). Where you are and **‹ ›** are in the bar. The ← and → keys do the same (not while you type in a field, use a menu or have words selected; the **?** sheet lists them). A new point starts at its top, just under the bar; the contents marks it. A heading of the contents, a code of **Lookup pages**, **Read** of **Today's points** or **Look over** shows that point (a chapter or section: its first point).

**More › Read whole chapters** (a check, remembered per course in this browser) shows the chapters in one scroll instead, each point folded to its title and one line (its takeaway) except the one being read; select a point's title to open or fold it; ← → still go point by point. Switching keeps the point you are reading. The way back after practice returns to the same point and scroll position, with the focus on the point's heading.

## More

**⋯ More** in the bar holds everything that is not reading, in four small groups (a one-line hint only where a rule is hidden); it never scrolls, at 420 px either:

- **This point**: **Edit this point…** (the editor, see **Edit it**), **Write questions for this point**, **Copy its code** (copies `h7 · 1.2.2 Title · course`, the lowercase id the main chat's book tools match; a quiet **Copied**), **Collapse / Expand this point's AI paragraphs** (by their state; only when it has some). On **未归位** (the unplaced notes) the group has only **Edit this point…**: it has no code, questions or AI blocks of a point.
- **Reading**: **Read whole chapters** (checked while on), **Look over** (the look-over view, see **The final week**), **Collapse / Expand the book's AI paragraphs** (kept in this browser only).
- **Whole book**: **Lookup pages…** (in a dialog over the book, without its own contents: a code closes it and opens the point), **Export…** (its hint is the page estimate), **Send to the main chat…** (the whole book; the same form as a point's, in a dialog; it only fills the input box).
- **Final week**: **Today's points** (only on a day of the plan: the day under the bar), **Make a mock paper…** (today's points, else the whole book; it says at once what can go in), **Set the exam date** (only without one: it starts the final week; opens the course settings), **Go to settings** (with an exam further away than the window its hint says **The final week starts N days before the exam**).

The editor and **Look over** take the page's place, with **Done · back to reading** on top, which comes back to the point you were reading.

## Reading a point

A point shows the program's text in reading order, then your own layer; nothing is left out of a file, the parts are only shown in another order:

1. Its heading, under its chapter and section path (the printed code is not beside it: hover the contents' row, or **Copy its code**).
2. The takeaway (一句话): the point's one sentence, in type a step larger than the text, with no box, no colour, no label and no heavier weight (Chinese fonts have nothing between regular and bold, so the size carries it). It is the notes' own one-sentence part when they have one, otherwise the first sentence of the explanation, which is then not repeated under **Explanation**. A leading 「一句话：」 / 「In one sentence:」 is left off what is shown (the file keeps it). A first sentence that is a list, a table, a formula or code, or is very long, gives no takeaway.
3. The story: **Explanation** and **Example** (and anything you wrote at the end of a generated file). An AI block about words you selected (**Explain**, **Let the AI write a paragraph…**, a follow-up) sits right after the paragraph that holds its words, as the book did before one-at-a-time reading: in the explanation or the example, or after your own note when the words are in the note (in **Mine**); words in **Checklist** or **Extra** put it right under that fold.
4. **Checklist** (要点清单, the key points) and **Extra (beyond the materials)**, each folded under its label. **Questions of this point** and every AI block row use the same fold: the same caret, the same room, the same turn when open.
5. **Mine** (我的): a quiet hairline and a small label (not a toggle; hover or focus it for 「Your notes, AI paragraphs and the Q&A you put into the book are here」). Under it: your notes (open), the AI blocks for the whole point (written by **Add a paragraph here**) in the order they were written, the Q&A put into the book, the suggestions, and last the blocks whose words are gone (**Its place has changed**). A point with two blocks or more has one quiet **Collapse this point's AI paragraphs** (or **Expand**) on the label's row, the same words as the item of **More**. When **Mine** has nothing of its own (no notes, no whole-point block, no Q&A, no suggestion, no lost block) it is not drawn at all, even if blocks sit in the text above (they are short and fold one by one): its words would point at an empty layer. A whole-point block that is longer than the point's explanation and mostly says the same (60 % or more of its sentences and quotes found in the notes by a cheap word-pair comparison) says **Mostly repeats**.
6. **Questions of this point (N)**, folded: its questions as they are now, the first five as links and **N more** for the rest.
7. **Sources N**: one quiet chip, the first of the action row (below); select it for the list, which opens under the row. The footnote marks in the text still open the reader at the quote. Inside a point the links, the footnote marks, the dashed words and the sources are the text colour (ink) with an underline, never cinnabar; cinnabar stays for the one primary button. A footnote mark never starts a line: it keeps to the character before it, or, right after bold text, a link, code or a formula, to that.
8. **The action row** closes the point, so the reading starts right under the heading: **Add a paragraph here** on the left; **Sources N**, **Practise 5** (a point with questions), **Questions and answers (N)** (N: how many items it has, read when the point is shown; with none it is just **Questions and answers**) and **Send to the main chat** on the right. On a narrow page the buttons are one left-aligned row that wraps. The row's buttons all share one quiet look. **Questions and answers** opens under the row. There is no **Tidy up** menu and no **Only what I wrote**: each AI block is one row that folds by itself (below).

An AI block is **one row**. A block longer than 1,500 characters that you did not keep starts folded; every other block, and one you kept, starts open; what you folded or opened yourself keeps that, and a block that lands from a task you started on the page opens. Folded, the row is the caret (the summary is one line cut with an ellipsis; only on narrow screens may it take two lines, so it still says something on a phone), the **AI** tag, the first real sentence of the text (the program skips the template a whole-point block is written in: 「这段在讲什么」, headings, list numbers, 「原文说：」, 「意思就是：」, 「资料原文」, 「补充（资料以外）」 and the About line) and its size (**about 5,200 characters**, with **Mostly repeats** when it does). Open, the row keeps the tag (and the size when the block is longer than 1,500 characters), the text follows with its leading 「原文说：」 / 「意思就是：」 labels muted, then the quiet **Keep** (while it is new) / **Write again** / **Delete**, one click each, and the follow-up field. There is no **New** badge: the state stays in the file, where the main chat reads it.

**Send to the main chat** (on the row, in the panel over selected words, and **More › Whole book › Send to the main chat…**) fills the chat's input box with a message that asks the main chat to change that point, your selection or the whole book with the `study-book` skill (see [The review book and the main chat](review-book-agent.md)); it carries no book text.

Folding is kept per course in this browser, never in the book's text, so the export and the editor ignore it. The old **Only what I wrote** setting of an earlier version is not read any more.

The reading text follows **Aa** in the bar (the same setting as the reader: size, line width, typeface, paper; the takeaway a step larger, and it avoids a lone last character on its own line); tables scroll inside themselves on a phone and nothing scrolls sideways. A formula is drawn once, as MathML; a copy of the page as plain text may hold it twice (its TeX source travels with it as a hidden annotation), which is a copy artifact, not what is shown.

## The links

- **A question** (`studyhub://card/<deck>/<card>`) opens the practice page on that question, the same answering, grading and scheduling as everywhere. **Back to the review book** returns to the book at the heading and scroll position you left, with the focus on the heading of that point.
- **The way back is the main button.** On the result page of a round started in the book, **Back to the review book** is the one filled button, with a quiet second line saying where it leads (**Back to 1.2.2 Title**, the number and title of the point you left; a long title is cut, and the whole of it is in a tooltip; the button is no wider than about the left half of the result card, and its arrow is the same icon as the reader's **Back to reading**). The page's own next step is the second button beside it only when it goes on (**Continue this scope**, **Next step**, **Continue studying**, the next course batch); a step that is just another place to go back to (**Back to the learning path**) is left out, and with no step on there is no second button. At 420 px a second button has the width of the main one, in one stack. During the round the return button in the header reads **Back to the review book** (not **Back to library**), and it is the only way back on the page: nothing repeats it under the question. A round started on the **Course outline** says **Back to the outline** in the same places, without the second line. On the result page the header does not repeat the button. A round nested inside a book round (a prerequisite round, a detour from the inbox) keeps its own way on as the main button, and the autopilot countdown does not run past a way back that is the main button. Back in the book you are at the same point and offset, and the point's heading has the focus (only when you come back through the way back, not on a later visit). Only a round started from the book page itself (**Practise 5**, a question link) goes back to the book: a round started from the reader (opened over the book by a footnote or a source) keeps the reader's **Back to reading**, and the page never has two filled buttons for the two. A reader round has exactly one filled button, **Back to reading**, whatever else the trail knows: the page's own next step is a plain button after it (and a next step that is only another place to go back to is left out), no second return button is drawn, the 点评 card's buttons are plain, and the autopilot countdown does not run. Every onward button on the result page ends in the same arrow icon as the way back begins with (never a text arrow), and the 点评 headline says nothing about a next batch when the page offers none. A round started from any other page keeps its own next step as the main button and its own words.
- **Practise 5** (`studyhub://practice?heading=<id>&n=5`) practises the first five of the point's questions in the order a practice round takes them (due, weak, new, then the rest); an unfinished round of exactly those questions goes on. A question answered well a moment ago is no longer due, weak or new, so it comes after the others.
- **Questions and answers** (`studyhub://qa?heading=<id>`) opens, under the point, what was asked about it: follow-ups kept on its questions, the reader's notes on passages inside its places, and question-and-answer cards. Each item is folded; open it for the answer, then go to the question or to the original passage.
- A footnote mark and the sources list open the reader at the quoted sentence.
- A link to a question that was deleted reads **This question was deleted**. Links only navigate; they never run anything. Any other link opens normally.

## Edit it

**More › Edit this point…** opens the raw Markdown of ONE file in the Markdown editor, in the page's place: the explanation of the point you are reading first; the file picker lists every file in reading order (each knowledge point's **explanation (generated)** and **my notes**, and 未归位), and any file can be edited. **Done · back to reading** comes back to the same point; with unsaved changes it asks first (**There are unsaved changes**: **Keep editing** or **Discard and leave**), and so do **Back to the outline** and the course switcher; closing or reloading the tab gets the browser's own question. Known limit: leaving through the sidebar or another page does not ask yet (the app has no navigation guard; the planned inline editor saves as you type). The book never opens in the editor by itself.

- **Save** saves the file. A heading you type (`## …`) gets a stable id on save (written at the end of its line, hidden in the preview); an id is never given twice and never taken from the outline's headings. **Discard changes** goes back to the saved text. While there are unsaved changes the file picker is locked, so switching files never loses them.
- **Editing a generated file makes it yours** (**Changed by you**). When the explanations are written again, a file you changed is never written over: the new text waits under it in the preview as **New generated text**, with **Take it** and **Ignore** (an ignored text is not offered again; a newer one is). A file keeps up to three waiting suggestions, newest first, each with its own buttons, so one never pushes out another. A file you did not change follows the new explanations by itself. Your notes are never touched by the program.
- **The book was updated.** A save is checked against the version of the file you started from. When the same file was changed meanwhile (by the program or in another tab), your text is saved anyway and the other text waits as a suggestion (**The book was updated**, with **Take it** and **Ignore**); other files are not affected.
- **Back to the previous version** takes the file's previous text back, one version at a time; any write of the program can be undone this way. The last 20 versions of a course are kept (fewer when they are large), outside the library's materials; a portable backup carries them and a restore brings them back. Two copies of the app writing the same book at the same moment may lose a version from this history, never the book.
- The preview of an edited file still draws the question links, footnotes and 本节问答, and never renders HTML: tags stay visible as text. A heading you typed is in the contents and can be reached from it, and the way back after practice returns to it.

## Q&A in the book

A follow-up you get while practising (an answer to **追问** or **帮我弄懂**) stays on its question as before. To keep it in the book too, select **Add to the review book** under it, on the practice page or in a point's **Questions and answers**; it then reads **Added · Take back**, and selecting that takes it out of the book again (the question keeps it either way).

- It goes into the point's own **Q&A** file, shown after your notes: the question's link first (when nothing under the point links that question yet), the follow-up quoted under it. A question of no knowledge point goes to 未归位. The same follow-up is never added twice.
- Once in the book it is your text: edit it like any other file (**More › Edit this point…**, the file **· Q&A**); changing the question later does not change it. While the Q&A file is open in the editor, an add that lands meanwhile is merged into your save: neither is lost.
- **Add to the review book automatically** (a small switch beside the buttons on the practice page, and in **Settings › Practice**; off by default): when on, each new follow-up or 帮我弄懂 answer that arrives while the practice page is open is added by itself. What is already in the book stays; switching changes only the next Q&A. If an automatic add fails, a small notice says so and the button stays. Only Q&A made on the practice page are added automatically.

## Explain while reading, add a paragraph

On the reading surface, select some words of a knowledge point (its explanation or your notes): a small panel opens under them with **Explain** and a field **Let the AI write a paragraph…** (more detail, an example, a comparison table). Under each point's heading, **Add a paragraph here** opens the same field. Either starts a task you can follow, stop or retry on the **Tasks** page (no estimate, no confirmation); without a model the panel shows the shared model setup note, and reading and editing go on.

- The answer comes from the point's own materials (the same grounded rules as asking about a passage in the reader). Quotes are checked word for word in the materials and dropped when not found; what goes beyond the materials is listed apart under **Extra (beyond the materials)**. A point without materials is refused plainly.
- **What you type is followed.** **Explain** (no instruction) keeps the fixed explain shape. When you write an instruction (**Let the AI write a paragraph…** or **Add a paragraph here**: for example "explain Day 1-5 with a chef analogy", "go into more detail", "compare X and Y in a table"), the answer follows your instruction for its form, tone, length and examples; the facts still come from the selected passage and the point's materials. An analogy, example or background that comes from outside the materials is written as the main text and each such part is marked in place with **(beyond the materials)**, never hidden in a list at the end; the AI is told never to present an outside fact as if the source said it, and to say once when the materials do not define something. A follow-up under a block is a new request of yours and is answered the same way (for example "once more, with the chef analogy"). If the model still returns a separate list of outside items, they end the text as plain bullets each starting with **(beyond the materials)**, not under a footnote heading. The checked quotes may still close the paragraph under **From the materials**.
- It is written as a NEW paragraph into the point's own notes, never over existing text, and shown right after the paragraph that holds the words you selected (in the explanation, the example or your note; never at the end of the point); when it lands it opens and the page shows it. The words you selected stay dashed in their paragraph (when they are found there; when they are gone the block goes to the end of **Mine** and is marked **Its place has changed**). **Add a paragraph here** writes a block for the whole point, shown in **Mine**, and a follow-up under it stays under it. A block about words says what it is about when open: **About: “…”**.
- It is yours from then on: edit it in the editor (**More › Edit this point…**) like any text; the book's updates never change it. **Keep** marks it as kept, **Write again** asks the same again, **Delete** takes it out, and the field under it asks a follow-up whose answer goes right under it.
- A block folds: its row (the caret, **AI**, the first real sentence of the answer when folded, and its size) opens and closes it with a click, Enter or Space, and **Collapse this point's AI paragraphs / Expand** on the **Mine** row (or in **More**) does every block of that point (see **Reading a point**). A block of 1,500 characters or less, or one you kept, opens open; a longer one you did not keep starts folded; the fold is the reader's own, kept per library and course in this browser, never in the book's text, so the export and the editor ignore it. The words you selected carry a dashed underline in their paragraph (when they are found there; otherwise none): pressing them opens the block and shows it, and pressing **About: “…”** in the block goes back to the words.
- Like the rest of the book it is a reference, never material for questions.
- While your notes are open in the editor, a paragraph that lands meanwhile is carried into your save: neither is lost.
- Known limits: the page checks a task it started every 1.5 s, only while that task runs. The preview and development server has no background-task executor, so these tasks (and writing the review book) run only in the real host.

## Answer cards of analysis questions

For a case or analysis question (an open question with marks and marking criteria, 大题) the answer is not one paragraph but one checked **answer card** (答题卡). After the question is graded on the practice page, its reference answer shows as before with **Generate answer card** under it (a task you can follow on the **Tasks** page; no estimate, no confirmation; without a model the shared model setup note says where to set one up). There is ONE full version of the card, never a short one:

| Part | What it holds |
| --- | --- |
| Question type and signals | The type (risk scenario, availability, performance, capacity and RAID, domain decomposition, cloud migration and choice, or general analysis; a course may add its own) and the words of the stem that point to it, with the stem's own sentence. |
| Stem facts | Each fact the answer uses, with its quote from the question or the case. |
| Concepts | Name, the material it is defined in, and the definition in the material's own words. |
| Assumptions | What the stem does not say, stated explicitly (a number the answer needs is stated here, never invented). |
| Reasoning, conclusion | The type's solving steps with the formulas filled in, then the answer. |
| Why it meets the goal, cost and failure handling, how to verify | The justification an examiner looks for. |
| Pitfalls, marks map | Typical mistakes; for each marking point of the rubric, the sentence of the card that earns it. |

What the program checks: every quote and definition is looked up word for word in the stem, the case or the materials (spacing and case do not matter); one that is not found is marked **Not verified**, and so is an elided quote ("…") and one too short to prove anything. A converted material with HTML (a PDF's tables) is read as its visible words: tags out, a cell boundary as a space, entities decoded, so a definition in a table cell is found and shown in those words. Which marking points are covered is counted by the program, not by the model, and numbers that stand in neither the stem, the assumptions nor the concepts (and are not a computed result) are listed. An independent review then looks for claims the stem does not support, contradictions of the stem, a missing cost and invented numbers; when the checks or the review find something the card is written once more (two or three model calls in all). The card shows its state: **Checked** (every check passed), **Partly unchecked**, or **Changed since** when the question, its marks, its rubric or its reference answer was edited after the card was made. **Checked ≠ correct.**

- The card is kept beside the question (`answerCard`); the question's own answer, its review schedule and history are never changed. It comes with the reveal like the reference answer, never during a mock exam, and a question in an unsubmitted mock exam gets none until it is submitted.
- When the deck's materials are longer than the budget (24,000 characters), the model is given the passages that share the most terms with the question (its stem, topic, concepts and rubric) first, then the rest in reading order; the quotes are still checked against the whole materials.
- Known limits: a card repaired after the checks or the review is checked by the program again but not reviewed again; the number check is a heuristic (a level such as "RAID 5" the stem does not name may be listed, and an input written after a calculation may be missed); the question type is chosen by the model from a keyword guess, and a course's own types are set through `course.save {caseTypes}` (no page for it yet).
- **Add to the review book** under the card puts it into the course's book, in the point's Q&A file under the question's link (a case question of no point goes to 未归位), once; **Added · Take back** takes it out. In the book it is your text like any other.

## Lookup and export (your printable CP)

A book read front to back is hard to search in an open-book exam. So the book has **lookup pages**, made from the book every time (never kept or edited by hand), and they lead the export: from a question to the section, the definition and the steps.

- **Codes.** Every heading has a stable code, its id in capitals (`H12`), shown when you hover or focus its row in the contents, copied by **More › Copy its code**, and in the margin of the export (`### 1.2 Title 〔H12〕`). A code is never renumbered: inserting, moving or removing sections changes the numbers (1.2 → 1.3), never the codes. The questions of a point are numbered by its code, `H12-Q1`, `H12-Q2`…; 未归位 is `U`.
- **Lookup pages** (**More › Lookup pages…**, a dialog over the book; its contents are the page's own): **By question type**, the cheat-sheet table: for each question type that has an answer card in the book (and each type of the course's own), its signals in the stem, its steps and formulas, its most common mistakes and the cost an answer must state (a built-in type in the book's language, Chinese or English; a course's own type as it was written), where it is (codes and question numbers), above them the answer order every answer follows (stem facts → explicit assumptions → design or calculation → why it meets the goal → failure and cost → how to verify); **By concept**: the concepts of the answer cards, a bold term that starts a definition in your notes or the explanations (`**term**: …`, `**term** is …`, `**术语**是…`, or any bold term on a line that starts with 定义 / Definition) and any word you mark `[[term]]`, each with its codes; **Mistakes by point**: the follow-ups you put into the book (what you had to ask) and the pitfalls of the answer cards. Select a code to close the dialog and go to its heading. Without answer cards nothing about question types is shown. (The export's lookup pages still start with the contents.)
- **Export** (**More › Export…**; the item's hint is the page estimate): one Markdown file, without or with the **answer key**. It starts with the book's title and the lookup pages, then the book in reading order (each point: the explanation, its questions when you choose them, your notes, its Q&A; 未归位 last; with the answer key, the key last). The program's marker comments are taken out (a heading's id becomes its Pandoc anchor `{#h12}` and its margin code; the content of Q&A, answer-card and AI blocks stays); **Which questions to print**: **Only the questions the book links** (the default: those of the Q&A files and the links you wrote yourself), **Also every point's own questions** (all of them, with their options, under each point; the most pages), or **No questions** (question links left out). A printed question link becomes the numbered question with its options (A., B., …) the first time it appears in its point; a link to a deleted question, **Practise 5** and **Questions and answers** are left out; a source keeps its words; footnotes are named per file, so they never collide. The answer key lists exactly the printed questions under the same numbers, and the estimate follows the choice: the answer (the right options, the blanks), the explanation, an answer card in full. The same book always gives the same bytes. **Export as files…** lists the folder form: one file per part (`000-front.md`, `001-h3.gen.md`, …) and `book.yaml` with their order; the app has no zip writer, so they are downloaded one by one, and `pandoc $(sed -n 's/^  - //p' book.yaml)` reads them as the same book.
- **Not printed.** Text between `<!-- sh:noprint -->` and `<!-- /sh:noprint -->` (written in the editor) is left out of the export and of its estimate; the page still shows it. A marker never closed is ignored (its text is printed).
- **Pages.** The dialog shows an estimate of the A4 pages of each choice by a fixed rule (about 40 Chinese characters or 80 other characters a line, 45 lines a page, a blank line half a line): an estimate, not a measurement. **Page limit** (empty by default) is saved as `settings.book.pageLimit`; once set, the **Export…** item says **About N pages / limit M** (the book without the answer key), and when the book is over it one quiet red line under the bar says how far.
- Known limits (accepted): the concept rule reads only bold terms at the start of a line, bold terms of a 定义 / Definition line and `[[term]]`; `course.book.open` carries the course's question-type catalogue (`caseTypes`, a few kB) on every open; the page runs the whole export again (estimate only) after each change of the book for the **Export…** hint and the limit line, which costs more on a very large book. That estimate is of the default choice (linked questions, no answer key).

## The final week (期末一周)

When a course has an exam date (**Course settings**) and a review book, the program plans its last days over the book's points: no model call, the same answer every time for the same book, answers and marks, and every day says in one line why it holds what it holds.

- **Learn days, then look-over days.** The days from today to the day before the exam: the last two study days (one to three; all of them when fewer remain) are **look-over days** (翻看): no new questions, every point once, those with the most mistakes first, then the weakest; the very last full day also has a **mock paper**. The days before are **study days**: read a point, then **Practise 5** (its next five questions). The exam is today: one look-over day without a mock. With no exam date there is no plan; the book works as before.
- **Which points first.** A point weighs 1 + the sample papers that tested it (the outline's 样卷考过); without sample papers every point weighs the same. Its weakness comes from its questions (a weak one counts most, then new, learning, familiar; a due one more). The most important points (weight × weakness) are learnt first; each day carries about the same minutes (reading its text, about 300 characters a minute, and its five questions), within the day in reading order. A point is learnt once: when at least five of its questions (or all, when it has fewer) were answered on one day, or, for a point without questions, when it is marked **Read it**. When there are more points than time, the days carry more than the minutes of a day (**Settings › Practice › Final week: minutes a day**: 60, 90, 120, 180 by default, or 240) and say so (**More points than time: …**): nothing is left out. Made again tomorrow, the plan keeps what was done on the day it was done and spreads the rest from today; after doing exactly today's points, the next days are the same as planned.
- **On the home.** Under **What to do first today**, a **Final week · course** card for each active course (a parked course is left out) whose exam is within 21 days (**Settings › Practice › When the final week begins**, 7–60 days), with today's kind of day, its reason, its points (**Read** opens the book at the point, **Practise 5**, on a look-over day **Look over**), **Look over the book** and **Make a mock paper from these points**. **Practise 5** on the card has a way back to the home, like any round started from a page. A course other than the current one is made current before its book opens (the book page shows the current course's book), and the book says so once, quietly (**Switched to the course X**).
- **In the book.** **More › Final week › Today's points** opens the same day under the bar. **More › Look over** (翻看) takes the page's place (with **Done · back to reading**) and lists every point in the plan's look-over order; each shows its **mistakes** first (what you asked and put into the book, the answer cards' pitfalls, what you had explained with 弄懂), its **Explanation** folded (drawn only when opened), **Looked over** (kept per course: the progress survives a reload) and **Into the mock paper**. A round started there comes back to the reading surface at its point; **Look over** is one press away again, its progress kept. Without an exam date **More › Set the exam date** opens the course settings; with one further away than the window, **Go to settings** says when the week starts.
- **Mock paper.** **Make a mock paper from these points** (the points picked in Look over, else today's, else the whole book) first says how many questions those points have, how many single or multiple choice questions can go in and what is left out by kind (the mock exam takes single and multiple choice only), with the number of questions (1–50, at most 20 by default) and the time limit (the course's writing time, else 30 minutes); **Start the mock paper** starts the ordinary mock exam over them, due and weak questions first. The exam page, its timer, its submission and its report are the same as always; its way back is the book.
- Known limits (accepted): days off are only an argument of the operation (`daysOff`, no page for them); the reading speed is a fixed rule; a point is learnt by its answers of one day, so answering five of its questions in a mock exam counts too; opening another course's plan from the home makes that course the current one (and says so); in Look over with **Today's points** open there are two mock-paper buttons with different scopes (today's points, and the points picked or the view's); the look-over order is fixed for the day (a point looked over stays where it is, greyed); the plan of a day is kept until the library or the book changes, so a question that falls due later that day moves a point only after the next change.

## Edit it from the main chat

Ask the main DSH chat to write or rewrite any part of the book: it works one knowledge point at a time with the `study-book` skill, reads the material pages first, checks every quote word for word and keeps the previous version of every file it writes. See [The review book and the main chat](review-book-agent.md). The book page can also hand a point, selected words or the whole book to the chat with **Send to the main chat**.

## Where it is kept

The book is one hidden record of the library (`provenance: 'course-book-doc'`) holding Markdown files: for each knowledge point a generated file (the program's) and your own file (empty in M1), a manifest (the outline's tree with a stable id per heading) and a file for text without a point; the final week's **Read it** and **Looked over** marks are a day per point in the same record (`bookDoc.marks`), never a file. It is a reference, never material: it is not in the materials list, the pickers or the search, not in the retrieval index, not counted in the assistant's library context, and a request that names it as material is refused. Questions keep citing the original materials.

Opening the page makes the files the first time (no model call) and brings the generated ones up to date with the explanations. The list of a point's questions is not kept in a file: it is read live each time, so new or deleted questions change no file, and an open that changes nothing writes nothing to the library. Your own files are never changed by this. When the outline is rebuilt, each knowledge point keeps its files and heading id if a new point holds the same materials (else one of the same title); what cannot be mapped goes to Not placed; nothing is deleted.

## Rolling back

Upgrade only. An older release (3.3.0 and before) does not know this record: it keeps it as it is, but may list it as a Markdown material named **复习全书 · course** whose text is one line, **复习全书（由 StudyHub 3.4 以上管理，请勿删除）** (the review book, managed by StudyHub 3.4 or later; do not delete). Deleting that entry in an older release deletes the book's files. The version history (the `book-history` folder of the library) is ignored by older releases. A question's answer card (`answerCard`) is kept as it is by an older release, which shows only the reference answer. The export writes nothing; an older release forgets the page limit (`settings.book.pageLimit`) the next time it saves the settings, and drops the `mistakes` of a course's own question types when it saves the course. The final week writes only its marks (`bookDoc.marks`, kept as they are by an older release) and an optional `settings.book.crunchWindowDays` (forgotten by an older release when it saves the settings); its mock paper is an ordinary exam run.

**The quality workflow (this version) is upgrade-only too: back up the library first**. Its records stay readable by 3.4, with these limits: 3.4 does not know the inventory record (`course-outline-inventory`) and may list it as a material (do not use it for questions); it cannot resolve the page spans (`doc@s3-7`) of an outline built from the inventory, so such points show no questions there; the explanations carry a 3.4 copy of their text and sources (`explain`, `cites`), shown without concept coverage, glossary or 未达标 marks. Do not run **Update the book** in 3.4 after upgrading: it cannot read the spans and would write empty explanations.
