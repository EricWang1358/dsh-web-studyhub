# Capture 已知题组的快速路径

实际会话中 `capture` 多次耗时 40–100 秒，报告的 mainframe economics 调用约 152.7 秒。请求已经包含 `deckId` 和 `answer`，但旧实现未读取这两个字段，仍串行执行一次题组分类模型调用和一次写卡模型调用。每份资料库的录卡串行锁还可能增加排队等待。

修正后，有明确 `deckId` 时先检查题组有效性，跳过分类调用。在一次写卡调用里处理目标题组内的语义重复判断、主题选择、给定答案核对和引用整理。相同题干的本地重复检查仍不调用模型；没有指定题组时保留自动分类。提供的答案只是待核对草稿，不能充当原文引用。校验失败时仍允许原有的一次修复。

同一请求、实际资料库副本（8 个题组、162 题、186 份资料）做无网络请求组装对照：旧流程 2 个模型阶段，共 63,291 字符；新流程 1 个阶段，40,393 字符。本地组装约 8ms 和 5ms，不包含真实模型响应、最终校验和写盘；不能据此声称端到端延迟已降到毫秒级。

结果新增 `performance`：排队时间 `queueMs`、每次模型调用的阶段/耗时/输入字符数、总耗时 `totalMs`。录卡仍按资料库串行，以使后来的语义去重看见刚添加的题目。测试覆盖指定题组只调用一次、给定答案传递、保留主题、语义及精确重复、无效题组零模型调用以及原有归类路径。

真实模型的优化后耗时需后端加载更新后实测；更新前已开始的录卡调用不会中途切换。
