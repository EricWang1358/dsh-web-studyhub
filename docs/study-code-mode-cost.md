# 学习子代理的代码模式成本

实际任务 `69bd1af7` 第 2 批独立审阅有 6 次 run_code 调用，逐轮重新读入材料、题目和此前工具输出，累计 totalTokens 为 221,549，最后在约 10 分钟被中止。规划、自查也有多次脚本执行；部分阶段把整份 JSON 放进通信消息后又在最终回答输出一次。截图的 222K 是多轮累计，不是单次上下文大小。

DSH 的 PTC 模式把 run_code 作为保留传输工具，在全局工具过滤之后额外暴露。因此 `toolFilter: {allow:["send_message"]}` 不能移除它。这是先前只测试 allow 列表而未测试工具呈现模式留下的缺口。

修复：在保留的 Study 子会话创建事件上，通过该代理的作用域调用 `tools.presentAs("native")`，在初始任务入队前移除代码传输；仅保留父子通信工具。主对话和其他代理的模式保持原样。能力存在但作用域设置失败时明确失败，不继续昂贵的代码执行。模式注册跟随代理作用域释放，监听器随阶段结束移除。

任务说明明确：逐字引用与结构由插件校验；模型聚焦语义审阅，不运行检查脚本；无须常规进度消息，完整结果只在最终 JSON 中提交一次。通信仍允许缺失信息问题和父代理要求的回复。出题、自查和独立验收没有移除。

统一规划后，每批只发送自己考点引用的来源全文；不把同一资料块内未分配给该批的页面重复发给作者和审阅者。原文没有截取为无上下文的孤立引用。

验证使用本机安装的 DSH ToolRuntime 与作用域实现（提示注册使用测试替身）：同一进程中 Study 子代理由 ptc 切为 native，主作用域仍为 ptc，子代理工具 schema 不再包含 run_code。回归测试另覆盖无关代理隔离和资料范围。尚未运行修复后的真实模型耗时对照，不能据此承诺具体倍数。
