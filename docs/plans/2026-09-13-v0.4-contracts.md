# v0.4 功能契约（2026-09-13）

7 项已确认需求的统一接口契约。后端动作走 `StudyService.call(action, args)`；UI 组件只通过 `call` 与 props 交互。文件所有权：后端 = `lib/` + `tests/`；视图 UI = `ui/Dashboard.jsx`、`ui/Exam.jsx`、`ui/WrongBook.jsx`、`ui/views.css`；图谱/挖空 UI = `ui/Graph.jsx`、`ui/Cloze.jsx`、`ui/graph.css`；接线（App.jsx / StudyMap.jsx / host.jsx / style.css / README）由主会话完成。任何代理不得改别人拥有的文件，不得 git commit。

## 1. 横向分叉图谱 `graph`

`graph {scope?: [{deckId, topic?}], mode?: "structure"|"path"}`（scope 缺省 = 全部非归档题组；卡片过滤沿用 planPath.wanted 语义，排除 suspended）

- `structure`：`nodes` = deck 节点（`id:"deck:"+deckId`，label=题组标题，mastery/due/total）→ topic 节点（`id:"topic:"+JSON.stringify([deckId,topic])`，syllabus 顺序 seq）→ card 节点（`id:"card:"+JSON.stringify([deckId,cardId])`，label=objective 或 prompt 截断 48 字，level/cardKind）。card 节点上限 400，超出时结果带 `truncated:true`。`edges`：tree 边（deck→topic→card，带 seq）+ 前置边 `{from:cardA,to:cardB,type:"prereq"}`（A.requires 含 B，两端都在图内才输出）。
- `path`：`planPath(s.decks, outcomes, {scope})` 的 entries 顺序，仅 card 节点，链式 `type:"order"` 边（seq 从 0），路径内两端都在的 prereq 边照常输出。
- 返回 `{mode, scope, nodes, edges, truncated?}`。

## 2. 统计仪表盘 `stats`

`stats {}` → `{generatedAt, totals, heatmap, trend, weakTopics}`

- `totals`: `{attempts, activeDays, streak, correctRate(0-100, grade≥3), cards(活跃未暂停), due, mastered, weak}`；streak = 含今天或昨天、连续有作答的天数。
- `heatmap`: 182 天（含今天）按本地日期 `YYYY-MM-DD` 零填充，`[{date, count}]` 按时间正序；count = 当日 attempts 数。
- `trend`: 有作答的日子的 `[{date, avg(0-5 一位小数), count}]`。
- `weakTopics`: 最近作答 grade<3 聚合到 deck+topic，`[{deckId, deckTitle, topic, attempts, wrong, lastAt}]`，wrong desc → lastAt desc，前 12。

## 3. 模拟考试（review.start 新增 mode:"exam" + `exam.submit`）

- `review.start {mode:"exam", scope?: [{deckId, topic?}], count?: 1–50(默认10), fresh?: true}`：池 = scope 内非 suspended 且 kind ∈ [quiz, multi] 的卡；shuffled 取前 count（池小于 count 用池）；`run.mode="exam"`，entry 增加 `selected:null`。
- `review.answer` 在 exam 运行中：仅校验并存储 `entry.selected`（与 choice 分支同样的合法性校验），**不判分、不更新 SM-2、不写 attempts、不 revealed**；可反复改答案（无 signature 冲突）。
- `review.move`：exam 模式放开「先作答才能下一题」限制；`review.reveal`：exam 未 closed 时拒绝。
- `projection`：exam 打开时照常返回 card/index/total（feedback 恒 null）；`exam.submit` 前不泄露正确性。
- `exam.submit {runId}`：mode=exam 且未 closed；对每道有 selected 的题按 choice 规则判分（对=4 错=1，更新 live 卡 SM-2、push attempt、entry.feedback），未作答的不动；`run.closedAt=now`。返回报告 `{runId, total, answered, unanswered, correct, scorePct, durationMs, byTopic:[{topic,correct,total}], byDeck:[{deckId,title,correct,total}], wrong:[{deckId,cardId,topic,prompt,kind}], weakScope:[{deckId,cardId}]}`（wrong.prompt 用 publicCard 形式，不带答案）。
- `runTitle`：exam → `模拟考试 · N 题`。

## 4. 跨题库错题本 `wrongbook`

`wrongbook {}` → `{items:[{deckId, deckTitle, cardId, topic, kind, prompt, lastGrade, lastAt, suspended}]}`：每卡最近一次 attempt grade<3，非归档题组，lastAt desc，上限 100。重练直接复用 `review.start {mode:"path", scope:[{deckId,cardId}...]}`。

## 5. 挖空卡 kind:"cloze"

- 卡片字段：通用字段同现有（answer = 含答案的完整句子）；新增 `cloze: {text, answers:[{id, value, accept?: string[]}]}`，text 内 `{{id}}` 标记与 answers 一一对应（无重复、无悬空）。
- `validateDeck`：cloze 校验失败报 `Card N: …`；单选题等既有规则不变。`generate` 的 kind 白名单与提示词加 cloze（沿用 author→editor→repair 管线，expectedKind 校验兼容）。
- `publicCard`：cloze 只暴露 `{text, blanks:[{id}]}`，**不得泄露 value/accept**。`solution()` 增加 cloze（含 answers）供 reveal。`substance()` 计入 cloze（改答案重置调度）。
- `review.answer {answers:{blankId:text}}`（run.mode!=="flashcard" 且 kind==="cloze"）：规范化比较（NFKC、小写、trim、内部空白折叠；匹配 value 或任一 accept）；全对 grade=4 否则 1，正常 SM-2 + attempts；`feedback.details=[{id, correct, expected?}]`（错时给 expected）。
- `capture`/`ingest` 不支持 cloze（保持现状）。

## 6. 笔记本联合视图（在 lib/notebooks.js 之上）

- 新增 `notebook.search {query}`（1–100 字符）→ `{items:[{root, workspace, title, deckId, deckTitle, topic, cardId, prompt, due}]}`：在所有已发布库里匹配题组标题/主题/题干（NFKC 小写子串），上限 50，只读。
- `notebook.list` 已含每库 decks 的 due —— 全局到期队列由 UI 从 list 派生，不加动作。
- host.js / index.js 的 notebook.* 分支加 `notebook.search`；工具描述补一句。

## 7. 源文高亮回链（纯 UI，主会话实现）

引用弹窗在原文/排版两种视图里定位并 `<mark>` 高亮 quote，自动滚动到位（引用逐字校验保证可定位）。

## UI 组件 props 契约

- `Dashboard({ call, data, onStartScope })`：`onStartScope(scope)` → 主会话用 path run 开始学习。
- `Exam({ call, data, onExit })`：自管理 setup→running→report；`onExit()` 回学习库。
- `WrongBook({ call, busy, onPractice })`：`onPractice(scope)`。
- `Graph({ call, busy, scope, onClose, onStudyCard })`：`onStudyCard({deckId, cardId})`。
- `Cloze({ card, values, onChange, disabled, details })`：纯展示，判分在服务端。
- 各组件自带 CSS 文件（esbuild `.css` loader 为 text），挂载时注入一次（按 id 去重），颜色只用 `:root`/`.study-app` 的 CSS 变量 token。
