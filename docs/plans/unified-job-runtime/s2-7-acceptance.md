## 1. 混跑

测试：`tests/unified-runtime-audio-family.test.mjs`（9 条）。每个开关都是"下一次提交"才读取，所以同一个服务里可以让旧路径和新路径并存；测试里的"开关板"在服务运行中翻开关。

| 验收项 | 结论 | 证据 |
|---|---|---|
| 同一份夹具，开关关/开，文档、信箱信种类、模型请求一致 | 成立（字幕、复查、课堂保存、单文件、批次各一条） | 比较的是读者看得到的结果：资料的 id/正文/标题/课程、关闭信的种类、模型收到的请求序列；批次自己的随机 id 折叠。策略改进（D-1/2/4/6/7/8/12 的措辞与用量、窗口 429 恢复）在各步的评审差异里，不在这个比较里 |
| 旧/新单录音、批次、字幕、复查、课堂保存混跑，无双计数 / 重复重试 / 重复结算 | 成立 | 一个服务里先全走旧路径各一次，再翻开关全走新路径各一次：每个任务只有一行、每个任务恰好一封结果信、没有重复的资料、宿主模型的 token 在账本里与请求数一致（每个请求只记一次） |
| 开关翻转不改变在途任务 | 成立 | 单文件：转写进行中把开关关掉，已在跑的任务仍是运行时任务并完成，下一个提交走旧路径，两个录音各转写一次 |
| 课堂校正的开关关闭 | 成立（评审过的差异） | 开关只管新开的课堂；正在跑校正任务的课堂把它跑到下课；开关关掉后新开的课堂走旧计时器，没有任务；被取消的校正保持停止，直到再次调用 `live.correct`。不回填旧定时器 |

## 2. 公共控制台：控制真实，无假按钮

同一个测试文件的第 9 条：六种运行时任务（含课堂校正）同时在跑，对每一种：`cancel` 可用当且仅当它声明了 `cancel`；声明了"不支持暂停/没有设置"的不出现暂停/设置按钮；运行中不出现重试；然后逐个 `job.control cancel`，全部结束。控制台按"音频家族"识别（`AUDIO_JOB_TYPES`），没有 `type === '<kind>'` 的分支（`unified-runtime-architecture` 守卫）。

## 3. 两个有时序的测试改为等观察到的状态

| 测试 | 症状 | 原因 | 修法 | 证明 |
|---|---|---|---|---|
| `unified-runtime-audio-windows`「a model that allows two at once…」 | 全套并行时失败 | 假模型靠 120 ms 的睡眠让调用重叠，运行时每个调用先落一个意图再发，机器忙时调用来不及重叠，就没有被拒绝的 | 假模型把前 `capacity + 1` 个调用扣住，等它们**同时开着**（观察到的状态）再推回 | 改前在 6 路并行下 12/12 红；改后 20/20 绿，整个文件 8 路并行 20/20 绿 |
| `unified-runtime-audio-batch`「a crash with every request answered resumes…」 | 在 Windows 上失败过一次：步骤表里缺 `member:0` | 结束进程的钩子在第二个文件的结果写完时就结束，而第一个文件的提交写进 manifest 可能还没落盘 | 钩子等 manifest **在盘上**也记着"前面的成员已提交、这个成员待提交"再结束 | **本机没能复现**改前的失败（16 路并行 48/48 绿），所以这是"按构造正确"的修法，不是"改前红、改后绿"；改后 12 路并行 24/24 绿 |

## 4. 回退到固定版本

**固定目标**：标签 `v2.7.1`，SHA `47f132815fc2fa65c7352f3f536109bb9c3ddd96`。

**演练发现的真实缺陷（已在内核修复，#331）**：演练第一次运行时，2.7.1 读不了当前代码写的任务 manifest——落盘的请求意图带了 `sideEffect` 字段和 `abandoned` 状态，2.7.1 的存储校验是封闭结构，`snapshot` 直接抛 `invalid-store-shape`，重试也抛。#331 把落盘意图恢复成 2.7.1 的形状，并加了守卫测试 `tests/unified-runtime-rollback-shape.test.mjs`（内置 2.7.1 的校验副本）。下面的演练是在修复之后的结果；以后任何改变落盘形状的改动会在 CI 里红，不再靠人工演练发现。

**排空**：开关在每次提交时读取。回退前的顺序：关闭六个开关 → 等控制台里音频任务结束（或取消）→ 换回 2.7.1。直接换版本（不排空）也是可行的，后果见 §4.2：这就是演练做的事（准备阶段的进程在任务还在跑时被**硬结束**，不 dispose、不清理）。

**演练**（`tests/fixtures/runtime-s27/run-drill.mjs`，需要旧版本的树，所以手动运行，不在 CI 里；结果在 [`s2-7-evidence.json`](s2-7-evidence.json)，`tests/unified-runtime-audio-evidence.test.mjs` 校验该文件与本文一致）。五个场景，每个场景同一个资料库和同一个 DSH_HOME：

1. 当前代码、六个开关全开，做出产物或未完成的工作，进程被硬结束；
2. 2.7.1 的树（`git archive v2.7.1`）打开同一个库，读取，并把未完成的工作做完；
3. 当前代码再打开它读取（回退后再前进）；
4. 把第 1 步的快照放回去，当前代码自己把未完成的工作做完（对照）。

全部使用 fake：Gemini 转写与宿主文字模型都是假的，没有网络、没有真实密钥；2.7.1 与当前代码拿到同一个"上一个进程的 agent 已消失"的执行器（真实宿主里由宿主回答）。

### 4.1 已完成产物：旧版本读得出（场景 `settled`）

当前代码、全开，做完一个单文件、一个批次、一份字幕、一次复查、一次课堂保存和一次课堂校正后结束：2.7.1 读到 5 份资料，资料 id 与内容哈希、5 封结果信与当前代码一致；当前代码在回退后再读也一致。**没有新的持久化格式**，唯一新增的文件种类是运行时批次的 `audio-batches/<id>/checkpoints/<id>.json`（2.7.1 从不读它，留着无害）；证据里逐类列出，测试断言除它之外的种类与 2.7.1 自己做同样的事留下的完全相同，且其中没有任务/运行时/attempt 类的文件。

### 4.2 未完成的工作：每条路径的去向

| 路径（场景） | 回退时的状态 | 2.7.1 看到的 | 能否继续 | 与当前代码的差别 |
|---|---|---|---|---|
| 单文件，校对请求在途（`single`） | manifest 记着运行中，没有进程 | 一行"已中断"，带「接着做」 | 能，**但 2.7.1 的「接着做」第一次点击会被它自己的 `revision-conflict` 拒绝**（后来在内核里修了，#303，2.7.1 没有）；换成"把同一个文件再导入一次"即可：转写在缓存里，只重做校对/翻译/标题（各 1 次请求），得到的资料与当前代码完成的**完全相同**（同样的哈希） | 当前代码一次点击即可，同样只重做 3 个文本请求。回退后再前进，当前代码读得出 2.7.1 做完的资料，但旧的已中断卡片仍在列表里，直到被移除 |
| 批次，**转写请求在途**（`batch`） | manifest 记着该文件在途 | 一行"已中断"，带「接着做」 | 能：重试把第二个录音再转写一次，完成 | **已知差异**：当前代码对"请求发出去了但没有收到答案"的情况拒绝重来（`remote-result-unknown`，S1-6，不替用户花第二次钱），2.7.1 没有这个保护，会再问一次模型。所以回退会**失去**这道保护；这是回退的代价，已记录 |
| 批次，**答案都已保存**（`batchAnswered`） | 每个文件的结果文件已落盘，提交没落完 | 一行"已中断"，带「接着做」 | 能：不发任何模型请求，发布一次，完成 | 与当前代码逐项相同（同样的资料、同样的哈希、0 个请求） |
| 字幕 / 复查 / 课堂保存 / 课堂校正（`text`） | 这四条路径没有持久化，任务随进程消失（D-9 如实保留） | 没有任务 | 把同样的请求再提交一次：两个版本得到同样的 3 份资料，校正覆盖完整 | 完全相同 |

2.7.1 与当前代码对"回退后可见状态"与"继续后的结果"在 `batchAnswered`、`text` 上逐项相同，在 `single` 上结果相同、点击路径不同，在 `batch` 上差一个明确记录的保护（见上）。

## 8. 已知缺口与限制（记录，不在本步修）

- **回退会失去批次的"在途请求不重来"保护**（见 §4.2）。要保留该保护就不能回退到 2.7.1。
- **2.7.1 的「接着做」在刚启动时可能被 `revision-conflict` 拒绝**：这是 2.7.1 自己的内核缺陷（#303 修了），回退到它时存在；变通是把同一个文件再导入一次。
- **回退再前进后，旧的"已中断"卡片留在列表里**：2.7.1 把工作做完只更新它自己的旧字段，不更新运行时的记录；资料本身是对的，卡片可移除。
- **课堂校正任务在内存里的调用数组随课堂长度线性增长**（约 0.9 KB/调用，约 90 分钟 180 个调用 ≈ 165 KB）：显示有界（`MAX_CALLS = 300`），内存里的有界历史由协调者记为内核后续项。
- **D-9**：字幕/复查/课堂保存/课堂校正重启后任务消失，信箱里旧的失败信仍提示「接着做」而没有可点的卡，没有输入持久化就没有可点的卡。
- 生成家族（出题、补题）的重启恢复清单经同一个存储，理论上适用同一类回退风险，已由 #331 的守卫覆盖形状；本演练只验了音频。
