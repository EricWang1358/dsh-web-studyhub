## 接手次序与开工门禁

1. 读完上表五份文件；保留本页的已定决策。文件中的目标接口和模块名不代表已经实现。
2. 核验 P0：记录 **2.6.0 发布证据、所在 commit SHA、任务控制台验证记录、`docs/job-contract.md` 实际版本**。缺少任一项，先记录缺口，不进入 Sprint 1；不要创建空壳契约来绕过前提。
3. 查看 [sprint-1.md](sprint-1.md) 的接手记录；进入 P2–P6 时再按 [续编](sprints-2-6.md) 的依赖和交接字段，确定第一个尚未通过门禁的步骤。领取该步骤，写明负责人、分支、基线 SHA、文件范围；同一核心文件只有一个修改者。
4. 先完成 S1-0：DSH 能力证据、现有任务服务审计、音频行为清单与特征测试。**评审通过链接是 S1-1 的输入**；不能用“已阅读”“本地看起来可用”代替通过记录。
5. 每个步骤提交证据后交接：已合并 PR、验证所用 SHA、测试命令与结果、未确认项、下一步。未合并的工作不能勾选为完成；上下文不足时重新核对源码，不能凭上一位代理的口述填入结论。

接手者的第一项可执行工作是核验 P0 门禁；门禁通过后执行 S1-0。本次规划与后续文档细化均不算实施完成。DSH 能力的“待核验”不能当作“宿主没有”，也不能据此自写公共部件。

## 一句话目标

新增一种普通后台任务时，主要增加任务定义、业务执行器和必要的详情展示；公共查询、等待、控制、计量、恢复与任务控制台直接复用。

## 已定的决策（不要重新讨论）

- 出题类任务重启后要可恢复（P3 交付）。
- 按资源与实际配额域调度，保留必要的资料/草稿写入互斥；翻译不再无条件排在出题后面（单独开关、单独验收）。
- 状态读旧写新：旧 `done` → `complete`；部分结果用 `result.completeness`，不占生命周期状态。
- 暂停按能力开放：`unsupported` / `queued-only` / `checkpoint`（安全边界检查点暂停）。
- 每日总结与学习流目标是子代理优先，统一入口接入后单独开关启用。
