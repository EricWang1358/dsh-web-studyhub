# S4-9：模型任务家族的回退演练（回到 v2.7.1）

核验日期：2026-10-07。分支 `codex/runtime-s49-rollback`。S4-9（U26）的"指定版本回退"项原先没有证据；本文补上翻译、每日总结、学习流、助教和笔记起草五个家族（音频由 A 道、出题由 B 道各自做）。演练工具沿用 [S5-7](s5-7-acceptance.md) 的做法：`tests/fixtures/runtime-s49/{families,rollback,run-drill}.mjs`，结果记录在 [`s4-9-rollback-evidence.json`](s4-9-rollback-evidence.json)，`tests/unified-runtime-model-evidence.test.mjs` 校验该文件与本文一致。

**固定目标**：标签 `v2.7.1`，SHA `47f132815fc2fa65c7352f3f536109bb9c3ddd96`。

## 1. 演练做了什么

每个家族各做两次——一次**跑完**，一次**还在跑时进程被硬结束**（不 dispose、不清理）：

1. 当前代码、该家族的开关打开、用假模型，给同一个资料库种数据并开始任务；
2. 2.7.1 的树（`git archive v2.7.1`，开关概念不存在）打开同一个库与同一个 DSH_HOME，读取它显示的内容，然后把任务**再做一遍**；
3. 当前代码再打开它读取（回退后再前进）；
4. 把第 1 步的快照放回去，让当前代码自己再做一遍（对照）。

全部使用 fake，没有网络、没有密钥；资料库路径在整个演练里不变（有些目录按库路径取键），所以每次都是把快照放回同一个文件夹。

## 2. 结果

| 家族 | 已完成的产物，2.7.1 读到 | 进行中被结束，2.7.1 读到 | 再做一遍 |
|---|---|---|---|
| `recap`（每日总结） | 同一篇笔记：正文哈希、`generation: done`、修订号都与当前代码读到的相同 | 笔记的生成状态是 **`interrupted`**（2.7.1 会核对死掉的生成进程并如实说"已中断"），不是"运行中" | 能；写出完整总结，状态 `done` |
| `note`（笔记起草） | 同一篇笔记，同一正文哈希 | 状态仍是 **`running`**（2.7.1 与当前代码都没有核对死进程的逻辑，这条没变）；学习者再点一次起草即可 | 能；`done` |
| `translation`（翻译） | 9 个段落的译文，哈希与当前代码读到的相同 | 0 个段落（翻译是一段一段通过后才写入的，还没有一段通过） | 能；9 个段落 |
| `workflow`（学习流讲解） | 同一份讲解（`done`，正文哈希相同） | 讲解记录是 **`running`**（同上，没有进程核对）；再开始即可 | 能；`done` |
| `assist`（助教） | 一条追问记录，问答内容哈希相同 | 没有记录（助教任务只在内存里，没有留下东西） | 能；一条记录 |

**共同结论**（测试固定）：

- 对每个家族和两个阶段，**2.7.1 看到的与当前代码对同一个库看到的完全相同**（`rolledBack.seen == sameCode.seen`）；
- **再做一遍之后两个版本得到相同的库状态**（`rolledBack.after == sameCode.after`），当前代码再读 2.7.1 做完的结果也读得出（`rolledForward.seen == rolledBack.after`）；
- 所以这五个家族迁移到运行时**没有改变任何一条路径的未完成工作的命运**：命运由领域自己的记录决定（笔记的 `generation`、讲解记录、已通过的译文、追问），内核没有留下任何新记录；
- **不需要兼容 checkpoint**：这五个定义都不持久化（`recoveryMode: none`）；`fileKinds` 列出当前代码在库里留下的每一种文件，都是 2.7.1 已经写的种类，测试断言其中没有任何任务/运行时类文件，这些家族也没有往 DSH_HOME 写任何东西。

## 3. 如实写下的限制

- **笔记起草和学习流讲解在进程被结束后会一直显示"运行中"**，直到学习者再开始一次。这与 2.7.1 自己的行为相同（回退没有让它变坏，也没有变好）；每日总结因为带了进程号核对，才会显示"已中断"。要不要给笔记起草和讲解也加这个核对，是产品决定，不在本步。
- 演练里**为你定制（备题）没有做**：S4-4 的备题批次只在 `prepared` 和 `coach-daily.json` 里留下记录，这两种文件 2.7.1 本来就写；它不在本步要求的五个家族里。助教只做了"问答"（`ask`）模式；"改题/出成题"模式是普通的卡片编辑，写的是卡片本身。
- 硬结束是 `process.exit`，不是对进程的强杀；假模型进程不存在，所以没有留下孤儿子进程需要处理。
- 全部是假模型。真实模型下的回退抽样在 S6-7。
- 每日总结的"日期"字段在证据里只记是否有（`dated`），避免证据文件随演练日期变化。
