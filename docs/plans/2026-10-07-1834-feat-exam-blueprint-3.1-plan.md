# Exam Blueprint and Integrated Practice 3.1 - Plan

## Goal Capsule

**Objective**：学生能从自己的考试大纲和历年试卷看清复习依据，完成一个板块的综合题，并知道哪些考点已有独立作答证据、哪些还需练习。

**Authority**：所有者于 2026-10-07 指定本功能进入 3.1.0，要求先设计、再用统一任务框架实现，并用开发记录检验框架的收益。所有者随后补充了组织原则（见下一节）：**考试蓝图是一种特殊的资料，有自己独特的工作流，并且可以选择性地与若干其他资料协作。** 本文仍是供讨论的设计；只有第 1 步（数据模型）和第 2 步（蓝图构建任务，默认关闭）已在本分支实现，第 3–7 步和下面的开放决定尚未获得批准，不授权发布。

**Baseline**：源码核验基于本地分支 `codex/studyhub-3.0.1`（HEAD `16f80101`，包版本仍为 3.0.0）；回退目标为 tag `v3.0.0`（`d18a501c`）。草案原基线 `4d04f751` 作废。3.0.1 的内容合入 main 前，本分支不得先于它发布。

**Open blockers**：开放决定 1（首个学科/板块的输入）已由所有者回答，见下一节；其余待决项见文末“开放决定”（2、3 已于 2026-10-08 答复，另有修订 3 新增的 14–17 待答）。不能把“考试重点”解释为必考概率，也不能把做完固定题数解释为通关。

---

## 组织原则：考试蓝图是一种特殊的资料

草案把蓝图当作“新领域数据 + 新页面 + 两三个新任务”。审计后改为一条主线，三句话：

1. **特殊的资料。** 蓝图是资料库里的一条 *source* 记录，不是新集合、不是旁路 sidecar。它的 `text` 是可读的考点清单（于是 资料 列表、阅读器、引用、选择器、导出、旧版本都把它当一份 Markdown 资料），同一记录上用 `provenance: 'exam-blueprint'` 与 `blueprint` 字段保存结构化的考点表。每个考点的出处是与其他引用同形的资料选区（`sourceId`、`quote`、`start/end`、`documentId`、`revision`），由同一个解析器 `resolveSelectionState` 核验。
2. **独特的工作流。** “从讲义（及可选的样卷、大纲）建出一份蓝图”是它自己的后台工作，只此一种新的任务定义（`exam-blueprint-build`）。综合大题**不**再造生成任务：用现有的案例题生成 `generate { kind: 'case' }`；小题诊断**不**造任务：用现有的 `card.grade` / 评分 / 作答记录。
3. **选择性协作。** 蓝图记录里的 `inputs[]` 写明它由哪些资料、以什么角色（讲义 `lecture`、大纲 `syllabus`、样卷/历年卷 `past-paper`、教材 `textbook`、答案或评分说明 `answer-key`）、哪个修订版本建成。角色是“这一次的用法”，不是资料的属性；一份资料可以在这份蓝图里是教材、在另一份里是大纲。一份资料也不需要都有：没选的角色，对应功能降级并明说（见 (c)）。

## 首版输入（所有者的回答，修订 3）

**事实（所有者 2026-10-07 所述）：** 资料库里目前**没有**期末样卷。所有者将导入：(a) 大学课程的讲义 PPT（`.pptx`；导入器原生读 `.pptx`，旧的 `.ppt` 不支持，导出成 PDF 也可以）；(b) 老师给的**一份**样卷。教材最多只有老师的**推荐**（书名/作者，没有正文，也许永远没有文件）。草案假设的“3–5 份完整历年卷 + 文本大纲 + 教材”在首版**不成立**，计划按真实输入重写如下。

### 角色与证据强度

| 输入 | 角色 | 在首版里的作用 | 不能做什么 |
|---|---|---|---|
| 讲义（逐页的 `.pptx`/PDF） | `lecture`（主要来源，与 `syllabus` 同属“可列考点”的主角色） | 考点**只**从这里来；每个考点的出处是具体哪几页（页/幻灯片为出处单位） | — |
| 一份样卷 | `past-paper` | 给出**考试的形状**：题型、分值分布、命题风格、老师选择考哪些主题；样卷题目通过讲义出处映射到考点 | **不能**给频率统计；一份卷里出现与否不是“考频” |
| 教材（可能只有推荐） | `textbook`（可选） | 若所有者日后导入摘录，就是普通输入；平时只是蓝图上的一条纯文本备注 `recommendedReading { title, author?, url?, note? }` | 绝不是输入、绝不是证据、绝不被要求提供 |

**每个考点说明自己靠什么支撑**（`point.backing`，由出处按角色计数，不由模型自报）：`slides`（讲义中出现于几页）、`samplePapers`（样卷中是否出现）、`kind`（`slides` / `sample-paper` / `both`）。界面文案形如“讲义 3 页 + 样卷”。

**蓝图对自己诚实**（`blueprint.basis`，同样由输入计算）：只有 1 份样卷时标题写“依据 1 份样卷；权重仅供参考”；没有样卷时写“没有样卷：只列出讲义中的考点，不含考试形态与权重”；不足 3 份不计算频率（`frequency: 'not-computed'`；3 是暂定门槛，见开放决定 14）。蓝图**永远不**声称它不可能知道的分布，也不输出“必考概率”。基于一份样卷的“样卷中出现 / 未出现”只是一次观察：未出现**不等于**不考。

### 最小有效输入与降级（在阶段 0 决定，零模型调用）

| 输入组合 | 结果 |
|---|---|
| 没有讲义也没有大纲（含“只有样卷”“只有教材”“什么都没选”） | **拒绝**，原因码 `blueprint-needs-primary-input`，零模型调用。样卷只能说明“考过什么”，不能说明“课上教了什么”；教材备注不是输入 |
| 只有讲义 | 考点来自讲义，状态“待核对”；没有考试形态、没有权重；说明“没有样卷” |
| 讲义 + 1 份样卷 | 首版目标路径：考点来自讲义；样卷提供考试形态，并给各考点标“样卷中出现”；权重仅供参考，不算频率 |
| 讲义 + 样卷 + 教材备注 | 与上一行相同；备注只在蓝图页显示为“推荐阅读（未导入，不作依据）” |
| 日后补导入教材摘录 | 成为角色 `textbook` 的普通输入；仍不是考点来源，只可作为出题时的事实资料 |
| 样卷里有讲义里找不到依据的题 | **不造考点**：该题列入“样卷题未能对应到讲义”，供学生处理（补导入资料或忽略） |

模块层面已强制：没有 `lecture`/`syllabus` 输入则拒绝；每个考点至少一处讲义/大纲出处（样卷不能单独支撑一个考点）；教材从不进入证据。

### 讲义图多字少时怎么办

- **出处单位 = 幻灯片。** 导入后一张幻灯片就是一条 `source`（`document.page` = 页码），出处 `{ sourceId, page, quote }` 由 `resolveSelectionState` 核验（含页码，第 1 步测试已覆盖）。每个考点的“看原页”就是用这个出处打开阅读器的那一页（对应阅读器路线图里的“看原页”浮层，见开放决定 15）。
- **幻灯片没有文字**（内容是图片/图表）：导入器已把它跳过并给出提示“第 N 页没有文字（只有图片或图示）”（`lib/office/index.js` 的 `skippedPages`）。蓝图把这些页码记在输入的 `skippedPages`，在清单里写“第 5 页没有可读文字，未列入”，任务详情里也汇总出来。**不猜、不替图片编考点。** 修补办法由学生选择：把该讲义导出成 PDF 后重新导入走 PDF 路线（仍可能无字），或用 PDF 转换（MinerU/Marker）读图，或接受缺口。
- **文字很少**：一页只有标题或几个词时，考点提取以相邻几页为窗口（滑动窗口，窗口内每个考点仍指回具体页），一页可以不产生考点；标题页、目录页、致谢页在阶段 1 的提示中明确排除。
- **备注页**（speaker notes）已被导入器读入页文本，可作为出处。

### 样卷的题如何对应到考点

样卷按题号切分（阶段 2），每题得到 `{ 题号, 题型, 分值?, 题干引文 }`，再由模型**提议**它考查哪些讲义页（阶段 3）；提议被接受的条件是：给出的讲义出处能在原文中定位、且属于某个已列出的考点。通过后，样卷题干引文作为该考点的一处 `past-paper` 出处写入。因此样卷题总是“经由讲义出处”映射到考点。考试形状（题型/分值分布）作为蓝图的 `examShape` 另存（附加字段，第 3 步实现），只描述这一份卷，不外推。

## Product Contract

### Summary

建议新增“考试蓝图”这种资料：把大纲要求、历年出现记录和学习者的作答证据放在同一条可追溯链上。学生选一个板块，可选地指定若干资料担任历年卷/大纲/教材/评分说明，由一个后台工作建出蓝图资料；再在案例题生成页生成一份共用题干、3–5 个小题的综合练习，按评分项补弱，用不同情境复测。
新工作只增加：一个资料种类（纯函数模块）、一个任务定义与执行器、对案例生成与评分的少量附加字段；任务查询、取消、计量、控制台、阅读器、案例练习页全部复用。


### Problem Frame

学生已有教材、大纲和往年题，但要反复整理“考什么、怎么问、自己哪里不会”。单纯按教材篇幅出题不能表达考试取向；只模仿真题样式又无法说明重点从何而来。
综合题能串联概念与应用，但题目涉及某个知识点不等于已经评估它，做对熟悉题也不等于能迁移到新情境。因此本功能保留考点到题目、评分项和作答证据的映射，不用一个总分掩盖空白。

### Alternatives and Recommendation

可选形态有三种：直接在现有参考题选择器上增加“模仿真题”指令；新增可审查的考试蓝图，再生成综合练习；先建设跨课程的完整证据学习系统。
第一种改动少，但不能可靠回答考频的分母和重点依据；第三种能覆盖长期学习，却把本次试点扩展成已有大型规划。推荐第二种，以单课程、单板块的完整闭环验证价值。

另一种值得保留的视角是从“哪些要求从未被验证”反推练习，而不只从高频题往前推。它能指出历年卷没有出现、却仍在当前大纲中的考点；推荐将这类缺口明确展示，而不是自动降为不重要。

### Requirements

**输入与证据**

- R1. 一次分析绑定一个课程、一个考试范围及一份当前大纲版本；试卷、评分说明和知识资料以不同角色选择。
- R2. 上传沿用资料导入，记录试卷身份、年份/场次、卷别、完整性、来源及内容版本；无法确认的元数据保持未知并允许学生修正。
- R3. 每个大纲考点、历史题目和模型映射都保留可打开的原文位置与引用，映射区分待核对、已确认及有争议。
- R4. 考频由已核验的试卷集合确定性计算，明示分子、分母、排除项和样本局限；模型只提出映射与解释。
- R5. 当前大纲要求、历史出现记录与建议复习优先级分别显示；不输出未经校准的必考概率或通过保证。

**综合练习与反馈**

- R6. 综合题围绕选定板块形成一个可独立理解的题干及有明确目标的小题，输出考点—小题—评分项覆盖表和未覆盖项。
- R7. 每个小题有可核验的解答、分值、逐项评分标准和显式依赖；知识结论来自选定事实资料，历年答案不能自动升级为正确依据。
- R8. 学生先作答再看解答，逐小题保存答案并提交批改；评分失败或评分项缺失保留为未评估，不计作答错。
- R9. 反馈将独立作答、使用提示、看过答案后的练习和尚未测到的考点分开，并提供最小补弱后返回原题的路径。
- R10. “本次已验证”只对该版本、该任务实际评分项成立；板块报告展示覆盖缺口、迁移复测及到期复习，不以完成三四道题宣布考试通关。

**运行与兼容**

- R11. 后台分析、出题与批改走统一任务入口和模型网关，公共生命周期、资源许可、用量、通知各只有一个责任者。
- R12. 任务可取消，重试与重启继续不重复生成已提交产物或重复记分；能力未验收时不得显示可用的暂停或恢复按钮。（修订 2：蓝图构建首版不持久，“重启继续”仅对出题与批改成立，构建任务在进程重启后需从头重试；是否升级为持久，见开放决定 2。）
- R13. 新领域数据采用版本化、可校验的落盘契约，旧资料、题组和学习记录保持可读；回退分别验证启动、产物读取与未完任务继续的范围。
- R14. 首版在合成/获授权材料上给出可重复的质量验收及框架接入成本记录，不用虚构的效率百分比证明框架价值。

### Key Flows

- F1. **建立范围，覆盖 R1–R5。** 在课程中选择“考试蓝图”，导入或选择当前大纲、历年卷和教材。系统提出元数据与题目边界，学生只处理缺失、冲突和低把握项，确认本次统计范围后开始分析。
- F2. **查看依据，覆盖 R3–R5。** 蓝图先显示样本摘要，再列考点：大纲要求、出现于几份卷/哪些年份、常见题型、可用分值信息、映射把握及原题链接。学生可修正一条映射，系统只重算受影响的统计，不重问整批模型。
- F3. **生成与独立作答，覆盖 R6–R8。** 选择一个板块，预览本次准备检验的考点、预计小题数和遗漏，再生成草稿并经过质量检查。发布后复用案例练习页面，逐小题写答案，整题交卷前不泄露其他小题的答案。
- F4. **补弱与复测，覆盖 R9–R10。** 批改给出每个评分项的得分、学生原文证据、缺失点和回到教材的位置。学生选择补弱，完成后回到原题；新的独立变式与稍后复习另计证据，原题订正不充作首次独立掌握。
- F5. **中断后继续，覆盖 R11–R13。** 离开页面不会丢失已保存答案；模型额度耗尽时保留已确认分析和草稿，说明剩余工作。重新打开后显示中断任务，由学生明确继续，不自动重新消耗模型额度。（修订 2：蓝图构建在首版只在进程存活期内可暂停/继续；重启后的“中断任务”仅指出题与批改，见开放决定 2。）

### Input and Corpus Rules

以下是 R1–R4 的推荐首版规则，字段名称须在契约 PR 中定稿。

| 对象 | 必要信息 | 缺失或冲突时的行为 |
|---|---|---|
| 考试范围 | 课程/科目、考试名称、目标大纲版本、选定板块 | 不跨校、跨科目或跨版本默默混算 |
| 大纲 | 原资料引用、修订版本/适用年份、条目边界、要求层级 | 无层级则显示原文，不让模型伪造官方重点 |
| 历年卷 | 逻辑试卷 ID、年份、场次、卷别、适用大纲、完整/节选 | 年份未知的卷可读与练习，但不进入按年趋势 |
| 文件 | document/source 引用、revision、内容指纹、页/段/字符位置、导入与提取结果 | 扫描/OCR疑点保留定位，缺图或公式不完整的题不进入已确认映射 |
| 原题 | 题号/小题号、题干、题型、分值、必答/选答组、引用 | 分值不全就不算整卷分值占比；选答卷只报告题面出现，不能当考生必答率 |
| 答案或评分说明 | 来源、版本、是否官方/学生确认、与题号的关联 | 没有答案仍可做题型/考点分析，但不能据此验证新题解答 |

**统计单位**：一份逻辑试卷是一个样本，跨页与题解副本不是新试卷。相同内容指纹自动折叠文件副本；不同扫描版本疑似同卷时先提示合并，保留所有文件证据。不同年份确实重复命题仍各计一个年度样本。

**主考频**：某考点在选定可比范围内“至少出现一次的完整卷数 / 已审定为完整且可比的卷数”。同卷多个小题只贡献一次分子；题次另列。节选卷单列“已观察到”，不进入完整卷的缺席判断。解析完成不等于卷面完整，完整性必须有学生确认或可核验依据。

**未知映射**：某完整卷有未解析题、争议映射或缺失图表时，该考点频次显示已确认下界与可能上界，不能把未知算成未出现；例如“已确认 2/5，另 1 卷待核对”，而不是伪精确的 40% 预测。没有合格分母时不显示百分比。

**分值**：仅在整卷分值完整且规则可解释时显示分值分布。同一评分点跨多个考点时优先按明确评分子项分配；无法拆分就标注共同涉及，禁止重复累加后声称占比为 100%。选答分值不折算成考生一定获得的暴露权重。

**版本与样本偏差**：不同大纲分层统计；旧纲考点只有在明确对应后才能列作历史参考，不并入当前可比分母。摘要展示年份跨度、缺失年份、完整/节选/排除卷数量，以及来源是否集中于某教师或院校。学生主动挑选的试卷不是随机样本。

**把握与优先级**：映射把握来自引用可定位、术语/题意匹配及人工核对状态，不采用模型自报的百分数。“复习优先”建议先列当前大纲明确要求，再参考历史频次和学生缺口；界面可解释排序理由，保留从未出现的大纲条目。按年趋势先展示逐年事实，不拟合未来命题概率。

### Integrated Question and Assessment

R6–R10 的首个试点建议限定为一个课程板块、一份可用文本大纲、3–5 份完整历年卷及必要教材，产出 1 道含 3–5 个小题的综合题。3–5 份是人工验收可操作的样本规模，不是统计可信门槛；资料少时仍能分析，明确降低可推断范围。

题干应让各小题服务于同一问题，依次考查适用条件、推导/方法选择、应用及条件变化；不能为了覆盖率把无关知识硬拼进去。考点在题干中被提及不算检验，必须至少关联一个实际评分项。若当前板块无法在合理负荷下被一题覆盖，生成器说明遗漏并建议拆题，由学生决定；不擅自把需求改成几十张卡。

小题依赖记录“先前结果是否必要”。评分区分知识错误与上游算错的后续影响：若允许沿用错误中间值，评分标准写明后续方法分如何判断。不能用依赖链让第一问失误把后面所有知识都判为不掌握。依赖必须无环；首版按题面顺序作答，不复用会改变题序的自动先修队列。

参考解答要标明定义、条件、推导和结论所用的知识来源；生成的情境与数值标注为练习设定。题型模仿使用历年卷的组织方式，不复制独特题干、不把未核验答案当教材。独立复核检查题目可解、条件充分、答案不泄漏、评分项总分一致及每个承诺考点确实可评。

批改按评分项引用学生答案。存在合理替代解法时按论证判断，不只做关键词匹配；模型证据无法定位或评分项缺失时保留“待评估”。允许学生指出争议并对同一答案重新评估，但新结果关联同一提交版本，不能重复增加成绩或复习记录。

报告分为“已出题覆盖”“本次独立作答证据”“仍缺证据”，不把它们合成单一掌握百分比。使用提示的结果标为练习证据；一次正确只证明该题本次表现。后续变式改变约束或情境，稍后复习复用已有调度，首版不构造新的全课程掌握认证系统。

### (a) “特殊的资料”在数据模型里是什么（第 1 步）

**已核验的选择**：蓝图 = 一条 `sources` 记录，不建 `documents` 记录、不保留原文件。理由：`documents` 记录描述“一个文件的各修订版本与原件”，蓝图没有原件；没有 `documents` 记录的 source 本来就被 `legacyDocument()` 当作“只有提取文本”的资料，列表、阅读器、选区解析全都支持（音频转写、粘贴文本就是这样）。

| 字段 | 内容 | 谁读 |
|---|---|---|
| `id` | `exam-blueprint-<内容指纹前 40 位>`；同一份蓝图保存两次是同一份，内容变了是新的一份，旧的保持可读 | `sources.ingest` 已有的“同 id 不同 text 则拒绝” |
| `title`、`courses`、`createdAt` | 与其他资料相同；课程由学生选，不写死当前课程 | 资料 列表、课程范围 |
| `format: 'md'` | 让旧版和现有界面按 Markdown 资料显示 | `sourceFormat` |
| `text` | 可读的考点清单：范围、依据资料及角色、编号考点、状态、每个出处的引文 | 阅读器、选择器、任何提示词 |
| `provenance: 'exam-blueprint'` | 种类标记，与 `json-card-self-reference` 同一习惯 | `isExamBlueprintSource` |
| `blueprint` | `{ version: 1, scope?, language?, inputs[], points[], supersedes? }` | 第 2–5 步 |
| `blueprint.inputs[]` | `{ role, documentId?, sourceIds[], title?, revision?, skippedPages? }`，role ∈ `lecture / syllabus / past-paper / textbook / answer-key`；一份 `.pptx` 是一个 input（每张幻灯片是它的一个 source）；`skippedPages` 是没有可读文字的页 | 协作（c） |
| `blueprint.basis` | `{ samplePapers, frequency: 'allowed'｜'not-computed', skippedSlides, label }`，全部由 inputs 计算；label 如“依据 1 份样卷；权重仅供参考” | 蓝图页、清单文本 |
| `blueprint.recommendedReading` | 可选 `{ title, author?, url?, note? }`：老师推荐、尚无文件的教材；纯文本，url 只接受 http(s)；**不是 input、不是证据** | 清单文本 |
| `blueprint.points[]` | `{ id, title, requirement?, parentId?, status: pending/confirmed/disputed, evidence[] }` | 诊断（d） |
| `points[].evidence[]` | `{ sourceId, quote, role, page?, start?, end?, documentId?, revision? }`：与 `materials.selection.resolve` 的选区同形；`role` 总是写入（缺省时由所属 input 推出），`page` 是幻灯片/页码 | `resolveSelectionState` |
| `points[].backing` | `{ slides, samplePapers, kind }`，由 evidence 按 role 计数（讲义/大纲出处按不同页去重，样卷按不同样卷计）；每个点至少一处讲义/大纲出处 | 清单文本、第 3 步 |

**出处如何指向各资料**：每个考点至少一处出处（构建时强制），引文必须在所指 source 的文本里定位成功，否则 `blueprintEvidenceIssues` 报告该点、该处、状态（`missing/ambiguous/stale`）。PDF 的 source 是逐页的，出处自然带页；资料被改版后，旧修订的出处仍按旧修订解析（`resolveSelectionState` 对历史修订的既有行为）；资料被删除则出处变为 `missing`，蓝图保留并标“证据不可用”，不从摘要恢复原文。

**在 资料 列表与阅读器里**：第 1 步不改任何界面——它作为一份 Markdown 资料出现，点开即阅读器，已由测试证明列表分组为 1 项、`materials.document.list/get` 可读。第 6 步再给 `sourceFormat()` 加一个分支和一个格式标签/徽标；`describe()` 当前用固定对象构造行，须把种类带进去（已核验，改动在 `lib/source-groups.js` 与 `ui/SourcePicker.jsx` 的 `FORMAT_LABELS`）。

**注册**：不新增公开操作。写入走已有的内部操作 `materials.v1 sources.ingest`（`lib/runtime/builtins.js`，音频已在用，幂等、拒绝同 id 异文本）；`source.add` 只白名单 `id/title/text/createdAt/courses/format`，会丢掉 `blueprint`，所以**不能**用它（已核验）。第 3 步的 `materials.blueprint.save` 才是对外操作：校验（`normalizeExamBlueprint`）→ 入库 → 把上一版自动归档（`source.archive`）。

**未被选择的方案**：新集合 `examBlueprints`。会动 `domain-contracts.js` 的 `fields/reads`、`store` 的集合定义、导出/恢复、旧版“缺席插件的集合”处理，且 资料 列表、阅读器、选择器、引用解析都要另接——正是“平行子系统”。新集合只在蓝图需要频繁就地写入（如每次勾选考点）时才值得，见开放决定 3。

**体量**：每份蓝图一个分片；上限 300 个考点 × 每点 6 处出处 × 引文 400 字，最坏约 0.7 MB，常规板块（几十个考点）远小于此；超出时拒绝而非截断。

### (b) 它自己的工作流（第 2 步）：一种任务定义

任务种类 `exam-blueprint-build`，定义放进生成上下文的子目录（与 `translation/`、`retrieval/` 并列，开放决定 6），注册到 `managedDefinitions`。

**输入（提交时冻结）**：`{ course, scope: { label }, inputs: [{ role, documentId?, sourceIds, revision?, skippedPages? }], recommendedReading?, language, budget }`。至少一个 `lecture`/`syllabus` 输入，否则在阶段 0 拒绝。提交时按 `inputRefOf` 的做法对每份资料取修订与文本哈希，写入任务详情；资料之后改版不影响这一次，只让结果标“依据已更新”。

**阶段**（每步用确定的 step key，如 `bp:syllabus:<sourceId>:<sectionIds>`；模型只经 `context.gateway.step(...)`）：

| 阶段 | 做什么 | 模型？ | 检查点保留什么 | 阶段边界可暂停？ |
|---|---|---|---|---|
| 0 准备 | 解析输入、冻结修订、按角色检查；给出估算；无任何可用输入则拒绝提交 | 否 | 冻结的输入表 | 是 |
| 1 讲义考点 | 按幻灯片窗口（相邻若干页，每批受字符/页数约束，仿 `assigned-plan`；`sectionsOf` 已把 pptx 按页分段）抽取考点，每个考点附具体页的原文引文；标题/目录/致谢页排除；无文字页只记录、不抽取 | 是（逐批） | 已核验的考点与跳过页 | 批与批之间 |
| 2 样卷切题 | 样卷（首版 1 份）切出题号、题型、题干引文、分值、是否节选；无样卷则跳过此阶段 | 是（逐卷） | 已核验的题目 | 卷与卷之间 |
| 3 映射 | 把样卷题目提议映射到阶段 1 的考点；每个映射带讲义出处，定位失败或对应不到已有考点的题归入“未能对应” | 是（逐批） | 已核验的映射 | 批与批之间 |
| 4 核验与汇总 | 逐处出处用 `resolveSelectionState` 核验，丢弃无法定位的并计数；确定性计算每个考点的 `backing`、`basis` 与分值分布（样卷不足 3 份不算频率）。**实际：核验在每个窗口/每个样卷题的答案一返回就做**（结果与丢弃计数一起进内存缓存，暂停后继续时不重复核验），汇总与保存在最后 | 否 | 汇总表与丢弃计数 | 是 |
| 5 保存 | `context.commitArtifact` → `examBlueprintMaterial()` → `sources.ingest` | 否 | 结果引用 `{kind:'source', id}` | 否（提交点） |

**取消/暂停/继续**（已核验的内核事实）：
- 取消：执行器在每步之间 `context.signal.throwIfAborted()`；进行中的网关调用随信号中止；未保存阶段 5 不留半成品蓝图（全有或全无）。
- 暂停：声明 `pauseMode: 'checkpoint'`，执行器在每批之间调用 `context.checkpoint('stage:n:unit')`；暂停**不会**中止进行中的模型调用，所以状态先是“暂停中”直到当前批返回。**这与旧的覆盖运行“在模型调用准入处暂停”不同**，界面文案不能沿用后者的承诺。
- 继续：`resume` 起一个新的 Attempt（同一个 jobId）。内核不替你跳过已完成的步骤：阶段结果存在领域侧的按任务内存缓存里（不是第二份任务表），已完成的单元用 `step.reuse(reason)` 记为跳过，控制台显示“复用”且不记令牌。进程重启会丢失这份缓存和任务本身（非持久任务仅在内存）。若要重启后继续，须声明 `recoveryMode` 并提供 `persistence.open`（新的落盘文件种类、回退矩阵、形状基线），见开放决定 2；首版建议 `recoveryMode: 'none'`、`retry: true`（从头重试，已完成的单元因同一 step key 与哈希不变而复用缓存时才省额度）。

**令牌与时间估算**：定义没有 `estimate` 字段；估算是领域侧 `lib/token-estimate.js` 的 `BUILDERS`，新增一个 `blueprint` 构建器，输入是冻结的输入表，给出 `{low, high}` 范围与调用数，不给价格。估算作为 `detail.estimate` 随任务出现，提交前的“预估”操作按 `workflow.teaching.estimate` 的先例（`canRunWithoutModel`）不调模型。实际用量由网关逐 Call 记录，控制台的“实际用量”“首 token/输出速度”自动出现。用量归类现有七类 `USAGE_FEATURES`（`generate/repair/coach/flow/case/audio/other`），首版记入 `other`（开放决定 9）。

**控制台详情**：`context.present()` 返回 `detail`（各阶段完成数/总数、输入表摘要、已核验/丢弃的条数、未处理范围）、`stage.text`（未知阶段族时控制台用文本）、`progress`（真实完成的单元数；未知总数时 `total: null`）；调用的 `purpose` 取已有标签（`plan`、`blueprint`、`review`），`blueprint` 这个词在出题评估里已有含义，起名要在界面文案里区分。结果引用 `{kind:'source'}` 让“打开结果”直接进阅读器。所以第 2 步**不需要改 `ui/tasks/**`**，也不改 `lib/jobs/**`。

**第 2 步实际怎么做的（与上面设计不同处，2026-10-08）：**
- **阶段编号：** 0 检查（`planBuild`，零模型调用）→ 1 讲义窗口（每窗口 ≤10 页且 ≤6000 字符）→ 2 样卷切题（每块 ≤8000 字符）→ 3 映射 → 4 保存。进度单位是“步”：窗口数 + 2 × 样卷块数（总数开始前已知）。
- **拒绝码**（阶段 0，均不调模型、不建任务）：`blueprint-disabled`（开关关）、`blueprint-title-required`、`blueprint-input-invalid`、`blueprint-needs-primary-input`、`blueprint-input-missing`、`blueprint-no-readable-text`。
- **答案读不出来：** 同一窗口再问一次（step key 加 `:r`），仍读不出就让整个构建**失败**并说明哪几页，不保存带洞的蓝图（设计原先含糊；此处定为失败，见开放决定 19）。模型调用本身出错（额度、网络）同样是失败。
- **继续 vs 重试：** 暂停后继续复用内存里已完成的单元（控制台显示为复用的调用，不记令牌）；失败/中断后重试**清空缓存、全部重问**，与决定 2 一致。实现靠一个“上一次是在检查点停下的”标记：只有 `context.checkpoint` 抛出暂停时标记为真。
- **只读一次的东西：** 提交时对每份资料取文本哈希做 `scopeHash`；同一范围已有一个在途构建时第二次点击得到同一个任务（`alreadyRunning`），不会重复花额度。
- **估算：** `generation.blueprint.build { estimate: true }` 与 `usage.estimate { feature: 'blueprint', …同样的参数 }` 给出同一个范围，按真实提示词计价（`token-estimate.js` 新增 `blueprint` 构建器），不调模型、不建任务。**控制台没有通用估算控件**，所以估算只由这两个操作返回，不进任务卡（任务卡只显示实际用量）。
- **控制台：** 没有改 `ui/tasks/**` 或 `lib/jobs/**`（测试扫描保证）。任务卡按通用任务画出标题、阶段文字、进度、调用与用量；`contract.detail.blueprint`（各阶段数、丢弃数、无字页、未能对应的题）已在合同里，但控制台不专门画——是否值得加一个面板见开放决定 18。
- **英文文案** 与中文一起写在 `jobs/messages.js`（按请求语言选），没有改 `lib/application-messages-en.js`。
- **`examBlueprint` 开关** 在 `MIGRATION_SWITCHES` 里没有“旧路径”可旁路，登记在清单的 `policySwitches`；关闭时操作拒绝，已保存的蓝图资料照常可读。
- **第 1 步模块的一处追加：** 样卷形态需要地方存，`examShape`（题目标签/题型/分值/所达考点，`unmatched` 列出对应不到的题）加进了 `normalizeExamBlueprint`（附加字段；v3.0.0 读写测试未变）。

**必须同步的公共登记**（计入框架成本，不是业务成本；第 2 步里它们集中在**一个单独的提交**，见开发记录）：`lib/runtime/builtins.js` 的 `managedDefinitions`；`lib/runtime-config.js` 的 `MIGRATION_SWITCHES` 增一个默认关闭的 `examBlueprint`；`docs/plans/unified-job-runtime/s1-7-legacy-exceptions.json` 的 managed 清单（18→19）与背景启动登记；`s6-6-rollback.md` 的开关行；`s6-7-acceptance.md`、`s6-0-coverage.md` 内嵌的计数；`lib/runtime/domain-contracts.js` 的写入字段表与 `actionGrants`（生成上下文需授权 `materials: ['sources.ingest']`）；`lib/contexts/library/operations.js` 的 `usage.estimate`（只接受 generate/selection/case/grade/suggest/audio，须加 `blueprint`）。这些文档只有内核负责人能合并（开放决定 13，已答复：本功能所需的登记改动由 lead 负责，范围见该条）。

### (c) 与若干资料的选择性协作（第 3 步）

**选择**：每个角色一个选择器，复用 `SourcePicker`（参考题选择器就是这样做的）。资料可来自任何课程，选择器逐行显示资料所属课程，蓝图所属课程之外的资料标“其他课程”（现有选择器没有这种标注，已核验，须在第 6 步补）；不设“只能选当前课程”的限制。同一角色同一资料只能列一次；同一资料可以同时担任两个角色（一本合订的“大纲 + 往年卷”；此时出处须写明 `role`）。

**什么都没选 / 缺角色时的行为**：见上文“最小有效输入与降级”（每种都在阶段 0 就决定，不调模型）。答案或评分说明（`answer-key`）只用于给样卷题附分值与评分提示，**绝不**升级为知识依据。第 3 份以上样卷到位后，才走草案 R4 的分母/下界/上界规则。

**每份资料的覆盖与出处**：`inputs[]` 记录用了哪份资料的哪个修订；每个考点的出处各自指向原资料。每份输入的“覆盖”行（贡献了几个考点；对大纲/教材，其叶子小节被考点触及的比例）由 `coverageOf` 计算——把考点当作“带引文的卡片”传入（待核验：`cardPlaceList` 是否接受没有题目字段的对象，否则写一个 10 行的适配纯函数）。覆盖与掌握继续分开：覆盖是“已建模”，不是“已学会”。

**对课程设置的影响**：不自动改课程的 `guidanceSourceIds`/`focusTopics`；学生可在蓝图页一键“用此大纲作为本课评分说明”，那是显式动作。

### (d) 综合大题与小题诊断（第 4、5 步）

**综合大题 = 一次案例生成**。蓝图选定一个板块和若干考点（建议 ≤5，因 `focusTopics` 至多 8 个、每个 60 字，`focus` 至多 2000 字），调用已有的 `generate`：

| 蓝图提供 | 传给案例生成的参数 | 限制（已核验） |
|---|---|---|
| 教材等事实资料 | `sourceIds` | 材料总字符 `CASE_LIMITS.materialChars` 40000，按份均分 |
| 大纲/评分说明 | `guidanceSourceIds` | ≤50，约 6000 字 |
| 历年卷（样式） | `referenceSourceIds` + `referenceFormat` | 默认 5 份/12000 字，硬上限 50 份/100000 字；与事实、评分说明**不得重叠** |
| 所选考点 | `focusTopics`（点名）、`focus`（要求原文摘要） | 见上 |
| 小题数与总分 | `questions` 3–5、`totalMarks` | `CASE_LIMITS` 1–5 题、4–100 分；沿用不放宽 |
| 再来一个不同情境的复测 | `fromDeckId` | 现有“再来一个同类案例”，同材料同形状 |

新增（均为附加）：`request.blueprint = { sourceId, pointIds }` 随 `editorial.generation` 保存；作者提示词与审题提示词各加一个可选的情境类型参数（默认文本不变，现提示词偏信息技术案例，已核验）；作者输出里每个小题带 `pointIds`，每个评分项带 `pointId`；`criterionOf`、`caseCards`、`normalizeGrading`、`compactRubric` 四处白名单与 `normalizeAuthoredCase` 保留这两个字段；小题可选 `dependsOn: [题号]`，保存前检查无环。**覆盖表由代码算**：考点 → 小题 → 评分项，评分项总分为 0 或只在题干被提及的考点记为“未覆盖”，发布前报告遗漏，不以提及率通过（AE4）。因为案例不能续补或并入已有题组，一道综合题就是一个案例题组，不触碰既有合并逻辑。

**诊断复用作答记录**：`card.grade` 写入的 `rubric` 作答记录已含 `criteria[{id,label,score,max,missing}]`、`quiz_id`、`deckId`；加上 `pointId` 后，`pointDiagnosis({blueprint, decks, attempts, runs})`（纯函数）按考点汇总：未测到（无任何评分项）/ 独立作答（首次、非 `retry`、非 `updatedAfterOpening`，沿用 `latestOutcomes` 的剔除规则）/ 练习证据（订正、看过答案之后）；弱项阈值沿用 `WEAK_RATIO = 0.6`。看板零改动的小技巧：蓝图出的小题把 `card.topic` 设为考点标题，现有的“薄弱主题”“错题本”按 `topic` 分组就会按考点显示；稳定的键仍是 `pointId`。补弱沿用 `case.drills`（把薄弱评分项转成补题运行）。缺口：作答记录没有“使用提示”字段，只有运行条目上的 `revealed`；第 5 步先读运行条目，不够就列缺口，不编造证据。另须在蓝图出的题组上拒绝提交不完整评分（`normalizeGrading` 对缺失评分项给 `not-scored` 与 0 分，会被误判为弱），按卡片的蓝图标记启用，既有案例行为不变。

### (g) 为检验框架收益而记录的度量

沿用草案的指标，并加两点：公共接入（上面列出的 7 处登记）单列；开发过程里用到的模型额度，能读到的记数字，读不到的写 `unknown`。每步记录：

| 指标 | 记录方式 |
|---|---|
| 起止时间 | 本文末“开发记录”，用 `date` 的真实时间，不凭回忆 |
| 业务新增/改动 | `git diff --numstat` 按类别：纯函数模块、定义/执行器、操作、UI、测试、文档 |
| 公共接入 | 登记文件清单与行数，单列；每个额外公共接口说明缺口 |
| 内核业务分支 | 对 `lib/jobs/**`、`ui/tasks/**` 的 diff 行数，期望 0；若被迫改，先报告框架缺口 |
| 重复基础设施 | 新增队列/任务表/退避/状态写入/账本的数量，期望 0 |
| 测试 | 新增测试数、复用的公共场景、发现的缺陷 |
| 模型额度（开发期） | 子代理审计等可读的令牌数；未知写 unknown |
| 可比基线 | 与 S4-10（`note.generate`，约 130 行含定义/展示/提交/领域本体与登记）比较接入文件类别，不比较时间 |

### Acceptance Examples

- AE1. **Covers R2–R4.** 同一试卷的PDF、分页文本与答案文件被导入三次，统计仍只有一份卷；同一知识点出现两道小题，卷频分子加一，题次加二。
- AE2. **Covers R3–R5.** 五份完整可比卷中两份确认出现某点、一份有相关未识别图表，显示“已确认2/5，1卷待核对”；修正映射后确定性更新，不能生成新的原文引用。
- AE3. **Covers R1–R5.** 当前大纲新增考点，过去五年未考；界面仍列当前要求和“历史未观察”，不会把它删掉或称为不考。旧大纲同名但内涵变化的条目不能自动合并。
- AE4. **Covers R6–R7.** 综合题承诺覆盖八个点，六个有评分项、两个只在题干出现；发布前报告只覆盖六个并给出遗漏，不以提及率通过。小题依赖成环、总分不符、无来源答案均拒绝发布。
- AE5. **Covers R7–R10.** 学生第一小题算错但后续方法正确，依评分规则给后续方法分；记录对应知识证据而非整串失败。看答案后的订正不替换首次独立作答记录。
- AE6. **Covers R8–R9.** 批改模型只返回部分评分项，答案保持已保存/待评估，成绩和SM-2不变；重试同一提交版本，完整结果只提交一次。
- AE7. **Covers R11–R13.** 分析中取消、草稿提交后崩溃、重复继续、旧Attempt迟到、模型额度耗尽分别注入；无重复产物/记分/用量、无孤立执行器，后续显式继续有可解释状态。
- AE8. **Covers R13.** 3.1写入蓝图资料（含 `blueprint` 字段）及普通综合题组后回到固定3.0，再返回3.1；核对旧学习记录不丢、新证据仍保留，分别报告新旧版本能打开和能继续什么（第 1 步已对“蓝图资料”这一项以 v3.0.0 标签树证明）。
- AE9. **Covers R14.** 真实模型固定一套授权材料，逐条核查映射、引用、可解性、评分一致性和补弱相关性；保留失败样本，不将用户提供的经验描述当产品准确率证据。

> **首版适用性（修订 3）：** AE1–AE3、AE9 假设 3–5 份完整样卷。首版只有 1 份样卷，这几条在纯函数层用合成集合验证，在真实资料上只验证“标签诚实”：显示“依据 1 份样卷；权重仅供参考”，不显示百分比、下界/上界或趋势。

### Scope Boundaries

MVP是一个“范围→证据蓝图→综合题→评分→补弱”的闭环，按 R1–R14 实现。优先支持既有导入后可可靠阅读的文本和PDF/Word投影；扫描图表、手写答案和复杂公式只在提取质量经核验时参与，不默默丢掉题目条件。

后续再评估跨板块三四道题的整体规划、更大规模题库、趋势校准、手写/图形作答、更多学科题型及经验分享。经验分享是所有者考完后可能做的事，不在本次授权中自动发布文章或公开试卷。

不增加联网题库抓取、考试包售卖、同学答案共享或新的模型平台。既有参考题/案例练习、资料覆盖和学习流继续可用；无需先实现完整证据学习系统才开始本试点。
