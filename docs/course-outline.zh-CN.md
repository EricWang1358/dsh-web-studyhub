# 课程总纲

「总纲」页按资料而不是按题组排开当前课程：每份资料、它的章节，以及每一章下面引用了这一章的题。想找课程某一部分的题、只练这些题时用它，不用先想题在哪个题组里。

第一步按资料自己的章节排开这门课，不含 AI 写的文字。第二步加上「生成总纲」：让模型把资料整理成像书一样的「章 → 节 → 知识点」，按学习顺序排好。复习全书的讲解层在总纲的每个知识点下写讲解（见下面的「复习全书」）。按 2026-10-12 的代码核对。

## 怎么进入

首页「学习库」的课程区（课程名和课程进度条下面）有「总纲」链接，打开当前课程的总纲。「返回学习库」回到首页。侧栏里没有这一页。

首页仍然只有一张主卡、一个继续按钮。进度条下面原来折叠的「课程路线」列表去掉了，由总纲取代；进度条和「继续课程」仍按题组顺序走。

## 整理好的总纲（第二步）

还没有总纲时，这一页照第一步那样按资料列出，上面只有一个主按钮「生成总纲」。点一下就在后台开始「整理总纲」任务；不先估算、不弹确认，进度和用量在「任务」页，和别的任务一样。进行中这一页显示「正在整理总纲（i/n 步）…」和「看进度」；可以在任务页暂停、停止（已读的资料清点会保留，不保存总纲）或重试（已完成的模型调用会沿用）。

有了总纲，这一页读起来像一本书的目录：

| 行 | 是什么 |
| --- | --- |
| 第 N 章 | 课程的一章，带一句简介。第一次显示总纲时各章展开。 |
| N.M | 一章里的一节，带简介（没有分节的章直接放知识点）。开始时收起。 |
| N.M.K | 知识点。它收下若干资料行（整份资料，或一份资料的某几章）；展开列出这些行，每行带资料名，再展开是题。只收一行的知识点直接展开成题。同一个知识点下同名的资料（四份「补充笔记 · Reintroduction」）合成一行，「（4 份同名）」。 |
| 其他 | 没有被任何知识点收下的：模型漏掉的，以及总纲做好以后新加的资料。不会被藏起来。 |
| 未归位 | 和第一步相同。 |

每一行都有掌握度（「掌握 62% · 12 题」）、「练这一节」，以及一个勾选框：勾上就选中它下面任意深度的全部题。数字按现在的学习库实时计算，不存进总纲：以后新出、做过或删掉的题马上反映出来。

总纲上方有一行说明学习顺序依据什么（「学习顺序依据：讲义大纲《…》的顺序 · 资料标题里的编号 · 录音的日期」）。模型被要求依次参照：这门课的讲义大纲（名字里有「大纲」或 syllabus 的短资料）、标题里的编号和版本号（01.、Lecture 3、Day1、v2.1）、录音日期和分段、先学什么后学什么；这一行只保留学习库里真有依据的项。旁边是不显眼的「重新整理」，生成新的一版，旧版保留为已归档的记录。总纲做好以后这门课的资料有变化（新增、删除、改名、重新导入）时，这一行会提示「资料有更新，建议重新整理」。

**样卷。** 名字表明是样卷的资料（样卷、真题、sample paper、past paper、exam paper……，考点清单用的同一条规则）默认就用上：按钮下面一行写「依据样卷：……（按名称自动识别，可更改）」，「更改样卷」（折叠）列出这门课的资料，识别出的已勾上。你勾选（或全部取消：不用样卷）的结果记在总纲上，直到你再改。任务会读每份样卷，按在样卷里逐字找到的题目原文，给它考到的知识点标上「样卷考过（N/M 份）」，其余标「补充」。没有样卷时不说任何和考试有关的话。

**只是参考，不是依据。** 总纲是学习库里的一条记录，但不是资料：「资料」页、各个选择器、搜索、计数和所有资料列表都不列它，把它当作资料（拿来出题、当参考资料）的请求会被拒绝。题目照旧逐字引用原来的资料。

**从清点出发。**「生成总纲」和「生成复习全书」都先清点资料（资料清点）：每份资料的每一段页面（整页，一段最多约 15,000 字；样卷不清点）交给模型，列出这一段教的每一样东西——术语、定义、概念、公式、步骤、规则、例子、论断、易错提醒——各带一句话说明、所在页和一句从原文照抄的引文。程序逐字核对每条引文；找不到的保留，但标为未核实。同名的条目（大小写、全半角、标点和括号里的注释不计）在不同段、同一份资料的不同版本之间合并。这些调用按你的文本并发数（「设置 › 音频」，音频流程文本步骤用的同一个设置）并行；每段单独重试，限流时自动降并发、等待；没变的段不会再读。清点是一条隐藏的机器记录（`provenance: 'course-outline-inventory'`），读完就写入，下一次清点替换它。

然后总纲由这些条目整理，而不是按文件名：条目按资料分批（几份资料一批）并行归成**知识点**（学的时候作为一个单元的一组内容，通常几条到十五条左右；大资料会分出很多知识点，讲同一主题的几份小资料合成一个），再用一次调用按学习顺序排成章 → 节 → 知识点（讲义大纲或开课资料、资料的顺序和编号、先学的在前）。每个条目恰好在一个知识点里；模型漏掉的放进最后一章「其他 / 未归位」，不会丢。每个知识点收下它讲到的页：整份资料、整章，或一段页（`doc@s3-7`）；一份资料的每一页都归一个知识点（在那页条目最多的那个；没有条目的页跟着前一页），所以题、「练这一节」和导出照常可用。没有可读文字的资料和样卷在「其他」。在按真实课程搭的测试库里（134 份资料，约 900 道题），是 7 次清点调用、2 次归纳、1 次排序，每 8,000 字样卷再加 1 次；再生成一次时清点和归纳都沿用（只重读样卷）。清点什么都没找到时（没有资料有可读文字），照旧按资料名、章节和题目快速整理。

## 复习全书（讲解层）

复习全书为总纲的每个知识点写一份可以代替课件去学的讲解，并且**对照资料里教的全部内容逐条核查**：这是把资料贴给聊天模型一次问答保证不了的。

**怎么生成。**「生成复习全书」（或「更新全书」）在后台开始一个任务：不估算、不确认；「任务」页显示并行时间线（**清点 · 归纳 · 写 · 审阅 · 修复**，每份资料或每个知识点一条），「知识点」页签列出每个知识点的状态（在写、在审阅、达标、未达标），可以暂停、停止（已读的资料清点会保留，不保存全书）或重试。唯一的前提是这门课至少有一份资料。

**流程，十行说完。**

1. 清点每份资料的每一段页面（并行，引文逐字核对，没变就沿用）。
2. 按清点生成或沿用总纲（知识点由条目组成；每个条目恰好在一个知识点里）。
3. 总纲还没收下的条目按引文所在页放进知识点，放不进的用一次便宜的调用归位，仍放不进就进「其他 / 未归位」。
4. 每个知识点得到一张「必须讲到」清单：它的条目，按「讲解详尽程度」分必讲和可选；资料强调的条目、样卷考到的知识点里的所有条目一律必讲。
5. 每个知识点单独一次调用来写（大的按整页分成每次最多 20,000 字的几遍），所有知识点并行：自由的、面向学习者的文字，用全书的语言，不套固定栏目、不设字数下限；清单里的每个术语在第一次出现处讲清楚，从上一个知识点过渡进来、引到下一个，资料以外的内容标「（资料以外）」。
6. 写的一方要说明讲到了清单里的哪些条目；每个角标都必须在这个知识点自己的页里逐字找到，否则连同标记一起去掉。
7. 一次独立的审阅调用（另一份要求，「设置 › 出题」里的审阅推理档）对照清单和原文检查：漏讲或只点名的条目、原文不支持的说法、矛盾、没解释的术语、缺过渡、难读的段落。
8. 由程序判定：只有写的一方声明讲到、正文里确实出现了名字、审阅也没有指出问题的条目才算讲到；必讲条目都讲到、没有不受支持或矛盾的说法，这个知识点才达标。
9. 不达标的知识点修复（只改指出的地方，问题逐条写明）后再审，最多两轮；仍不达标的保留下来，标「未达标：缺 N 个概念」，绝不显示为完成，任务以「部分完成」结束。
10. 一次写入保存讲解、覆盖情况和「生词与概念」（程序按讲到的条目生成，按字母排序，在「查找」里）；下一次生成，达标且没变的知识点不再调用，只补未达标的。

**覆盖怎么算。** 分三层，在总纲页和书页目录的最上面显示：**资料**（清点读到的有可读文字的资料和页数）、**知识点**（达标：必讲条目都讲到，没有不受支持的说法）、**概念**（所有清单里讲到的必讲条目）。展开的知识点显示「概念覆盖 N/M」和缺的名字；未达标时有「补漏」：单独一个任务，只按缺的清单审阅、修复这一个知识点（从没写成的那一遍单独写）。覆盖是对照资料里实际有的内容清单来量的，从不按字数或模板。

**每个知识点有什么。** 展开后显示「考情」（只在有样卷时）、讲解（Markdown，公式用 KaTeX，角标点开在阅读器里定位到原句）、出处，以及它的概念覆盖。旧版本写的讲解（知识梳理、讲解、例子、补充、「第 a–b 页」分段、斜体过渡句）照旧显示，直到下一次更新重写。

**讲解详尽程度。** 在「生成复习全书」旁边或「设置 › 练习」里选（同一个设置，`settings.book.coverage`，默认「标准」）。它决定哪些条目必讲：「精简」术语、定义、概念和公式；「标准」再加步骤、规则和易错提醒；「详尽」全部条目，例子和论断也算。其余条目作为可选给写的一方。每一档都读这个知识点的全部页。

**只是参考，不是依据。** 和总纲一样，复习全书是学习库里一条隐藏的记录（`provenance: 'course-outline-notes'`），不是资料；题目照旧引用原来的资料。你在书里写的东西不会被它覆盖。

**更新只改变了的部分。** 每份讲解记下它读过的文字、清单、前后知识点、详尽程度和语言的指纹；考情记下样卷位置。没变且已达标的知识点不调用；变了的重写；未达标的补；新的样卷只重写考情；新出的题不算输入。在测试库里（134 份资料，19 个知识点，一份样卷）第一次生成是 7 次清点 + 2 次归纳 + 1 次排序 + 1 次读样卷 + 19 次写 + 19 次审阅 + 1 次考情（缺东西的知识点各再加一次修复和一次审阅）；没变时第二次一次都不调用。每次更新把旧版本保留为已归档的记录。

## 显示什么（没有总纲时）

| 行 | 是什么 |
| --- | --- |
| 资料 | 归在这门课下的每一份资料，还没出题的也列出（「还没出题」）。资料自己没写课程时，按引用它的题组所在的课程算。明确没有归入任何课程的资料、别的课程的资料、已归档的资料都不列，即使这门课的题引用了它们。 |
| 章节 | 资料在「资料」页上的章节：转换书籍得到的章节，或你从保留的目录里应用的章节。没有章节的资料就是一行。 |
| 没对上章节的题 | 有章节的资料里，位置放不进任何一章的题（例如按旧版本出的题，引文在现在的文字里已经找不到）。 |
| 未归位 | 这门课里没有任何资料行收下的题，每题写明原因：没有引用资料；「引用的资料没有归入这门课」（资料没有归入任何课程）；引用的是别的课程或已归档的资料；或引用的资料已被删除。这一组会列出没有归入课程的资料，并链接到「资料」页：在那里把它们归入这门课，引用它们的题就会移到对应的资料行。这些题可以练，不能手动归位。 |

每一行用「资料」列表的说法显示掌握度（「掌握 62% · 12 题」「未学 · 3 题」「还没出题」），并有「练这一节」。如果恰好由这一行的题组成的一轮练习还没做完，按钮会显示「接着练 i/n」，接着那一轮做。

展开一章（或没有章节的资料，或「未归位」）会列出它的题：题目、所属题组、掌握程度，到期的标「到期」。一行最多列 400 题，其余只计数，「练这一节」会一起练。

「按题组筛选」把每一行都缩小到一个题组的题。题组本身不变，这一页不修改题组。

唯一的悬停说明在课程那一行的「总纲是什么？」上。

## 题放在哪里

题的位置和覆盖率用同一条规则：先看它的选区，再看出题计划核对过的位置，再看引文在资料文字里的位置（引文写法略有不同也能找到）。引用某一页的题放在该资料里包含这个位置的那一章；引用资料旧版本、或同一段录音做成的另一份资料的题，按引文在现在的文字里重新找位置。

引用了两章的题两章下都列出，并标「也列在别处」。它在资料合计、课程合计和一轮练习里都只算一次。

题来自这门课的题组：已归档的题组和停用的题不算，和别处一样。还在草稿里的题只计数（「草稿里另有 N 题」），发布后才算进来。

这一页的数字是它自己的：「资料」行统计的是任何课程里引用这份资料的题，总纲只统计这门课的题。「资料」页上的数字没有变。

## 练习

勾选一行就选中它的全部题，也可以单独勾选题目。底部的栏显示选中了多少题（每题只算一次），「练选中的 N 题」开始一轮。行上的「练这一节」开始这一行的一轮。

一轮最多 200 题。选中更多时，按练习的出题顺序取前 200 题，栏里会说明。练习先出到期的题，再出薄弱的题，再出新题，不按总纲的顺序。

练完回到总纲：练习中和结果页上的「回到总纲」会按离开时的样子打开它（展开的行、题组筛选都不变）。在结果页上它是主按钮，这一页原本的下一步只在它是「往下走」时（继续这个范围等）退成它旁边的次要按钮；只是另一个「回到哪里」的下一步（回到学习路径）不显示。420 宽时第二个按钮和主按钮一样宽。

## 限制

- 整理出来的总纲好不好取决于模型；目前只用假模型在一个仿照真实学习库的合成库上核对过，还没有用真实模型在真实课程上验证。
- 「继续课程」、首页和学习地图的新题顺序仍是题组顺序（第三步会优先按总纲）。
- 总纲不能手动编辑；「重新整理」会生成新的一版。复习全书里你自己的内容（你的笔记、放进来的问答、你改过的生成部分）随后会按页跟到新的知识点；如果没有哪个新知识点占到它足够多的页，它就先放在全书的「未归位」，写明最接近的知识点和有多少页在那里。已知限制：一段笔记的页被切成几个部分时，它会跟着最大的那部分走，不管那部分叫什么，哪怕那部分只是它的一小片。书里的章和知识点可以改名、移动、删除，总纲不受影响（见复习全书的「编辑」）。
- 不能手动把题移到别的行。
- 录音只有在资料有章节时才按章节分行；不能跳到录音的某个时间点。
- 复习全书的讲解质量取决于模型；目前只用假模型核对过流程、调用次数和引文校验，还没有用真实模型在真实教材上检查内容好不好。
- 复习全书整体更新；「补漏」只补一个未达标的知识点，书页自己的编辑可以改正文。
- 每次生成有自己的并行调用池，大小是文本并发数：两门课同时生成时，合计最多是它的两倍。
- 清点和归纳的回答按内容沿用（文字、提示词版本、语言），不按模型：换了模型不会重读资料；提示词版本变了才会。
- 一个知识点最多存 80 段（遍）；更长的只留前 80 段，并标「内容过长未全部保留」。很大的课程会把总纲压到最多 800 个节点、每个知识点最多 400 个条目：拆分或合并知识点，从不丢条目。
- 清点的某段或某次归纳失败时，「生成总纲」以「部分完成」结束；下一次只补这些。
- 按页段收下资料的知识点不统计草稿题（草稿按资料统计，不按页）；已发布的题照常统计。
- 没有清点出的概念可以核对的知识点显示「未检查」，不算完成；有条目的知识点至少保留一个必讲条目。

## 开发者

- `course.outline {course?, deckId?, expand?, pick?}`（lib/course-outline.js；放置规则在 lib/course-outline-index.js）按需读取，不随快照发送。不带 `expand` 时返回资料行和计数；`expand: [key]` 加上某份资料的章节或某一行的题；`pick: { keys, cards }` 只返回 `practice: { scope, total, capped, limit }`，`review.start {mode:'path'}` 可以直接使用这个范围。
- `course.outline.qa {course?, keys?, cards?}`（lib/course-outline-qa.js）按需读取一些行（书页「本节问答」的一个知识点）里留下的问答：题目在当前写法下的追问、阅读器里落在这些行位置之内的批注（按偏移所在章节判断，和题目归位同一规则；原文未改）、以及问答卡。最多读 200 道题（`cards: { total, read, capped, limit }`）；每一项是 `{ kind: 'card' | 'passage' | 'qa-card', question, answer, at, place, openRef }`，按阅读顺序。
- 放置结果按学习库版本、分钟、课程和题组筛选缓存。合成的 200 份资料（600 万字符）、3000 道题、600 条写法不同的引文：第一次约 75 毫秒，之后约 5 毫秒；不展开任何行时的返回约 55 KB。
- 页面在 ui/outline/，页面注册表里是 ui/pages.js 的 `outline`。
- 整理好的总纲是一条 source 记录（lib/course-outline-book.js）：`provenance: 'course-outline'`、可读的 `text` 和结构化的 `courseOutline`（最多三层的 `nodes`，每个叶子的 `anchors` 是 `course.outline` 的资料键和章节键；`other`、`orderBasis`、`papers`、资料指纹 `fingerprint`、`supersedes`）。lib/exam-point-list.js 的 `isLibraryListSource` 把它和考点清单一起隐藏。`course.outline` 返回 `book`（lib/course-outline-book-view.js 把它叠在引擎的行上；键以 `bk:` 开头，可用于 `expand` 和 `pick`）。
- `generation.courseOutline.build {course, language?, papers?, supersedes?}` 启动 Job `course-outline-build`（lib/contexts/generation/outline/）：按批的 map 调用、一次 reduce、每段样卷一次调用、一次写入。`papers` 里的每份样卷可以用这门课资料的任一种 id 来写：资料的 key（`doc:…`、`pdf:…`）、资料 id（`document-…`）或它任一页的 id（`source.courses.set` 和 `source.list` 用的就是页 id）；同一份资料的几页算一份，最多 20 份资料（outline/papers.js `paperKeys`，和 `coverage.get` 用同一条规则）。指不到这门课资料的 id 会被拒绝（course-outline-paper-invalid），说明里写出字段、这个 id 和原因：资料库里没有它，或它指的资料归在别的课（写出是哪门，和课程页看到的一致）或已归档；这一步在数 20 份之前做，20 份只数这门课的资料。选的样卷没有可读文字时，拒绝（course-outline-no-readable-text）会写出是哪一份。拒绝码：course-outline-no-course、course-outline-no-materials、course-outline-paper-invalid、course-outline-no-readable-text、course-outline-supersedes-invalid。结果引用 `{ kind: 'course-outline', id, course }`，任务页的打开按钮会转到那门课的这一页。`papersOnly: true` 保留现有总纲的知识点（编号不变），只按 `papers` 重新标样卷；没有总纲时拒绝（course-outline-no-outline）。复习全书的任务进行中时拒绝（course-outline-book-running）。
- 复习全书是一条 source 记录（lib/course-book.js）：`provenance: 'course-outline-notes'`、可读的 `text` 和结构化的 `courseNotes`（`outlineId`、`language`、`leaves: [{ id, title, anchors, body?, exam? }]`、`papers`、`counts`、`supersedes`）。`body` 是 `{ fingerprint, points, explain, example?, extra?, cites: [{ n, sourceId, quote, start, end }], replaces? }`（正文里 `[^n]` 标角标）或 `{ fingerprint, empty: true }`；`exam` 是 `{ fingerprint, tested, note?, replaces? }`。指纹和「是否过期」在 lib/course-book-inputs.js，页面和任务共用。`isLibraryListSource` 隐藏它，`assertMaterials` 以 course-notes-not-material 拒绝。`course.outline` 的 `book.notes` 是 `{ id, stale, missing, changed, leaves, papers }`，展开的知识点在 `open[key].notes` 里带上自己的讲解（lib/course-book-view.js）。
- `generation.courseBook.build {course, language?, papers?}` 启动 Job `course-book-build`（lib/contexts/generation/book/）：需要时先跑总纲的阶段（同一个 Job，`organiseOutline`），再按批写讲解、写考情，最后一次 `sources.ingest`（总纲和全书一起，旧版在同一次写入里归档）。语言跟随请求的 `language`。拒绝码：course-book-no-course、course-book-no-materials、course-book-outline-running，以及总纲自己的拒绝码。结果引用 `{ kind: 'course-book', id, course }`，任务页的「打开复习全书」转到那门课的总纲页。
- 一次整理的粒度（#462）：`granularity`（`coarse` | `medium` | `fine`）决定一个知识点要求多大（outline/constants.js `GRANULARITY`：清点里一个知识点通常包含多少条、一次 map 调用最多给几个点）；`medium` 就是加这个选项之前每次整理的粒度，所以它的提示词和清点里缓存的答案都不变。`maxPoints`（1–800）限制知识点总数：排序（以及 reduce）调用会被要求最多给这么多，outline/fit.js `fitOutline({ leaves })` 再把同一章里最轻的相邻知识点合并直到满足（每个条目和锚点都保留，合并后的点用两个名字，`A / B`）。`fine` 只改变清点的分组调用；快速整理（按资料描述）的 map 调用和 `medium` 问的一样。为了这个上限，它从不合并章，也不合并最后一章「其他 / 未归位」和其中放零散概念的那个点（标 `fixed`）；达不到的部分记成 `counts.overCap`，并在任务里说明。默认两个都不设（和以前一样切）；为了不超过记录的 800 个节点而做的合并，现在合并后的点也用两个名字。一次整理用了什么会记在总纲上（`courseOutline.shape`），所以之后重新整理——包括复习全书自己发起或扩充的那次——沿用同样的粒度；传 `null` 去掉某一项（契约里这两个字段类型放宽，好让不合法的值走到 course-outline-shape-invalid，写明是哪个字段）。
- 整理前先估一下（#462）：`generation.courseOutline.build {course, estimate: true}` 立即回答一次整理会做出什么，**不调用模型、不建任务、不写入**——`estimate: { basis, materials, papers, ranges, calls, items, chars, points, nodes, bodyChars, cut }`：知识点 `points`、目录的 `nodes`、这些点所带正文的 `bodyChars`（每个点会要求写的介绍）。`basis` 说明这些数字依据什么：`inventory`（按资料的清点）、`descriptors`（没有可读文字时的快速整理）、`current`（`papersOnly` 会保留现有总纲，所以它的点数和节点数是准确的）。这些数字跟着粒度（`granularity`、`maxPoints`）和资料量走；它只是预估，不是承诺——点、章和措辞由模型决定。这些尺寸的依据在 lib/contexts/generation/outline/estimate.js（一个清点条目、一个知识点大致对应多少字符）。
- 太短的知识点会说出来（#462）：`minBodyChars`（0 到 360 的整数，不写时 200；0 关闭这个提醒）让一次整理在结果里报告 `bodyWarnings: { minBodyChars, leaves, count, list: [{ nodeId, title, bodyChars }] }`——正文（也就是介绍，复习全书一个知识点的正文由它起步）短于这个值的知识点，按阅读顺序，最多列出前 50 个（`count` 是全部的数量）。它只是报告：写入的总纲和以前完全一样，停止或失败仍然什么都不保存。契约（lib/contexts/generation/outline/contracts.js）声明的正是 `OUTLINE_BUILD_OPTIONS`（outline/plan.js）列出的那些选项（也包括整理自己的 `papersBy`、`inventory` 和 `concurrency`），所以整理接受的参数都能在 `study_capabilities` 里看到。
- 重新整理与复习全书（#461）：lib/course-book-remap.js 按「新知识点占了旧知识点多少页（或条目）」给每个旧知识点的候选排序，占得最多的是最接近的（一样多时取靠前的），并从占比最大的配起、一对一。只有当一个**不同标题**的新知识点占到旧知识点至少 `MOVE_MIN_SHARE`（一半）的页，或者它就是最接近的那个、且它自己至少一半的页在旧知识点里（它是旧知识点的一部分：一份资料被切成几节，切成多少节都跟着最大的那节走）时，才会拿走旧知识点的文件；同标题的新知识点只要和它有共同的页就行（和任何新知识点都不共享页的旧知识点仍可以去一个同名的空位，和以前一样）；否则这个旧知识点被 `held`，它自己的内容进 `unplaced.md`，写明最接近的知识点和占比。`course.book.open` 的 `moves` 是 `{ at, outlineId, total, list: [{ from, to, folded, share?, own?, first? }], held, heldList: [{ from, closest, share, first? }], gone, goneList: [{ from, first? }], revisionAfter, undoable }`。带 `holdRebuild: true`（书页）打开时，如果这次会搬动或放进未归位学习者自己的内容，回答 `{ status: 'rebuild-pending', course, title, moves }`，什么都不写；其他方式打开照常应用。`course.book.rebuild.undo {course?, outlineId}`（lib/course-book-rebuild.js）：还没应用的这次整理就放弃（两份总纲对调，书的文件一个不动）；已应用的按整理前留下的状态退回（`book-history/<课程 hash>.rebuild.json`，由 pushHistory 写，只留最近一次，不进便携备份），前提是书的修订号和文件指纹还是那次整理留下的样子，否则 course-book-rebuild-conflict，什么都不变（那份状态没了就是 course-book-rebuild-no-undo）。写在新总纲上的讲解一起退回；新总纲留着归档，再次保存同一份时重新成为当前总纲（`sources.ingest`）。没有重做。（`list` 只列真的移过去的，最多 `MOVES_KEPT` = 800 条，和总纲节点上限一样，学习者自己写过的排在前面，`total` 是总数；`first` 是新标题下正文的第一行，或放进未归位那段文字的第一行；另列被扣下、而且确实有内容放进了未归位的知识点），移过的知识点带 `movedFrom` 和 `moveShare`；全书页用一行说被扣下的有几个。这门课的全书里有学生自己的内容（自己的文件或问答文件不为空，或改过生成文件）时，`generation.courseOutline.build` 和带 `rebuildOutline: true` 的 `generation.courseBook.build` 以 course-outline-book-confirm 拒绝（不调用模型）并列出这些知识点，直到带上 `confirm: true` 再发；`papersOnly` 不改知识点编号，不需要确认。总纲页的按钮会带上 `confirm: true`（点按钮本身就是同意）。复习全书任务自己重新整理总纲时（资料变了，或者现在的总纲是按资料名快速整理的，`from: 'descriptors'`）不会问：内容照上面的规则按页跟过去，没有哪个新知识点占到足够多的页时放进未归位。已知限制：一份资料被切成几部分时，内容跟着最大的那部分走，不管它叫什么（它唯一的去处是完全在它里面的一小片时，也跟着那一小片）；3.4 按资料整理的笔记，只有新知识点大多是从这份资料切出来的时候才会跟过去，新知识点如果把几份资料里的同一主题归到一起，笔记会先放进未归位。
