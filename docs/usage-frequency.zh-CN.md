# 使用频率记录

*English version: [usage-frequency.md](usage-frequency.md)。*

StudyHub 可以在**本机、由你主动打开**的前提下，记录每个按钮和控件被用了多少次，并生成一份个人使用报告：哪些按钮你每天都在点，哪些功能你从没碰过，哪些东西放错了位置。
它的目的，是让使用 StudyHub 的人（以及你愿意把数字交给的开发者）看清产品的分量到底在哪里。**默认关闭**，StudyHub 的任何功能都不依赖它。

位置：**设置 › 高级 › 使用频率记录**，和「显示实验性功能」并列、互相独立。

## 隐私约定

下面这些是代码的承诺，测试在守着它们（`tests/usage-capture.test.mjs`、`tests/usage-frequency.test.mjs`、`tests/usage-report.test.mjs`、`tests/usage-registry.test.mjs`、
`tests/usage-ui.test.mjs`，以及浏览器流程 `scripts/qa/usage-frequency.mjs`）。

- **默认关闭。** 打开开关之前什么都不记：页面上不安装监听器，不跑定时器，不创建文件；页面只向宿主问一次「记录开着吗」，之后什么都不做。关闭或暂停后，监听器和定时器会再次被移除。
- **一条记录是什么。** 只有：一个稳定的*控件键*、发生所在的*页面*、一个*日期*（`YYYY-MM-DD`，你的本地日期）和一个*次数*；再加每个控件第一次和最近一次出现的日期。没有几点几分，最细到天。
- **绝不包含。** 不含你输入、阅读或回答的内容；不含卡片、资料、课程或文件的名字和编号；不含输入框里的值（点进文本框或编辑器只记作「文本输入框」，它的值、标签、占位符和内容一概不读）；
  不含网址、窗口标题、文件路径。一个控件的名字只有在**它本来就是应用自己的文案**时才会进入键；题组、资料、课程、文件的名字不是应用文案，所以永远进不了键。
- **存在哪里。** 本机上的一个小文件：`<DSH home>/study/usage-frequency.json`。它不在学习库里：学习库的导出、备份和快照都不带它。StudyHub 从不把它发送到任何地方；要不要把导出交给别人，由你决定。
- **由你掌握。** 你可以随时查看（我的使用报告）、导出（Markdown 或 JSON）、暂停和继续、全部删除（有确认）、关闭。关闭只是不再记，已记的内容保留到你删除为止。
- **助手看不到、也改不了。** `usage.frequency.*` 这些操作只供面板使用；助手的 `study_workspace` 工具会拒绝它们。

## 记什么，一个控件怎么得到键

应用根节点上有**一个**委托监听器（捕获阶段的点击，加上文档里写明的键盘快捷键），把你用的东西解析成一个**中英文一致**的键（`ui/usage/keys.js`）：

1. `data-usage` 属性（手工标在不好自动命名的控件上：侧栏各页、做题按钮、开始与生成、添加资料、阅读器的翻译 /「做这几页的题」/「看原页」/ 显示设置按钮、实验性开关；清单见 `lib/usage-registry.js`），取点击位置往上最近的一个；
2. 只属于某一个控件的 class 钩子（`reader-peek`、`nav-reset`、`review-return`），然后是控件自己的 `data-tour` / `data-testid` 或稳定的 id；
3. 否则是 `<页面>/<角色>/<名字>`，名字取控件的可访问名称，**而且只有当它是应用自己的文案时才用**。每句文案的中文原文是英文目录的键（`ui/i18n.js`），页面把它反过来查，所以「Save review settings」和「保存复习设置」得到同一个键。
   数字会被去掉（`开始做这 12 道题` 和 "Start these 12 questions" 都是 `开始做这 N 道题`）；
4. 没有这样名字的控件退回 `<页面>/<角色>`（没有序号，也没有你的数据）。

打字从不计数。按住不放的键和重复事件只算一次（150 毫秒内同一个键算一次）。使用「使用频率记录」这一节本身不计数。文档里写明的快捷键（S、A、?、P、数字键、Enter、方向键、空格、H、T）只在应用自己也会响应它们的地方计数。

## 数字去哪里

次数先在**页面里**累加，再分批发给宿主：有新内容时约每 30 秒一次、窗口隐藏或关闭时、以及你关闭或暂停记录时。（窗口被强行杀掉时，最后几秒的次数可能丢失，别的都不会。）打开记录在当前窗口立即生效；已经打开的其他窗口要重新加载后才开始记录，而宿主一旦告诉它们「已关闭」，它们会自己停下。
记录不读布局、不触发重新渲染；一次事件的开销是一次查表加一次自增，快照不受影响。

文件（`lib/usage-frequency.js`）原子写入（先写临时文件再改名；写入排队，所以多个窗口会累加），并且有上限：

- 最多 **800 个不同的键**，超出的合并进一个 `other` 键；
- 只保留 **180 天**的按天记录，更早的天折进每个键的 `older` 计数，所以「全部时间」仍然正确；
- 最多 24,000 个「键×天」格子（最老的天先折叠），每批最多 500 条；
- 文件损坏或不是我们的文件时，读作「关闭、没有记录」；重新开始就能用。

## 操作（仅面板）

| 操作 | 作用 |
| --- | --- |
| `usage.frequency.status` | 开着还是暂停、有没有数据、有记录的天数、从哪天起、文件在哪里。从不创建文件。 |
| `usage.frequency.set` | `{ enabled?, paused? }`：开关和暂停。 |
| `usage.frequency.record` | `{ records: [{ key, area, day, n }] }`：一批次数。关闭或暂停时被拒绝（什么都不写）。 |
| `usage.frequency.report` | `7`、`30` 或 `"all"` 天的个人报告。从不调用模型。 |
| `usage.frequency.export` | `{ format: "markdown" \| "json", period, language }`：返回文件名、类型和内容。 |
| `usage.frequency.clear` | 删除全部记录；开关保持不变。 |

## 个人报告（设置 › 高级 › 我的使用报告）

记录里有数据之前是折叠的。可看最近 7 天、最近 30 天或全部时间：概览（有记录的天数、互动次数、用过的控件数）；最常用的控件（白话名字、次数、占比和一条横条，每条横条的数字都有文字）；
按页面和按*使用时机*（每天 / 阶段性 / 一次性，来自 `lib/usage-registry.js`，依据 [feature-tiers.md](feature-tiers.md)）的占比；每天的节奏；清单里从没用过的控件；以及最多六条**按固定规则得出的提示**。
不调用模型，也不打分；每条提示都说明是哪条规则，而且都可以不管：

- *忙的控件放在安静的组里*：最近一周用了 8 次以上、分布在 3 天以上，却在「阶段性」或「课程准备与管理」里：可以考虑放进「每天」；
- *30 天没用过*（记录覆盖了 30 天以后才会说）：可以继续收着；
- *有键盘快捷键*：一个月里点了 8 次以上，却很少按快捷键；
- *每天要用的控件一次都没用过*；*某个控件占了 30% 以上*；*多数操作花在不是每天用的控件上*。

记录太少时，报告会直说，而不是瞎猜。

## 导出

Markdown 是一份可读的报告；JSON **只含汇总的次数**：应用版本、时间范围、生成日期（不含几点几分）、概览、每个控件一行（`key`、`count`、`daysUsed`）、按使用时机和按页面的占比、每天的节奏、提示，
以及登记表的「键 → 名字」对照（不用应用也能读懂数字）。没登记的键（页面/角色/名字）在 Markdown 里按页面语言写出名字。导出后由你保存或复制来看，或在你愿意时发给开发者；StudyHub 自己从不发送。

## 给开发者

汇总后的 JSON 导出就是开发者一侧视图要用的单位。**2.5.2 会增加跨多份导出的开发者侧汇总**（2.5.1 里还没有）。登记表（`lib/usage-registry.js`）是稳定的词汇表：给控件加了 `data-usage` 就要登记；
`tests/usage-registry.test.mjs` 会在「标了没登记」「登记了没标」「同一页面中英文产生的键不一致」时失败。
