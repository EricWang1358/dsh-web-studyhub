# 使用频率记录

*English version: [usage-frequency.md](usage-frequency.md)。*

StudyHub 可以在这台电脑上统计你用每个控件的次数，前提是你自己打开它。统计结果会整理成「我的使用报告」：哪些按钮你天天在点，哪些功能从没碰过，哪些可能放错了位置。它帮你看清自己的使用习惯；如果你愿意把导出发给开发者，也能帮开发者看清产品的重心在哪里。

这项记录**默认关闭**，StudyHub 的其他功能都不依赖它。从 2.5.2 起提供。

位置：「设置 › 使用频率记录」。

## 隐私约定

下面这些是代码的承诺，每一条都有自动测试把关（见[开发与验证](#开发与验证)）。

- **默认关闭。** 打开之前什么都不记：页面上不装监听器，不跑定时器，也不创建文件。页面只向宿主询问记录是否开着：加载时问一次（宿主还没启动好时会再试几次），打开「设置 › 使用频率记录」时再问一次。暂停或关闭后，页面会再次移除监听器和定时器。
- **只记次数。** 文件里每个控件只有每天的次数、第一次和最近一次使用的日期，以及累计总数；每个页面只有每天的次数。另外只记着记录是否开着、是否暂停，以及从哪天开始记录。日期是你的本地日期（`YYYY-MM-DD`），最细到天，没有几点几分。
- **不含你的内容。**
  - 不含你输入、阅读或回答的内容。
  - 不含卡片、资料、课程或文件的名字和编号。
  - 不含输入框里的值。点进文本框或编辑器只记作「文本输入框」，它的值、标签、占位符和内容一概不读。
  - 不含网址、窗口标题和文件路径。
  - 控件的名字只有**本来就是应用自己的文案**时才会进入键。题组、资料、课程和文件的名字都不是应用文案，所以永远进不了键。
- **只在本机，不在学习库里。** 记录是一个小文件：`<DSH home>/study/usage-frequency.json`。DSH 主目录默认是 `~/.dsh`，设置了环境变量 `DSH_HOME` 时以它为准。「我的使用报告」里的「记录文件」会显示完整路径。学习库的导出、备份和快照都不带它。
- **StudyHub 从不把它发送到任何地方。** 要不要把导出交给别人，由你决定。
- **由你掌握。** 你随时可以查看报告、导出为 Markdown 或 JSON、暂停和继续、删除全部记录（会先让你确认）、关闭记录。关闭只是不再记录，已有的记录会保留到你删除为止。
- **助手看不到、也改不了。** 只有设置面板能读取和更改这份记录。助手的 `study_workspace` 工具会拒绝所有 `usage.frequency.*` 操作，所以助手既读不到它，也不能打开它或把它发出去。

## 打开记录

1. 打开「设置 › 使用频率记录」。它在左侧列表靠下的位置，紧挨「实验性功能」，两者互不影响。
2. 先读开关上方的四条承诺。
3. 打开「记录使用频率」。状态行会变成「正在记录。还没有记录：照常使用 StudyHub，过一两天再来看。」
4. 照常使用 StudyHub。一两天后回到这里，展开「我的使用报告」。

在哪个窗口打开记录，就在哪个窗口立即生效。已经打开的其他 StudyHub 窗口要重新加载后才开始记录。

## 暂停、关闭或删除

| 你想 | 怎么做 | 已有的记录 |
| --- | --- | --- |
| 暂时不记 | 点「暂停记录」，以后点「继续记录」 | 保留。暂停期间什么都不记。 |
| 不再记录 | 关掉「记录使用频率」 | 保留，仍然可以查看、导出或删除。 |
| 从头开始 | 在「我的使用报告」里点「删除全部记录」，再确认 | 所有次数和日期都会删除。开关保持原样；开着时从当天起继续记录。学习库和已经导出的文件不受影响。 |

## 看「我的使用报告」

有了记录之后，「我的使用报告」会出现在开关下方，默认折叠，展开才显示。关闭记录后它仍然在，直到你删除记录。

先在顶部选时间范围：「最近 7 天」「最近 30 天」（默认）或「全部时间」。

| 部分 | 内容 |
| --- | --- |
| 概览 | 「有记录的天数」「互动次数」「用过的控件」。 |
| 「最常用的控件」 | 最多 15 个，按次数从多到少。每个都有白话名字、次数、占比和一条横条。 |
| 「按页面」 | 用这些控件时你在哪个页面。 |
| 「按使用时机」 | 按登记表里每个控件本来的使用时机归类：每天、阶段性、一次性（依据 [feature-tiers.md](feature-tiers.md)）。登记表以外的控件算作“其他”。 |
| 「每天的节奏」 | 每天一根柱：7 根或 30 根，选「全部时间」时显示最近 60 天。下面写出最忙的一天。 |
| 「从没用过的功能」 | 整份记录里一次都没用过的登记控件，按侧栏、做题、阅读等分组。默认折叠。 |
| 「小提示」 | 最多 6 条，每条都标着「可选」。见下一节。 |

时间范围只管概览、「最常用的控件」「按页面」「按使用时机」和「每天的节奏」。「从没用过的功能」看整份记录。「小提示」不随时间范围变化，每条规则看哪段时间见下一节。

每条横条旁都有文字写出数字。报告不调用模型，也不打分。

### 小提示怎么来

每条小提示都来自一条固定规则，并说明为什么出现。每一条都可以不管。

| 小提示 | 什么时候出现 |
| --- | --- |
| 记录还太少 | 整份记录不到 20 次，或者有记录的日子不到 3 天。这时只显示这一条：报告会直说，不会瞎猜。 |
| 常用页面放在不常用的组里 | 「阶段性」或「课程准备与管理」组里的某个侧栏页面，最近 7 天用了 8 次以上、分布在 3 天以上。可以考虑把它放进「每天」。最多 2 条。 |
| 30 天没用过 | 记录满 30 天后才会出现。最多列出 3 个以前用过、但最近 30 天没用的控件，说明它们可以继续收着。 |
| 有键盘快捷键 | 某个控件最近 30 天点了 8 次以上、分布在 3 天以上，而对应快捷键按的次数不超过点击的五分之一。提示会写出是哪个键。最多 2 条。 |
| 每天要用的控件从没用过 | 记录满 14 天后才会出现。最多列出 3 个一次都没用过的“每天”控件。 |
| 某个控件占比很高 | 最近 30 天至少 30 次操作，其中最常用的控件占 30% 或以上。只针对登记表里的控件。 |
| 多数操作不在“每天”控件上 | 最近 30 天至少 50 次操作，用在“每天”控件上的不到 40%。 |

## 导出或复制报告

「我的使用报告」底部有「导出 Markdown」「导出 JSON」和「复制报告」，按你当前选的时间范围导出。

- 「导出 Markdown」：下载 `studyhub-usage-YYYY-MM-DD.md`（日期是导出当天）。这是一份可读的报告：时间范围、生成日期、StudyHub 版本、一段隐私说明，然后是和屏幕上相同的各个部分。登记表以外的控件按页面语言写出名字。
- 「复制报告」：复制同样的 Markdown 文字。窗口不允许复制时，改用「导出 Markdown」。
- 「导出 JSON」：下载 `studyhub-usage-YYYY-MM-DD.json`，**只含汇总的次数**：
  - 应用名、版本、时间范围、生成日期（不含几点几分）和语言；
  - 概览；
  - 时间范围内用过的每个控件一行：`key`、`count`、`daysUsed`；
  - 按使用时机和按页面的次数与占比，以及每天的节奏；
  - 小提示；
  - 登记表里键与名字的对照（中英文名字、使用时机和分组），不用应用也能读懂这些数字。

在 JSON 里，登记表以外的控件只以键出现：`页面/角色/名字`，名字是应用自己的中文文案。

StudyHub 自己从不发送导出。你可以保存、自己看，或在愿意时发给开发者。

## 什么算一次使用

- **点一下控件**：按钮、链接、标签页、开关、菜单项等。点在普通文字或空白处不算。
- **点进文本框、多行文本框或编辑器**算一次「文本输入框」。打字从不计数。
- **文档里写明的快捷键**，只在应用自己会响应的地方算：
  - `?`、`S`、`A`：任何页面；
  - `P`：阅读器；
  - 数字键 0–6、Enter、← 和 →、空格、`H`、`T`：只在做题页。

  按住 Ctrl、Alt 或 Cmd 时不算，在输入框、编辑器或对话框里不算，阅读器里的 `P` 除外。焦点在按钮上时按 Enter 或空格，算这个按钮的一次点击，不另算一次。
- **重复只算一次。** 同一个控件 150 毫秒内算一次；按住不放的键也只算一次。
- **这一节本身不计数。** 在「使用频率记录」这一节里的操作（开关、报告和其中的按钮）都不记。

每次使用记在你当时所在的页面下。

## 次数怎么保存

次数先在页面内存里按“日期、页面、控件”累加，再分批发给宿主：

- 有新次数后约 30 秒发一次；
- 窗口隐藏或关闭时；
- 暂停或关闭记录之前，以及这一节读取状态、整理报告或导出之前，这样最后几秒的次数也算进去。

一批发送失败时，次数留到下一批。窗口被强行结束时，最多丢失最后约 30 秒的次数，别的都不会丢。页面里最多同时攒 400 个不同的“日期、页面、控件”格子，超出后新的计入 `other`。记录不读取布局，也不触发重新渲染：每次使用只是一次查表加一次自增。

同时开着几个窗口时：

- 在哪个窗口打开记录，只在那个窗口立即生效；其他已经打开的窗口要重新加载后才开始。
- 暂停或关闭会让所有窗口停下。其他窗口在下一次发送时才知道：宿主拒收这一批，窗口就丢掉它并移除监听器。

文件 `<DSH home>/study/usage-frequency.json` 有上限：

- 最多 **800 个不同的键**，超出后新出现的键都计入同一个 `other` 键；
- 按天的次数保留 **180 天**，更早的天并入各键的 `older` 计数，所以「全部时间」仍然准确；
- 全文件最多 24,000 个“键 × 天”格子，超出时最早的天先并入；
- 每批最多 500 条；
- 文件损坏或无法识别时，读作“已关闭、没有记录”；重新打开记录就能从头开始。

## 开发与验证

### 控件怎么得到键

捕获层（`ui/usage/capture.js`）是应用根节点上的**一个**委托点击监听器（捕获阶段），外加 `document` 上的按键监听器，只认文档写明的快捷键。`ui/usage/keys.js` 把控件解析成一个**中英文一致**的键，依次尝试：

1. 文本框、多行文本框或编辑器：一律是 `control.text-field`，不读取它的任何信息。
2. 点击位置往上最近的 `data-usage` 属性。它手工标在不好自动命名的控件上，例如侧栏各页、首页主按钮、做题按钮、生成题组、添加资料、阅读器的按钮和实验性开关。完整清单见 `lib/usage-registry.js`。
3. 只属于某一个控件的 class 钩子：`reader-peek`、`nav-reset` 或 `review-return`。
4. 控件自己的 `data-tour`、`data-testid` 或稳定的 id，记作 `tour.…`、`testid.…` 或 `id.…`。
5. `<页面>/<角色>/<名字>`，名字取控件的可访问名称，**而且只在它是应用自己的文案时才用**。每句文案的中文原文是英文目录（`ui/i18n.js`）的键。`ui/usage/names.js` 用中文或英文都能查到，并统一换回中文原文，所以“Save review settings”和“保存复习设置”得到同一个键。数字换成 `N`：`开始做这 12 道题` 和 “Start these 12 questions” 都是 `开始做这 N 道题`。
6. 没有这样名字的控件退回 `<页面>/<角色>`，不带序号，也不带你的数据。

页面取控件上方最近的 `data-usage-area`，认不出的页面记作 `other`。

写入前，宿主（`lib/usage-frequency.js`）会再检查一遍每条记录，不合格的直接拒收：

- 键不超过 96 个字符，至少含一个字母或数字；
- 键里没有 `@`、`\`、`?`、`=`、`&`、`#`、`%`、`<`、`>`、引号、反引号或控制字符，也没有 `//` 或 `..`；
- 日期是 365 天前到明天之间的本地日期；
- 次数是 1 到 10,000 之间的整数。

文件原子写入：先写临时文件，再改名。写入排在同一个写入者后面，所以多个窗口的次数会累加。

### 操作（仅供面板）

| 操作 | 作用 |
| --- | --- |
| `usage.frequency.status` | 是否开着、是否暂停、有没有数据、有记录的天数、从哪天起、文件在哪里，以及键数和天数的上限。从不创建文件。 |
| `usage.frequency.set` | `{ enabled?, paused? }`：开关和暂停。只传 `enabled: true` 时同时取消暂停。还没有文件、而且结果仍是关闭且未暂停时，什么都不写。 |
| `usage.frequency.record` | `{ records: [{ key, area, day, n }] }`：一批次数，最多 500 条，多出的算作拒收。返回收下和拒收的条数。记录关闭或暂停时什么都不写，返回 `enabled: false`。 |
| `usage.frequency.report` | `{ period?, language? }`：个人报告。`period` 为 `7`、`30`（默认）或 `"all"`，`language` 为 `zh` 或 `en`。从不调用模型。 |
| `usage.frequency.export` | `{ format?, period?, language?, labels? }`：`format` 为 `"json"`（默认）或 `"markdown"`；`labels` 用页面语言给未登记的键起名。返回 `{ filename, mime, content }`。 |
| `usage.frequency.clear` | 删除全部记录。开关保持原样；开着时，起始日期改为当天。 |

### 登记表与测试

登记表（`lib/usage-registry.js`）是稳定的词汇表。每一项有键、中英文名字、使用时机、分组；侧栏页面还有所在的侧栏组。给控件加了 `data-usage`，就要把它登记进去。`tests/usage-registry.test.mjs` 会在两种情况下失败：标了 `data-usage` 却没登记；登记了却哪里都没标，又不是 class 钩子或快捷键。它还检查侧栏各行、首页、做题页、设置页和快捷键面板在中英文下得到相同的键。

守着隐私约定的测试：

- `tests/usage-capture.test.mjs`：键、名字、快捷键、页面内的累加，以及记录关闭时什么都不安装；
- `tests/usage-frequency.test.mjs`：文件、上限、原子写入，以及记录不在学习库里；
- `tests/usage-privacy.test.mjs`：把课程、题组、资料、输入的文字、网址、邮箱和路径放到页面上，全部点一遍，确认这些内容进不了文件、报告和任何一种导出，中英文都查；
- `tests/usage-report.test.mjs`：报告、小提示规则和两种导出；
- `tests/usage-registry.test.mjs`：登记表，以及助手调用不了这些操作；
- `tests/usage-ui.test.mjs`：设置里这一节的每种状态，中英文都查；
- `tests/usage-docs.test.mjs`：让本文和英文版里的数字、名称与代码保持一致；
- `scripts/qa/usage-frequency.mjs`：在真实应用里走一遍流程（先构建 `dist/`），并确认没有请求离开这台电脑。加 `--all` 时跑中英文、深浅两种主题和两种宽度，并检查两种语言记下的键相同。

汇总后的 JSON 导出就是开发者一侧视图要用的单位。使用频率记录和个人报告随 2.5.2 发布；跨多份导出的开发者侧汇总已在计划中，但还没有做。
