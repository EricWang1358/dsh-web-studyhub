# 生成任务可见性与侧栏隔离

原实现的 `Part 1/6 · Repairing flagged questions` 来自后台队列的阶段字符串：每批最多 5 题，作者调用后本地验证引用/结构，再调用编辑审阅，有问题则调用作者修复并复审。这些都是直接模型调用，没有 DSH 子会话。

新实现沿用该质量流程，在原生宿主存在运行中的父代理及 `spawn` 能力时，每次模型阶段通过 `ctx.subagents.start` 创建有名称的子会话，跟随当前模型选择。子代理限制全局工具访问，只处理传入的材料和候选题目。输出必须以 completed 结束；失败或中断的片段不被当作最终答案，已发布的运行句柄在结束后释放。

生成任务记录每次模型任务的阶段、实际运行方式、开始/结束时间和真实子会话 ID。界面可展开记录并打开该子会话。本地结构检查没有子代理；独立预览或缺少原生能力的宿主明确标识为直接调用，不伪造子代理。旧任务没有追溯记录，需新任务才能观察新流程。

遮挡来自学习根元素的 `::before { position: fixed; inset: 0 }`，它绘制到了整个宿主窗口。背景现直接绘制在学习元素上，原生挂载增加独立的布局与绘制容器，弹窗也限制在该容器内。移到侧栏同时恢复主区聊天。

初版验证：59 项自动测试通过。浏览器在 440px 模拟侧栏打开弹窗后，验证遮罩边界没有超出侧栏、左侧按钮仍可点击；模拟任务记录验证阶段翻译和子代理 ID 展示。

## 桌面端后台助教兼容（2026-09-30）

桌面面板可以有已选择的模型和已保存的会话，却没有运行中的父代理。旧助教把这当作完全不支持后台工作，报「当前宿主暂不支持后台助教」，同时实录历史校正还存在模型包装丢失 `spawnCorrection` 能力的问题。

助教解答、修题、生成和历史校正共用宿主能力判断，优先官方 `spawn` 子代理。桌面没有活跃父代理时，只要宿主提供 `agents.create` 和会话工作目录读取接口，就创建新的空闲协调代理，再从它启动实际工作子代理；协调代理不接收模型任务，不恢复或驱动学习者的聊天。两者沿用本次选择的模型，实际子代理返回后依次释放子代理及协调代理。只有宿主缺少原生能力、工具限制或所需的模型覆盖能力时才直接调用模型。助教在提交时固定模型选择。原生启动或运行已经发起后，失败直接结束任务，绝不再自动切换另一条执行路径重做。

助教两条执行路径统一返回有界 JSON，由服务在同一事务中校验和保存。原生助教现在使用 `toolFilter: {allow: []}`；旧的 `study_workspace` 允许列表测试已改为此契约，因为子代理自行写库会绕过超时和题目版本校验。解答仍走已有追问和信箱逻辑；修题复用内容校验、历史版本和撤销；只有本次明确选择了前置知识，才允许关联已有题或新增经过引用校验的前置题。新题继承目标题组课程，补充知识仍以明确标识的补充资料保存。无效结果不会产生半份解答或孤立前置题。

超时、启动失败、运行失败都会结束任务并显示实际原因。晚到的模型输出和基于旧题的结果不会覆盖新内容，已启动句柄在结束后释放。宿主快照包含助教状态指纹，因此即使题库没有变化，失败状态也能刷新。实录历史校正尊重音频设置的文字模型：选 Gemini 时调用 Gemini，选宿主时优先官方子代理，能力不足时独立调用同一宿主模型；语言及轻量包装保留该能力。

接口依据：本机官方 `@deepseek-ai/dsh` 0.2.0-rc.1 内 `dsh-subagent/lib/types/types.d.ts` 的 capability、parent、signal、start/result/dispose 契约。没有把 Codex 自身代理工具当成产品宿主接口。

冷会话模型选择另核对了实际桌面安装包 0.2.0-rc.2 的官方实现：输入框使用 `modelSelection.next`，尚待下一次使用的选择不会被正在结束的旧模型请求覆盖。学习面板优先读取同一投影；尚未恢复为运行中 Agent 的会话，通过 `sessionQuery.observeSession` 读取已保存的投影并释放观察句柄，不为读取模型而启动父代理。按持久化 revision 缓存选择摘要，内容未变的轮询只核对元数据，不重复读取或重放长会话。显式固定的学习模型仍优先；无投影的兼容路径遵循同样的 pending/last-used 规则。

桌面发布须区分代码目录和实际加载的包：桌面 profile 可以安装 tarball 的独立副本，网页 profile 可以链接工作区。修改工作区并不能证明桌面已更新。官方桌面 0.2.0-rc.2 的插件管理器对已安装依赖更新返回 `restart-required`；更新包、完成生效重启、验证运行中功能是三个步骤。有进行中或排队中的学习生成任务时，不能仅凭 Host 通用任务检查判断可重启，因为该插件另有内存任务队列。

## 子代理复用评估（2026-09-30，尚未实现）

依据本机 rc.2 的官方 `SubagentRuntime.startContinuable/sendMessage` 及 continuation activation 实现：持续子代理空闲时收到消息会开始下一轮；已卸载的直属子代理可从持久化会话恢复。一次性 `start` 的运行句柄则没有同样的持续会话契约，不能把保留句柄当成复用接口。

建议按任务身份及角色复用：同一道题、同一题目版本的连续追问保留一个助教；同一批次的作者在审题反馈到达后继续修题。独立审题仍使用独立代理，作者不能审阅自己的历史输出。不同批次并行执行，不能只按 jobId 共享一个代理；当前服务向宿主执行参数只传 stage/jobId，还需显式传 part、角色、题目或材料版本，不能依靠阶段文字猜测归属。课堂历史校正暂保持有界新任务，其输入已经包含窗口、记忆和证据，长期历史反而容易携带旧的听写判断。

复用实现需要：按会话、模型、角色、批次/题目版本确定键；同一子代理串行收件；监听每一轮真实的完成事件，不能把上一轮结束或消息接受回执当成新结果；保存题目版本校验、取消、超时和晚到输出拒绝；明确空闲清理和作业结束清理；冷桌面协调代理的所有权从单次请求提升到整项作业或连续追问会话。换模型、换资料/题目版本或任务失败后应新建。现有持续代理逻辑支持一个阶段内的补充要求，阶段间复用仍是另一个生命周期改动。
