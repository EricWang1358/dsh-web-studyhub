# StudyHub 4.0.0 使用案例与分阶段规划架构书

> 版本：设计稿 v2（取舍后版本）　日期：2026-10-29
> 性质：规划文档，不是已实现说明；不代表已验证的教学效果、用时或费用节省。
> 基线：StudyHub 3.7.2（2026-10-28）的现有架构与能力。
> 原则：**教学上自由，数据上可靠，操作上简短。**

---

## 0. 文档定位与阅读方式

本书回答四个问题：

1. 4.0 要让用户获得什么体验（第 2 章）；
2. 哪些规则必须由代码强制执行，哪些交给模型和用户决定（第 3 章）；
3. 最少需要新增什么，最多复用什么（第 4 章）；
4. 按什么顺序推进，每一阶段如何判断完成（第 5–6 章）。

凡是写成"默认值""初始预算"的数字，都是可通过实测调整的起点，不是教学内容上限，也不是验收的硬阈值。本书不估算人日；工期在 Phase 0 核实涉及组件与宿主能力后再定。

## 1. 版本主张与设计原则

### 1.1 版本主张

> 与主会话自然交谈，就能让这段学习变成右侧可操作、可回看、可继续的学习现场。

4.0 的差异不在于"模型更会讲"，而在于讲解、练习、QA、进度和跨日恢复作用于**同一组学习对象**：主会话的动作会改变右侧，右侧的真实作答又成为下一轮教学的依据。

### 1.2 设计原则

| 原则 | 含义 |
|---|---|
| 代码管事实、权限与数据安全 | 作答、成绩、来源、授权范围、编辑冲突由应用强制 |
| 模型管教学策略 | 先讲还是先练、是否补前置、用图还是推导，由主会话结合现场决定 |
| 应用提供少量稳定操作 | 读现场、定位或准备对象、保存产物；不是一套流程引擎 |
| 复用优先 | 能用现有工具、记录、修订、幂等与作业契约表达的，不另建 |
| 实测后再优化 | 增量协议、租约、预测校准、复杂预热都等到出现真实问题再做 |
| 诚实降级 | 宿主或模型能力不足时，说清楚能做什么、不能做什么 |

### 1.3 不做的方向

- 不建设通用教学引擎、权限平台、消息总线或新存储；
- 不把教学过程写成固定流程（如"错了→前置→更简单的题"）；
- 不为了"避免硬编码"再开发一个规则配置器；
- 不让"可测试"变成"所有教学行为都必须固定"。

## 2. 使用案例

### 2.1 角色与对象

- **用户**：在左侧对话、在右侧原生题卡作答，也可直接操作右侧；
- **主会话**：理解目标、讲解、决定本轮教学动作、调用 StudyHub；
- **右侧工作台**：呈现当前教学内容、练习、QA/笔记、学习状态；
- **学习对象**：资料与锚点、题目（已有或经审核新建）、作答记录、QA、知识点笔记、本次学习记录。

对话操作与直接操作作用于同一对象，不维护两套进度。

### 2.2 用例总览

| 编号 | 用例 | 首次交付阶段 |
|---|---|---|
| UC-01 | 开始一段带学 | Phase 1 |
| UC-02 | 讲解一个知识点并在右侧呈现 | Phase 1 |
| UC-03 | 定位已有练习 | Phase 1 |
| UC-04 | 作答后求助 | Phase 2 |
| UC-05 | 补前置或对照支线，并返回原题 | Phase 2 |
| UC-06 | QA 与笔记归位 | Phase 2 |
| UC-07 | 准备一道经审核的新题 | Phase 2 |
| UC-08 | 查看学习状态、进度与剩余时间 | Phase 3 |
| UC-09 | 暂停、次日或新会话继续 | Phase 4 |
| UC-10 | 能力不足时降级 | Phase 1 起逐步覆盖，Phase 4 收口 |
| UC-11 | 临时问答，不进入带学 | 全程保持 |

### 2.3 主用例叙事（条件概率示例，拟议体验）

用户说："带我学这节条件概率，边讲边练，重要问答帮我整理下来。"

1. **开始（UC-01）**：主会话确认资料范围，建立本次学习；右侧显示本次目标与当前知识点。不要求先建题组或模板。
2. **讲解（UC-02）**：主会话用一个具体例子说明"条件改变了计算范围"，右侧出现对应原文锚点和一个对照表或公式推演。
3. **练习（UC-03 / UC-07）**：有匹配旧题就直接定位；没有则走现有生成审核链路准备一道，右侧显示真实准备状态，成功后才可作答。
4. **求助（UC-04）**：用户在右侧提交后问"我还是分不清两个条件的方向"。主会话读取本题现场（答案、提示使用、揭示状态），先追问确认困惑。
5. **支线（UC-05）**：主会话判断需要一道对照题（可能同难度、表述更清楚，不一定更简单），右侧打开并显示"之后回到原题"；原题输入与揭示状态保留。
6. **归位（UC-06）**：补讲后，精炼的问答写入原题 QA，标注 AI 整理、来源与时间。
7. **返回验证**：用户完成对照题，返回原题或做一道同目标变化题。
8. **状态（UC-08）**：真实结果记录后，右侧显示"独立检验 2/5；另 1 项借助提示完成"及初步时间区间。
9. **暂停（UC-09）**：用户说"今天先这样"，保留位置、QA、已做题与下一步，不在后台继续出题。

### 2.4 用例规格

每个用例只写**触发、主要流程、系统保证、交给策略的部分**。"系统保证"由代码执行；"交给策略"的部分不得写死。

#### UC-01 开始一段带学

- **触发**：用户表达带学意图，并（明示或可推断地）给出资料范围。
- **主要流程**：主会话确认范围 → 建立本次学习记录（范围、目标、设置）→ 右侧呈现目标与当前知识点。
- **系统保证**：
  - 范围必须落在用户已授权的课程/资料内；
  - 本次设置（是否允许准备新题、是否自动整理 QA、是否允许修改笔记）来自用户请求，不由模型自行扩大；
  - 只保存目标与学习位置，不标记任何掌握。
- **交给策略**：目标粒度、是否先给概览、是否先做诊断题。
- **说明**：范围或设置有歧义时由主会话用一句话确认，而不是弹配置面板。

#### UC-02 讲解并在右侧呈现

- **主要流程**：主会话讲解 → 将有用的学习产物（原文锚点、关键解释、推导、对照、图示）放到右侧当前知识点下。
- **系统保证**：内容走现有安全渲染（富文本、公式、表格、受控图形）；不执行任意脚本、不访问网络、不能写成绩或进度。
- **交给策略**：表现形式、详略、是否同时出题。
- **持久化规则**：加载态、动画中间态不保存；恢复当前学习所需的教学块在授权范围内保存；不要求每轮讲解都归档，也不要求用户逐段收藏。

#### UC-03 定位已有练习

- **主要流程**：主会话按知识点与目标在现有题库中选题 → 请求右侧打开 → 用户在原生题卡作答。
- **系统保证**：
  - 打开请求与实际显示是不同事实：能获得显示确认才说"已在右侧"，否则说"已请求打开"；
  - 过期的异步打开请求不得抢走用户已经切换到的新现场；
  - 作答只由原生面板收集，模型不代答、不自评。
- **交给策略**：选哪道题、一次几道、是否先讲再练。

#### UC-04 作答后求助

- **主要流程**：用户在左侧提问 → 主会话读取本题相关现场 → 追问或解释。
- **系统保证**：读取结果反映最新提交、提示使用与揭示状态；读取有界，不携带全库或全部历史。
- **交给策略**：是否追问、判断错因、下一步动作。
- **说明**：纯解释性追问（如"你上一句的分母是什么意思"）不强制读现场。错因判断属于 AI 教学判断，可被用户纠正，原始答案始终保留。

#### UC-05 支线与返回

- **主要流程**：主会话打开支线题，并记录返回位置 → 右侧显示返回入口 → 用户完成后点击返回，或主会话调用返回。
- **系统保证**：
  - 原题的未提交输入、揭示状态、轮次与返回位置可恢复，宿主重启后亦然；
  - 支线练习与原题练习分开记录，不重置原题成绩；
  - 用户明确要求离开当前题时，保存草稿后正常切换，不再额外确认；只有草稿无法可靠保存或目标有歧义时才确认。
- **交给策略**：是否开支线、支线是前置、对照还是变化题、难度如何、是否继续深入。
- **说明**：首版只需支持有限嵌套和清楚的返回链；不建设通用分支栈引擎。

#### UC-06 QA 与笔记归位

- **触发**：已启用自动整理，或用户说"记到这题下面""加入笔记"。这句话本身就是保存授权，不需要另点相同确认。
- **主要流程**：主会话把本轮解释精炼后写入本题 QA 或知识点笔记；知识点级内容通过引用关联题级 QA，不复制多个版本。
- **系统保证**：
  - AI 写入的内容标注来源与时间，可编辑、可删除、可回溯修订；
  - 默认不覆盖用户内容；用户明确要求"重新组织我这段笔记"时可以修改，走现有版本检查与修订记录；
  - 可能被重复提交的写入使用幂等标识，模型重试不产生重复 QA；
  - QA 中声称引用资料的部分，可复用现有引用比对做轻量检查。
- **交给策略**：哪些内容值得沉淀、写到题级还是知识点级、措辞与结构。
- **边界**：QA 默认不作为出题事实来源；用户若将个人笔记作为资料导入，则走现有材料链路，不硬编码禁止。

#### UC-07 准备一道经审核的新题

- **主要流程**：复用不到合适的题时，主会话通过现有生成审核链路请求一道题（小资料范围、数量 1）→ 右侧显示准备、失败或部分完成 → 成功后才进入练习。
- **系统保证**：
  - 不得用未审核的聊天文本冒充正式练习；
  - 生成可取消、有预算、失败按现有分类用人话说明；
  - 新题默认保存在本次学习范围，不进入公开或外部发布；
  - 生成费用单独计入。
- **交给策略**：等待期间是否继续讲解、失败后改用复用题还是换个讲法。
- **说明**：先验证现有链路处理"1 道题 + 小范围"的实际等待；确有瓶颈再优化，不先复制一条"快速通道"运行时。

#### UC-08 学习状态、进度与剩余时间

- **主要流程**：真实结果记录后，应用按规则更新状态；主会话读取后说明下一步理由。
- **系统保证**：
  - 进度只由已记录证据推导，主会话一句"你已经懂了"不能改进度；
  - 讲解覆盖与练习掌握分开显示；
  - 课程总目标与本次目标的分母分开；
  - 目标范围变化时留有说明，不能通过缩小分母制造突增。
- **交给策略**：目标拆成哪些检验项（由主会话根据本次目标提出，用户可调整）。
- 计算口径见 4.6。

#### UC-09 暂停与继续

- **主要流程**：用户说暂停 → 保存位置、QA、已做题、下一步 → 下次说"继续昨天这节" → 主会话读取本次学习记录与真实练习，右侧恢复对应内容 → 主会话决定先回未完成题，还是在用户接受后做一次短检验。
- **系统保证**：不读取其他会话的私有完整聊天；资料修订或旧题变化时明确提示，不把旧依据当作当前事实；暂停后不在后台继续出题。

#### UC-10 降级

| 情况 | 行为 |
|---|---|
| 模型不可用 | 带学开始前说明；阅读、练习、复习、查看 QA 照常可用 |
| 无法生成新题 | 只复用已有题，并明确说明 |
| 无法确认右侧已显示 | 只说"已请求打开" |
| 面板不能主动向主会话发消息 | 题卡"请教"按钮预填带对象引用的请求，由用户点击发送；不声称已自动发送 |
| 宿主缺少某项能力 | 通过 `study_capabilities` 暴露，按能力选择路径 |

#### UC-11 临时问答

用户只想问一页资料时，不建立本次学习记录，不写 QA，不产生进度。4.0 不强迫所有使用都进入结构化学习。

### 2.5 用户随时可以改变策略

以下表达不需要分别开发工作流，主会话调整策略即可，应用只检查动作是否合法：

- "先让我试，不要先讲。"
- "今天只理解，不出题。"
- "公式我会，直接练应用。"
- "不要再补基础了，回原题。"
- "跳过这题 / 换一道 / 先看解释 / 结束。"

## 3. 边界划分：什么固定，什么不固定

### 3.1 四层划分

| 层次 | 设计方式 | 例子 |
|---|---|---|
| 可信边界 | 代码强制，不随意放松 | 不代答、不伪造成绩、不越权读写、不丢输入、不静默覆盖用户内容、正式新题经过审核 |
| 教学策略 | 模型结合现场决定，用户随时改变 | 讲练顺序、是否补前置、题量、表现形式 |
| 性能与成本目标 | 默认预算 + 实测调整 | 现场大小、工具调用数、生成等待、整理频率 |
| 高级优化 | 出现真实问题再建设 | 增量协议、租约、预测校准、复杂预热 |

### 3.2 硬边界清单（代码强制）

1. **作答真实性**：答案、提示、揭示状态只由原生面板产生；模型不能代答、自评、标记完成。
2. **证据驱动状态**：进度与掌握状态只从已记录的作答推导；AI 对开放回答的判断单独标注。
3. **范围与授权**：读写限定在本次学习的授权范围；设置来自用户请求与已有权限，模型不能自行扩权。
4. **输入保护**：切换对象前保存草稿；迟到的异步请求不得抢走当前焦点。
5. **写入安全**：可能重复的写入幂等；修改已有内容需版本检查；保留修订。
6. **用户内容**：默认不覆盖；明确请求后可改，且可回溯。
7. **新题信任**：正式练习必须经过现有生成审核链路。
8. **渲染安全**：不执行任意脚本，不访问网络，组件不能写成绩或进度。

### 3.3 由默认策略转化而来的规则

以下在早期讨论中曾被写成硬规则，现降为默认策略：

| 原硬规则 | 现在的默认策略 |
|---|---|
| 每轮都读现场 | 涉及当前题、最新提交、导航或保存时读取；纯讨论不强制 |
| 现场 ≤ 固定 token 数 | 返回最小充分上下文，长内容按引用展开；预算用于发现异常，不截断必要条件 |
| 有草稿就不能跳题 | 用户请求离开时保存后切换；只在无法保存或有歧义时确认 |
| 讲解一律不落盘 | 恢复所需内容在授权内保存，临时态不保存 |
| 模型永远不能改用户块 | 默认保护，明确授权后可改 |
| 绝不再调用摘要模型 | 默认复用本轮内容；长篇或跨多题整理在授权内允许额外调用 |
| 教学形式必须是预定义组件 | 默认富文本、公式、表格、图形；真有交互需求才加受控组件 |
| 错答 → 前置 → 更简单题 | 由主会话判断错因并选择动作 |

## 4. 架构

### 4.1 总体结构

```text
用户 ──对话──▶ 主会话（理解、讲解、决定下一步）
  │                    │
  │                    ▼
  │        薄操作适配层（能力分类，不是新平台）
  │          · 读现场  · 定位/准备对象  · 保存产物
  │                    │
  │                    ▼
  │        3.x 已有上下文与机制
  │          资料/锚点 · 题库与生成审核 · 原生练习与 FSRS-6
  │          题目追问/QA · 知识点书页/笔记 · 作业契约
  │          修订 · 幂等与回执 · 快照指纹轮询
  │                    │
  └──直接操作──▶ 右侧工作台 ◀───────┘
               （教学内容 · 当前练习 · QA/笔记 · 本次状态）
```

"三个操作"是能力分类，**不要求开发三个新工具**。已有工具（例如主会话查询、`panel.current`、`panel.open`、题目追问与笔记工具）能表达的直接复用；只有当主会话调用明显繁琐、出错率高时，才增加薄封装。

### 4.2 复用与新增

| 类别 | 内容 |
|---|---|
| 直接复用 | 资料阅读与锚点、题目身份、原生作答与记录、FSRS-6 调度、生成审核链路与作业契约、题目追问、知识点 QA 与书页修订、幂等与版本检查、快照指纹轮询、`study_capabilities`、主会话按需查询 |
| 需要核实与补齐 | `panel.open` 的显示确认能力；资料锚点与教学块在右侧的呈现；不同对象写入范围是否能被主会话一致调用；草稿保存是否跨切换和重启可靠 |
| 最小新增 | 本次学习记录；紧凑现场读取；返回位置；检验项与进度聚合；时间区间估算；右侧按动作调整的布局 |
| 暂不建设 | 增量现场协议、属主租约与接管、持久导航状态机、预测校准引擎、通用教学组件库、新权限平台 |

### 4.3 本次学习记录（唯一主要新增状态）

只保存恢复与权限判断所需的最小内容：

```ts
type StudySession = {
  id: string
  courseId: string
  scope: SourceRef[]              // 本次资料范围
  goal?: {
    title: string
    checkItems: CheckItem[]       // 见 4.6
    scopeNote?: string            // 目标变化时的说明
  }
  settings: {
    allowNewQuestions: boolean
    autoOrganizeQA: boolean
    allowNoteEdits: boolean
  }
  focus?: ObjectRef               // 当前对象
  returnPath?: ObjectRef[]        // 支线返回位置，有限长度
  artifactRefs?: ObjectRef[]      // 恢复所需的教学块引用
  status: "active" | "paused" | "ended"
  version: number
  updatedAt: number
}
```

归属需在 Phase 0 按 ADR-02 的纪律决定：优先放入已有的学习流/学习者相关上下文；只有现有上下文无法合理承载时，才新建一个小上下文。草稿内容沿用原生面板现有存储，此处只记引用。

### 4.4 现场读取

- 由已有上下文的**有界读取**聚合，不能先构建整库快照再截取；
- 默认内容：范围与目标摘要、当前对象（题干、选项、揭示状态）、最近几次相关作答（含提示使用）、返回路径、当前状态摘要；
- 资料全文、历史 QA、长题干通过引用展开；
- 能复用快照指纹判断"没有变化"就复用；不在首版建立每个会话的增量游标；
- 上下文丢失、新会话或版本不匹配时，总能重新读取完整的紧凑现场。

### 4.5 各操作需要的字段

不是每个动作都要携带全部机制：

| 操作 | 通常需要 |
|---|---|
| 读当前现场 | 范围、对象引用 |
| 打开已有对象（异步） | 目标、所属面板/会话、简单新旧标识用于过期检查 |
| 新建 QA / 教学块 | 幂等标识、目标对象 |
| 修改已有笔记 / QA | 对象版本 |
| 请求新题 | 现有生成作业参数与 `operationId` |
| 更新本次学习记录 | 记录版本 |

### 4.6 进度与时间口径

**检验项**由主会话根据本次目标提出（例如"独立辨别条件方向""选对公式并说明理由""在变化情境中应用"），展示给用户并可调整。开发者不为每门课手写规则。

每个检验项状态由作答记录推导：

| 状态 | 含义 |
|---|---|
| 待检验 | 尚无相关作答；不等于"不会" |
| 借助提示完成 | 使用了提示或揭示后完成 |
| 已独立通过 | 未用提示独立完成；同一检验项重复通过不重复计分 |
| 需复核 | 后续出现矛盾证据 |

**显示口径**：

> 独立检验 2/5（40%）；另 1 项借助提示完成，2 项待检验。

- 主数字只计"已独立通过"；借助提示的完成单列，**不计入独立进度**；
- 隔日巩固单独显示，不放进今天目标的分母；
- 开放回答的判断标注为 AI 判断，保留原话；
- FSRS-6 继续只管单题复习调度，不改名为知识点掌握率；
- 计算是纯函数，可单元测试，不调用模型。

**剩余时间**：

- 估算目标是"完成本次检验项"，不是"彻底学会"；
- 初期使用明确标注的经验区间，按剩余检验项与已发现的前置缺口给出；
- 有了可靠的活动用时后再更新区间；生成等待、暂停和纯阅读分开，不把"打开到提交"的墙钟时间直接当有效学习时间；
- 目标或路径明显变化时记录一次预测与依据，供日后对照；不在每次显示时写账本；
- 证据不足时显示"尚在估计，完成首个检验后更新"。

### 4.7 成本口径

- 导航、保存、渲染、进度计算不调用模型（沿用 ADR-04 的 `requiresModel` 声明）；
- 主会话的推理、读取工具结果、生成工具参数仍计入模型用量，不能写成"对话同步免费"；
- 默认复用本轮讲解内容进行整理，不为每次保存单独调用摘要；
- 学习总结分行报告：教学对话、复用题、新题生成与审核、QA 整理；
- 额外报告"每个独立通过检验项的总成本"，用于判断 4.0 是否值得。

## 5. 分阶段规划

对内分阶段推进，对外**一次发布完整主路径**，不交付换皮侧栏。总开关默认关闭，内部按阶段开启（沿用 3.x 默认关闭开关的做法）。

```text
Phase 0  核实与基线        ─┐
Phase 1  带学骨架与定位     │ 内部，开关默认关闭
Phase 2  求助、支线与归位   │
Phase 3  状态、进度与时间   │
Phase 4  恢复、降级与发布 ─┘ → 4.0.0 对外发布
```

### Phase 0：现状核实与基线

**目标**：用事实决定要新建什么，避免先造平台。

| 项目 | 内容 |
|---|---|
| 核实 | `panel.open` 能否得到显示确认；`panel.current` 返回哪些字段；草稿在切换与重启后是否保留；题目追问、知识点 QA、笔记、书页工具的写入范围是否可被主会话一致调用；现有生成链路处理"1 道题 + 小范围"的实际等待与费用 |
| 原型 | 只用现有工具，让主会话手动走一遍主用例，记录卡点 |
| 基线 | 同一资料与目标下，网页版对话学习、3.x、Phase 0 原型的操作数、重述次数、等待和费用 |
| 决策 | 本次学习记录归属哪个上下文；哪些操作需要薄封装；是否需要新增任何工具 |
| 产出 | 能力差距清单、薄封装列表、基线数据 |
| 退出条件 | 每个缺口都有"复用 / 补齐 / 新增"的明确结论；无未知的宿主依赖 |

### Phase 1：带学骨架与定位（UC-01、02、03，UC-10 部分）

**目标**：用户说"带我学"，右侧随讲解与练习变化。

| 项目 | 内容 |
|---|---|
| 交付 | 本次学习记录的建立、暂停、结束；紧凑现场读取；定位已有题与资料锚点；右侧教学内容区（复用安全富文本）；诚实的打开反馈；草稿保存后切换；按当前动作调整布局；模型不可用时的开场降级 |
| 硬边界 | 不代答；范围校验；过期打开请求不抢焦点；草稿不丢 |
| 不做 | 新题生成接入、支线、自动 QA、进度 |
| 退出条件 | 用户说"出一道练练"后，已有题无需进入管理页即可作答；纯讨论不触发多余工具调用；现场读取不携带全库；草稿在切换与重启后可恢复 |

### Phase 2：求助、支线与归位（UC-04、05、06、07）

**目标**：从"这里不懂"到继续学习，不需要复制题干、手动找题或搬运笔记。

| 项目 | 内容 |
|---|---|
| 交付 | 求助时读取本题现场；支线打开与返回路径；返回入口常驻；QA 与笔记按授权自动归位（标注来源、可修订）；用户请求时可编辑用户内容；通过现有生成链路准备单题，并显示准备状态；题卡"请教"预填 |
| 硬边界 | 支线不重置原题成绩；QA 写入幂等；默认不覆盖用户内容；未审核题不进入正式练习 |
| 不做 | 独立的快速生成运行时；块级所有权系统；任意 HTML 组件 |
| 退出条件 | 求助无需复制题干；支线返回后原题输入与揭示状态完整；同一 QA 不因重试而重复；新题失败时主会话能继续教学并说明原因 |

### Phase 3：学习状态、进度与时间（UC-08）

**目标**：用户看得见真实进展，且每次变化都能追溯到具体作答。

| 项目 | 内容 |
|---|---|
| 交付 | 检验项（主会话提出、用户可调整）；状态纯函数；"独立检验 x/n"主显示与借助提示单列；详细依据可展开；隔日巩固单列；经验时间区间与"尚在估计"状态；目标变化时的预测记录 |
| 硬边界 | 状态只由记录推导；分母不因临时支线悄悄改变；讲解覆盖不计入掌握 |
| 不做 | 个体化预测模型、复杂校准、知识点认知测量模型 |
| 退出条件 | 每次进度变化可追溯到作答；借助提示的完成不计入独立进度；只读讲解不改变掌握；时间显示总有明确目标与区间或"尚在估计" |

### Phase 4：恢复、降级与发布验证（UC-09、10、11 收口）

**目标**：跨日可继续，能力不足时不说谎，并验证 4.0 确实优于现状。

| 项目 | 内容 |
|---|---|
| 交付 | 次日或新会话继续；资料修订、旧题变化提示；完整降级矩阵；临时问答不产生学习记录；学习总结中的分项费用 |
| 验证 | 脚本化的假模型教学循环测试；故意破坏测试；与网页版、3.x 的对比实验（含即时学习与隔日继续） |
| 退出条件 | 满足第 6 章发布门槛 |

### 阶段依赖与可并行部分

- Phase 0 是所有阶段的前置；
- Phase 3 的纯函数与显示可在 Phase 2 期间并行开发，接入依赖 Phase 2 的作答元数据；
- 降级能力从 Phase 1 开始逐步覆盖，Phase 4 只做收口与验证。

---

## 6. 发布门槛（4.0.0 对外）

用户可以从头到尾完成：

> 讲一个知识点 → 主会话定位已有题或准备经审核的新题 → 用户真实作答 → 用户求助 → 主会话补讲或开支线 → QA 归位 → 返回原题 → 右侧显示有依据的进展与初步时间区间 → 暂停 → 下次继续。

缺少任何一环都不算 4.0.0 完成。进度与时间估算成熟度不足时，显示"待检验"与依据，**不得从发布范围中删除这项需求**，也不得输出假精确数字。

---

## 7. 验证与度量

### 7.1 测试重点

测试系统是否守住硬边界，而不是规定老师每次按相同顺序调用工具。

| 类别 | 内容 |
|---|---|
| 边界 | 范围外读写被拒绝；模型无法写成绩或进度；未审核题不能进入练习 |
| 写入 | 重试不产生重复 QA；修改已有内容的版本冲突被拒绝；用户内容默认不被覆盖 |
| 输入保护 | 切换、支线、重启后草稿与揭示状态可恢复；过期请求不抢焦点 |
| 证据 | 借助提示的完成不计独立通过；重复作答不重复计分；反证转为需复核 |
| 恢复 | 次日继续不依赖其他会话的私有聊天；资料变化被明确提示 |
| 故意破坏 | 模型调用失败、生成审核失败、面板导航中关闭、迟到写入、设置撤销后仍尝试写入 |
| 性能 | 现场读取不随库规模无界增长；沿用现有性能预算测试 |

用脚本化的用户语句驱动假模型跑教学循环，断言对象和记录的变化；这契合 3.x 现有的纯模块测试方式。

### 7.2 体验度量（目标，不是实测结果）

- 用户管理操作数与重述次数；
- 从求助到可以继续作答的等待时间（双栏方案相对网页版最可能失分的指标，应优先观察）；
- 教学与出题调用次数、实际费用、每个独立通过检验项的成本；
- 次日独立应用表现。

不以更多点击、更长聊天或更多生成题作为学习效果的证据。

---

## 8. 明确不做（4.0.0）

多用户云协作；全库自动出题；任意脚本写成绩；全自治课程规划；通用 HTML 应用执行器；每次错答自动触发模型；默认读取其他会话私有历史；后台运行时大迁移；新消息总线、新存储、新权限平台；完整增量现场协议；属主租约；持久导航状态机；预测校准引擎。

这些不是永久否决，而是"出现真实问题、有数据支撑后再评估"。

---

## 9. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 宿主无法确认右侧显示 | 主会话可能误报"已在右侧" | 措辞绑定实际能力；Phase 0 核实 |
| 单题生成等待过长 | 带学节奏被打断 | 复用优先；等待期间继续讲解；实测后再优化 |
| 自动 QA 沉淀错误解释 | 错误被长期保留 | 标注 AI 来源、可修订、引用轻量比对；QA 不作为出题来源 |
| 检验项由模型提出质量不稳 | 进度口径不可信 | 用户可见可调整；主显示用分子分母；依据可展开 |
| 主会话调用工具过于频繁 | 成本与等待上升 | 纯讨论不读现场；观察调用数，必要时增加薄封装 |
| 支线与草稿状态丢失 | 体验崩塌 | 列入硬边界与重启测试 |
| 为"完整"重新长出平台 | 工期与复杂度失控 | 新增机制必须对应 Phase 0 差距清单或实测问题 |

---

## 10. Phase 0 需拍板的决策

1. 本次学习记录归属哪个上下文；
2. 主会话是否需要新的薄封装，还是现有工具已足够；
3. `panel.open` 是否能提供显示确认，以及措辞规则；
4. 原生草稿的保存位置与恢复路径；
5. 现有生成链路以"1 道题 + 小范围"运行时的实际等待和费用；
6. 检验项的展示与调整交互：以主会话对话调整为主，右侧是否提供直接编辑。

---

## 11. 结语

4.0 的价值是：**主会话围绕同一个可验证、可恢复的学习现场教学；右侧把教学动作变成真实学习对象；用户的真实作答反过来改变下一轮教学。**

实现这一点需要的是少数几条坚决执行的硬边界，加上一层很薄的操作适配，而不是四套平台。新学科主要更换资料与目标，新教法主要调整主会话指导，新展示优先复用富文本；只有涉及权限、记录真实性和数据安全时，系统才不让步。
