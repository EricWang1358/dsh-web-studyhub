# 生成任务双向通信

原生宿主具备 `spawn.prepareContinuable`、通信工具和生命周期接口时，每个生成阶段创建一个可继续通信的子会话。父代理补充要求通过 `job.message` 传递，子代理仅获得 `send_message` 工具，按指令只向直接父代理反馈。DSH 自身校验父子关系、处理消息归属及会话持久化。

`job.message {jobId?,message}` 接受最多 4,000 字符；每个任务最多 20 条。多个活跃任务时必须指定 ID。消息一律保留给后续模型阶段；只有原生接口返回接收凭证，才标记已送达当前子代理。缺少通信能力或投递失败时明确显示未送达。已完成批次不自动重写；如果最后阶段已经结束，需重新生成以应用新要求。

主对话的模型通过 Study 工具转发相关要求，不自动转发所有聊天内容。子代理可以发送简短进展或缺证据问题；主代理可以回复，但子代理不会无限等待用户。生成所需证据不足时仍返回错误，不能用通信绕过质量验收。任务完成不发布草稿。

阶段监听在保留子会话 ID 后、启动前安装，避免极快返回丢失结果。只接受对应子会话的 completed 输出；超时或失败时清理当前子会话，监听器和投递句柄总会释放。正常空闲由 DSH 持久化并释放运行实例，原生会话仍可查看、后续通信可由 DSH 冷恢复；生成流程不会把已结束阶段的新一轮输出自动当作草稿更新。

兼容旧宿主的一次性子代理和独立预览的直接模型调用，界面如实标记通信能力。自动测试验证启动前监听、消息凭证、父子投递、失败清理及补充要求跨阶段保留。尚未在真实 DSH 模型上运行端到端通信任务。
