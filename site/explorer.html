INK DESK · ARCHITECTURE StudyHub v4.6.1 · Node.js ≥22.19 · Cordis Runtime

把每道题锚回原页的
开放式学习架构

StudyHub 不是写死步骤的黑盒刷题模板，而是一套运行在 DSH 宿主内的模块化学习工作台：底层用声明式上下文边界、分片内容寻址存储与五阶段证据校验守住数据可靠；上层用可组合的技能、按需契约、动态数据围栏与可编辑课程「学法」，让学习者能和主对话一起自由定制每门课的学法。

1 + 6 + 1 工作台主包 + 6 个能力插件 + 1 个检索扩展包
7 · 19 7 个 DSH 工具 · 19 个 StudyRuntime 上下文（16 业务 + 3 纯数据）
5 阶段 规划 → 蓝图 → 写题硬绑定 → 六维独审 → 有界修补
1308 离线确定性测试文件（1112 快速 + 196 慢速 · 0 外网请求）
设计哲学 · 开放可组合而非死板模板

为什么学习者能和主对话一起「改学法」？

固定按钮管高频确定动作，开放探索交给主对话：技能、契约、围栏与课程学法全部作为一等数据暴露，既防提示词注入，又不把学习锁死在单一路径里。

02RELIABLE GENERATION PIPELINE

五阶段有界出题流水线与故障拦截演练

长资料先按 ≤ 60,000 字符分组、每批最多并行 4 组（每组 ≤ 5 题）。流水线把「找依据」「锁答案」「写题面」「独立审题」与「微调补缺」拆成五个职责隔离的阶段：能用确定性代码核对的绝不交给模型猜，重试次数严格封顶，仅统计调用次数与 Token 规则。

03 · AUTHOR source ↗

模型撰写自包含题干、提示与解析；若输出在尾部被截断，括号平衡扫描器（salvageAuthoredCards）直接提取已闭合的完整题目。随后代码按 targetId 用第 2 步锁定的答案、选项、评分点与引文强制覆盖作者输出，杜绝写题阶段篡改事实。

每批 1 次写题调用（并行度 concurrency = 4）· 仅当 0 题可恢复时重问 1 次 JSON · 绑定与自动修复 0 次模型调用

04 · REVIEW source ↗

先过本地规则门禁（拦截“根据课件/讲义”上下文依赖、提示泄底、空解析、填空占位符失配、正确项鹤立鸡群）；再交由不看写题推理过程的独立审阅提示词，从 6 个维度逐题打分，严格区分阻断缺陷（fail）与非阻断建议（suggest）。

本地确定性门禁 0 次调用 + 1 次独立审阅调用 · 协议缺失最多追加补问 REVIEW_REASKS = 2 次（保前缀缓存）

05 · PATCH source ↗

若题目证据扎实但仅因题干/提示/干扰项措辞被标 fail，执行 1 次冻结答案与引文的批量措辞改写（PATCH_FIELDS）并只复审改过的子集；若仍有数量缺口，最多携带前轮拒因摘要（priorRoundBrief）补跑 2 轮，证据不足时诚实报告实得题数，绝不死循环凑数。

仅措辞缺陷题做 1 次批量改写 + 1 次子集复审 · 缺口补齐上限 fillRounds = 2（可设 0..4，预留槽位 ≤ 3）
