## 4.7.2 — 2026-11-11

- **The practice page now tells you, once, where the help is.** After your first wrong answer a small note points at “Help me understand”; after you first mark “Something is wrong with it” it points at “Improve question”; and the first time an explanation stands under a question it points at “Turn into a prerequisite question”. Each note appears once, only after you did something, never during a mock exam or the feature tour, and closes with “Got it” or Esc without moving anything on the page. Settings › Guidance lists the three, shows whether you have seen them, and can bring each back or switch it off. Not verified: checked in a browser preview with made-up questions and no model at 1280 and 420 px, not with a real library, a real model or a first-time learner.
- **Help me understand, Generate a prerequisite question and Improve question now say where the result shows before they mention the Inbox.** The note under the form, the message after you submit, the tour and Find a feature all say the same thing: the explanation appears under the question in its Q&A, the new question goes into the same deck, the edit changes this card in place; the Inbox only tells you when it is done, and holds the one-step undo of an edit. Find a feature now also has an entry for “Generate a prerequisite question…”. Not verified: read in the English and Chinese interface with made-up data; no first-time learner has read the new sentences.
- **The tours name the three tools under a question.** The short tour’s practice step now says what “Help me understand”, “Improve question” and “Generate a prerequisite question…” (under “More”) are for; the full tour’s help step says where the explanation appears and where each of the three is. The short tour keeps its seven steps. Not verified: read in the tour with the sample course at 1280 and 420 px, not by a first-time learner.
- **The "Restart DSH to finish the upgrade" notice no longer traps you when the restart did not work.** If DSH was started again after an upgrade and the old version of StudyHub still runs (for example because another StudyHub profile on this computer took the upgrade, or the new files were not really put in place), the sidebar now says "Upgrade did not take effect", and its page and Settings › About & updates explain the possible causes and offer to reinstall the new version or follow the manual steps. When a restart really is still to come, hovering the notice says what restarting means, and its page adds a line (quit DSH from the tray icon first) for the case where you restarted and still see it. Not verified: only checked with tests and a preview page with made-up data, not in a real DSH desktop app; the cause on the reporting learner's machine is not known; a DSH that was closed to the tray and opened again is not detected (the old process is still the one running), it is only explained.
- **Stubborn-question actions in the wrong book now let you agree or set up a model on the spot, and no longer block a retry within ten minutes.** Pressing “Too hard: add a prerequisite card” before background preparation is on now opens an inline confirmation (“Agree and generate”) that turns it on and starts writing the prerequisite card for “Personalised” in one step; when no AI model is set up, both “Too hard: add a prerequisite card” and “Report a problem: fix it in the background” show an inline “Open model settings” button. If you first pressed either button before turning background preparation on or setting up a model, pressing again within ten minutes now starts the card or repair instead of refusing it as duplicate feedback, while a repeat press after the work has started still avoids running twice. The background-repair notice also says up front that it edits this card directly before mentioning the Inbox reminder and one-step undo. Not verified: tested with automated service and interface tests; not clicked through end to end against a live model provider in the desktop app.
- **Updating or repairing the search extension now keeps its restart notice across page switches, names the desktop tray icon, and stops looping when a reset did not help.** On DSH desktop, installing, updating, repairing or saving the model download address for the search extension now says to quit DSH desktop fully (including the tray icon) and reopen it instead of just closing the window. After an extension update that needs a restart, switching to another page or reopening the window from the tray keeps the "updated, restart to take effect" notice until DSH actually restarts into the new version, and if DSH restarted without picking up the updated extension it says so and offers "Reinstall the search extension"; a first-time install no longer shows the update banner alongside the startup notice. On the "search service did not start" card, "Copy diagnostic information" and "Send to the main chat" stay visible after clicking "Repair", and if DSH has already restarted after an index reset and the service still does not start, the card stops asking you to click "Repair" again and points directly to those troubleshooting actions. Not verified: in a real DSH desktop window with the system tray icon or a real search extension upgrade; checked with automated unit and server-rendered UI tests only.
- **Opening two StudyHub windows or two libraries on the same computer no longer turns a running local install into "interrupted" or leaks search warnings across libraries.** While one StudyHub window is installing MinerU, Marker, local transcription or the system-audio component, a second window sharing the same DSH home now shows the install in progress with a note that another window is running it, and refuses a second install into the same folder instead of claiming the last install was interrupted; only an install whose process is actually gone is marked interrupted. A brand-new or unindexed library no longer shows "the index was damaged and has been reset" because another library reset the shared search index earlier, and a custom search tool chosen in one DSH configuration no longer triggers a "cannot be found" warning in another library whose DSH does not have that tool, while keeping the choice saved for the original library. Not verified: across two real DSH desktop windows or real MinerU and Marker installs; checked with multi-instance unit tests and real child processes only.
- **When “Improve question” or “Turn into a prerequisite question” makes no change or cannot link the question, the reason stays on the card and in the Inbox.** You can read why the card was kept as-is or saved in the deck without a prerequisite link, edit your request and resubmit, or check the result later in the Inbox. Not verified: real remote model wording across different providers.
- **Practice AI tools check whether a model is ready before you type, and failed requests keep what you wrote.** When no model or API key is configured, opening “Help me understand”, “Improve question”, “Turn into a prerequisite question”, or guided steps shows a model setup prompt right away without spending first-use tips, “Show English” turns back off instead of showing an error on every card, and a rejected key lets you recover or resubmit your text after updating settings. Not verified: live API key rotation against a third-party provider.
- **Opening cited materials or original figure pages from a practice question keeps a “Back to question” button, and PDF citations can open the original page directly.** Collapsed citation rows now badge self-cited and unverified AI-drafted sources upfront, the source reader offers “Original page” beside highlighted PDF quotes, and long Q&A threads include an “Ask a follow-up” button at the bottom. Not verified: large scanned PDFs over 200 pages.
- **First-use tips on the practice page wait until you have had a moment to read them and stay out of the way of menus and feedback tags.** Advancing right away no longer uses up a tip before 1.5 seconds, pressing Esc closes open menus or sheets before dismissing a tip, pressing G or B pauses auto-advance so you can pick feedback tags, and marking “Too hard” guides you to “Help me understand” instead of “Improve question”. Not verified: touch-only mobile browsers.
- **“Help me understand” answers now appear directly below an unanswered question without revealing the answer first.** Inbox reminders for new explanations stay unread until the Q&A is actually shown on screen, and opening an “Explanation ready” item in the Inbox expands the Q&A even before you submit an answer. Not verified: live multi-window sync with an external chat session.
- **Unpublished drafts now show as the next step on the library home when no due reviews or open practice rounds are waiting.** After generating a new draft or importing a JSON deck, the “Next step” card, the today card, and the “Drafts to publish” list surface the waiting draft directly instead of saying everything for today is finished or nothing is ready to study, and the draft list opens on its own when today’s round is empty or already done. Not verified: live visual layout inside the desktop Electron shell across custom OS font-scaling levels.
- **Study notes and case exam reports no longer stay stuck when AI drafting or background grading is interrupted.** In Study Notes, you can now click "Stop drafting" while AI is writing a draft, and reopening a note after restarting DSH marks an unfinished draft as interrupted so you can edit, save, or start drafting again right away. In Case Paper exam reports, if background grading fails or did not finish before a restart, the spinner stops, the report shows what happened with a "Submit for grading again" button, and retrying sends your saved answers for the remaining ungraded questions instead of blank answers. Not verified: checked with automated service and UI tests using simulated models and restarts, not clicked through in a live DSH desktop session with a real model provider.
- **Background generation, translation, note drafting, case grading and audio transcription now state where the result lands before mentioning the Inbox.** Live-class question generation now points to “Library › Drafts to publish” and “Jobs” instead of the Inbox, page and chapter translations reveal newly translated paragraphs even when “Hide translations” is selected, and the empty Inbox and unread badge describe completion reminders rather than stored results. Not verified: checked in English and Chinese preview builds with seeded data rather than a full end-to-end live-class or audio transcription session.

Not checked before this release: `main` did not run for a day of real use on the experience channel, and nothing here was tried with a real library and a real model in a real DSH window. ## 4.7.1 — 2026-11-10

- **Final-week points say whether they will still hold on the exam day, and Today names the chapters that will slip.** With an exam date ahead, each point you have answered questions on in the review book's Final week and Study plan shows one word, "Holds on exam day", "Slips by exam day" or "Already shaky", projected as if you did no further review; hover it for what the three mean. No percentage is shown. When the course has a study plan and a chapter will slip, Today's focus under Tasks › Today says so in one sentence ("At this pace, by the exam day these chapters will slip: 3, 7") with a button that starts one round of those chapters' questions most likely to be forgotten, at most your round size (asked in practice's usual order, not by how likely they are to be forgotten). Nothing changes for a course without an exam date, after the exam date or on the exam day itself. Not verified: on a real library; whether the bands match how you actually do on the exam (they follow the review schedule's own forgetting curve, not proven for questions answered only a few times); the Today sentence only appears for the course whose study plan Today already shows.
- **A big library opens faster: Sources, Mistakes & weak points and a long draft draw their first rows at once, and more as you scroll.** A day with hundreds of materials, a group with hundreds of mistakes or a draft of more than 80 questions now shows the first 120 rows (80 questions in a draft), then another batch as you scroll toward the end (or Tab into the last rows); the counts, "Select this scope", the filters and "Practise this group" still cover every row. Anything that takes you to a row shows that row first and goes there in one scroll: a material you just imported, a feature "Find a feature" points at, a question you add to a draft, "View details" on a draft. Browser find-in-page cannot find a row that is not shown yet. Not verified: a real library, a real DSH window, the page in Safari or Firefox; measured only on a made-up library in headless Chromium. A row that sits right under the end of a long list that is still being drawn can be pushed down by the next batch after you are taken to it.
- **Saving an exam date no longer brings back, for today, questions you just answered.** Exam alignment now never moves a question to a day before the day after you last answered it, and spreads the rest over the days left, so a deck you finished today is not due again today. Not verified: a real library across a day change and a daylight-saving change; the browser tests run only on one machine.
- **When a local tool fails, the main chat can now repair it, and the failed card tells you how to let it.** On the failed card of MinerU, Marker, local transcription, the system-audio component or the search extension, "Send to the main chat" now asks the main chat to find the real cause (the card's sentence is only a guess) and then repair this computer step by step: it says what a step changes before doing it, asks you before ending a process, deleting files or changing permissions, and checks the result only by reading (it never starts or stops the tool's service, changes system settings, or deletes the tool's files). What it may do depends on the failure (folder permissions, a busy port, the VC++ runtime, a location that cannot be written, a broken install, the network); folder permissions are only touched inside the tool's own folders in its install location, and it ends by telling you which button to press back in StudyHub (the card's check first, its fix only if the error is still there). Installing and uninstalling are still your buttons. For failures whose repair changes files or permissions, a sentence under the buttons says to choose the full-permission option in the permission menu at the bottom-left of the main chat's input box before sending and to switch back afterwards; a hover explains why, and that full permission lets that chat change any file on this computer. Find it in the finder as "Let the main chat repair a local tool". Not verified: a real repair by a real main chat in DSH; the English name of the permission option in DSH's English interface; what the experimental auto-review option allows outside the workspace; whether a plugin can read the chat's current permission (no supported way was found, so the sentence always shows).
- **Other ways on when a MinerU fix does not help: a "⋯" menu beside it.** When the MinerU card shows an error (and, in Settings, when an install is paused), a "⋯" button next to the one fix opens: "Switch to the basic tier" (only when the tier in hand is not basic), "Uninstall and reinstall" (one confirmation, then it uninstalls and installs again in the same place and tier, downloading everything again, so it needs as much free space as a new install; if files StudyHub did not create are still in that folder, it goes into a new "StudyHub-MinerU" folder inside it; if the uninstall fails, the dialog says why and nothing is started), "Install in another location…" (unless the fix already is a change of location) and "View the install log". After the same fix has failed twice, one sentence points to the menu. The feature finder now has "Uninstall MinerU" and "Change the MinerU tier". Not verified: no real MinerU install, uninstall or reinstall was run (tested with fake answers, in a real browser for the menu and "Uninstall and reinstall").
- **MinerU's settings folder is repaired in place instead of sending you to another location.** When MinerU cannot read a file in its settings folder, or finds it not private enough, the card now says which file and that the install location is fine, and its one button is "Repair permissions" during an install (it continues from the step where it stopped, downloading nothing again) or "Repair permissions and restart" after it. A local service refused for its folder's permissions also offers "Repair permissions and restart" first, with "Choose another location" as a quiet second button. Every install step and every service start now gives the files already in that folder back their usual permissions (on Windows: inherited from the folder, which only you, the system and administrators can use; elsewhere: the folder 0700, its files 0600), at most 2,000 entries per pass; on Windows only the entries that need it are changed, and links and files with more than one name are left alone; when such a file had the wrong permissions, the card says how many were left alone and that the repair is not complete. This is done only in the settings folder of the MinerU StudyHub installed: for a MinerU you installed yourself, StudyHub changes no permissions, says which file of that MinerU's own settings folder it could not read, and offers "Restart the service" and "Send to the main chat"; the main chat is then asked to have you press "Restart the service" first, and may change permissions only in that MinerU's own settings folder, after asking you. If a repair did not help, the card says so and points to "Send to the main chat". Not verified: no real MinerU install was run (the permission repair was tested on real Windows files with broken access lists in a temporary folder, and the rest with a fake MinerU); which files MinerU checks, and what wrote the empty access lists seen on a learner's computer, were not confirmed against MinerU's source.
- **The MinerU tier you pick is the tier that gets installed, also for an install that did not finish.** Before, an unfinished install kept asking for its old tier even after you picked another one under More. Now a tier picked there wins; otherwise a fix continues the unfinished install's tier, then the installed tier, then the plan's. When you pick another tier for an unfinished install, its one button becomes "Install the basic tier instead" (or standard), with one sentence saying what is kept: the program and Python already downloaded when those steps finished, only the models change. Not verified: no real MinerU install was run (tested with a fake MinerU: an unfinished standard install continued as basic in the same folder and downloaded only the basic models); the old tier's models stay on disk until you uninstall.
- **The task card now says "at most" for what is left before the run has a pace of its own.** For a question run, the card used the middle of the estimate made before the run; it now uses the upper end of that range and says so ("Up to about 3.3M tok to go (upper estimate from before the run)", and "Used 1.1M + up to about 3.3M to go ≈ up to about 4.4M tok in all"). Once the run has made enough questions the number comes from its own progress, as before; only when it is heading more than a quarter above that upper end does "Before the run: up to …" appear beside it. The home row and the draft page say the same number as the card. The create page still shows the whole range. Not verified: with a real model; the upper end is still too low for some runs (one 197-question run was heading for about 10M tokens against a middle of 4.5M), so the number can still be exceeded.
- **The task page now says that the model and the reasoning level change the usage.** Under Live controls, for a question run that lets you change the model or a reasoning level, one line says "Model and reasoning level change the usage a lot."; hover it for the detail: the estimate is made once when the task starts, from typical usage, and is not scaled by the level; a higher level or a model that thinks more writes more tokens, so the real usage can end above the estimate, even above its upper end; a change made here applies from the next call and does not redo the estimate. Tasks without a model or a level to change, and ended tasks, show nothing new. Not verified: on a real run; the wording follows the code (the estimate reads no reasoning level), not a measurement of how much a level adds.

Not checked before this release: `main` did not run for a day of real use on the experience channel, and nothing here was tried with a real library and a real model. A single Latin letter or digit on its own is still too short and gets a clear message. Not verified: the notes page in a real browser.
- **A right answer given after opening the hint now comes back sooner.** For choice and fill-in-the-blank questions, a right answer after you used the hint is recorded as "Correct with effort" instead of the plain right answer, and the line under the answer says so. A right answer without the hint, and a wrong answer, are scheduled as before. Not verified: not tried in the live app with a real learner's history; only the server grade, the next interval and the line text were checked in tests.
- **A page that fails to draw no longer takes the sidebar with it, and you can copy a diagnostic text for a bug report.** The failed page shows a notice with Retry and Copy diagnostic information, the sidebar and top bar stay, and another page opens normally. The same button is in Settings › About & updates, and "See what will be copied" shows the text before it goes to the clipboard. The text holds only the StudyHub version, interface language, page, the error type, the program's own short error phrase (any other error text is replaced by its length), the names of the functions where it broke, job kinds and statuses, the number of sources, decks and questions, and whether experimental features are on; the DSH version is left for you to fill in. API-style keys are now also removed from the reasons shown for failed conversions. Not verified: in a real DSH window with a real page failure; the clipboard in the DSH desktop app; the Board, which is drawn outside the page boundary and does not get the new notice yet.

It is only a heads-up: both questions stay, and saving and publishing work as before; while a background job is still changing the draft it is not checked again, only once the job is done. A choice question and a fill-in-the-blank on the same point are not flagged. Not verified: in the real DSH panel and on the owner's own library (checked with tests and synthetic stems only); a draft with no course is compared with every deck that has no course, and a chapter draft only with that chapter (and the chapters inside it), not with the other chapters of its course; 500 x 3 000 synthetic English stems of a very small vocabulary take 0.25-0.6 s on a developer machine and close to 1 s when the machine is busy; how often the 0.72 threshold flags questions a learner would call different.
- **The copy buttons for the import prompt, the diagram file and a translated passage now copy the text.** Before, clicking them put a few lines of program code on the clipboard instead of the prompt, the diagram or the translation. Not verified: clicking each button in a real DSH window and pasting the result.
- **The whole review book can be saved as one page that opens offline and prints cleanly.** In More › Export… the new "Whole book (.html)" button saves the book (cover, contents, lookup pages, every chapter) as a single file with no Pandoc: footnotes are numbered and stand at the end of their chapter, each chapter starts a new page on paper, formulas are drawn, and the button says about how many A4 pages it is. Tick "Leave quotes from the materials out of the book page" before sharing it and the words quoted from your materials (footnotes and the concepts of answer cards) are left out while the source (its title) stays. Not verified: a source title that itself holds a closing quotation mark is cut short too (it leaves less, never more of the quote); printed to paper or PDF only through Chromium's print emulation; a book of hundreds of pages was not tried, and the page estimate was not compared with a real print.

It clears once the latest 5 attempts are all right, and answering right never makes a question stubborn. Open its row for four ways out that already existed elsewhere: fix it in the background, add a prerequisite card, send it to the main chat (about this one question), or suspend it (with an Undo). A collapsed row gains no button; "Stubborn" above the list shows only these questions; a finished round that held some says so in one line with a link that opens the wrong book on exactly those questions; and the two numbers can be changed in Settings › Practice. Not verified: not tried in the live app with a real library or a real model; the mark, the filter, the result line, the settings, the hand-off text and the finder entries were checked in server-rendered tests, and the notes after each action were checked against the service with a fake model. - **Evidence before questions.** Select valuable knowledge points with passages that can be located in the material, build supported answers, options and scoring requirements separately, then write stems and scenarios and review them independently. Corrections retain verified knowledge points and answers even when the next reply omits them; invalid targets cannot occupy slots needed by corrected targets. Citation, structure and independent-review checks remain enforced. First-batch acceptance with real models has not been measured.
- **Save useful batches sooner and customise generation.** Reviewed batches reach the draft promptly. Question defaults exposes batch size, concurrency, time limit, and default kind, language, difficulty, count and additional instructions. Continuations retain actual job parameters. Settings, scheduling and estimates share limits, and polling wakeups are coalesced.
- **Settings no longer overwrite one another.** Saving review intervals preserves newer generation preferences; refreshes update untouched defaults while keeping edits. Saving after a course merge retains merged exam settings, focus topics and guidance. Case creation follows the saved language, supports bilingual output and preserves manual input. Course settings and case exams share timing limits, so accepted pace and reading time no longer revert when an exam starts.
- **Consistent practice and materials.** Repairs preserve the question snapshots learners saw and answered. Mastery, scheduling, material identity and retained history stay consistent. Edited questions no longer display stale English. Source selection, notices and case creation work better on narrow screens and at enlarged display sizes while retaining the existing application design.
- **Complete import and settings contracts.** Jev custom endpoints and models can be saved with URL validation and secret masking intact. The chat audio tool declares uploads, file lists and glossary terms. Preflight shows the actual chunk duration. Paused usage recording with no data no longer shows an endlessly waiting report, and the reader's P shortcut is counted where it works. Stale settings paths, button names and feature descriptions are corrected.
- **Finish the documentation and introduction site.** English and Chinese guides match current features. Package contents include linked documentation; private historical paths and unverifiable promises are removed, and the introduction uses the StudyHub name. Artifacts include the full plugin, six capability plugins, search extension, bilingual setup assistants and checksums.
- **Isolated verification.** Default tests use temporary libraries and an independent configuration directory with external requests blocked. Browser acceptance uses fixtures and fake models. Passing checks does not guarantee a real provider's speed or acceptance rate.

## 2.5.8 — 2026-10-03

- **A big selection no longer loses most of its questions to "the quoted text was not found".** Asking for 25 questions over 36 pages of a converted book kept only 4: the check that each question quotes its source only forgave spaces, so real quotes were refused when they differed by a hyphenated line end, markdown or table markup, curly quotes and dashes, an elided "…", a quote running over a page break, or a page id the model garbled; and one bad quote in the plan failed a whole group. Now the comparison forgives those harmless differences (an invented quote, a changed number or a different order is still refused), a citation points at the page that really holds its quote, a big selection is cut into groups of whole consecutive pages (at most 60,000 characters and 10 questions each, each part checked against only its own pages), the plan keeps the questions it could ground, and a card whose quote still cannot be found gets one repair call that is told the exact quotes and the allowed pages. The draft, the job card and the home card now say how many parts passed and why the others did not ("5 个部分的引用在资料里找不到"), and 继续补齐 tops it up.
- **The step path for a big book is a better starting point.** A step is named from its usable chapter names (a one-letter index heading or a cut-off word is no name; with none, the title is the page range, "Pages 69–137"). Index, colophon, about the author, acknowledgments, contents, copyright, dedication, preface and appendix steps are optional and unchecked by default, with a tag that says so. Each step shows its pages, is cut into balanced parts of at most 20 pages and 15 suggested questions, and the brief for the chat tells the AI the page numbers, how to get page ids for a custom range, to keep each generate call small, and to check a job with the new read-only `job.status` instead of promising to report later.
- **“帮我想想” says why it failed.** The line "generation did not finish" now says whether no model is set (with a link to the model settings), the call failed (with its short error), or the answer was not in a form StudyHub could use (with the answer to look at); it reads more reply shapes, asks once more with the exact format, and has a "Try again" button. The step path uses the same line.
- **Jev can be configured for OpenCode Go.** The Jev provider list has "OpenCode Go · Jev" (opencode.ai/zen/go/v1/systemone, key from OPENCODE_GO_API_KEY_2, worded as Go, not Zen). Not verified: the route exists but OpenCode's public Go model list names no Jev model, so whether a Go key is accepted is unknown; the custom endpoint remains the way out.
- **The large-book advice builds the index for the book's own course.** It used to preselect whichever course the page was focused on.

## 2.5.4 — 2026-10-03

- **No more questions that ask what the material says.** Questions such as "What does the material use to tell 4xx from 5xx?" test memory of a document's wording, not the concept or how to act in a situation. Generation now forbids them at every step: the planning, writing and independent review prompts all carry an explicit rule (ask about the concept itself, or put the learner in a concrete situation with the facts needed), and a deterministic check rejects stems such as "资料说…", "文中提到…", "根据资料…", "资料用什么…" and "what does the text say…", asking for a rewrite as a concept or scenario question.
- **Fixing a bad question no longer needs you to know what to say.** On the review page, a question that asks what the source says is called out with a one-click **Rewrite as a concept or scenario question**. **Improve question** offers the usual problems as choices (don't ask what the source says, inaccurate answer, unclear stem, too easy) and **Let the assistant check and fix it**. A 👎 on such a stem picks the reason "Only asks what the source says" by itself, there is a seventh reason (key 7) for it, and even a bare 👎 or "this question has a problem" tells the rewrite what is wrong.
