## 2.6.2 — 2026-10-06

- **Questions now cover the whole material, and you can see it.** A long material (a transcript of several recordings, a book) used to get about as many knowledge points as questions you asked for, so most of it was never asked about, and the only trace was a dashed circle. Now every material is split into sections (a recording's parts, PDF pages or chapters, headings), and each section is shown as covered, planned but not produced (with the real reason) or never planned: on the 资料 row, in the reader's outline (with a filter for what is not covered), on the draft page (with a bar per recording and the list of uncovered sections, each opening the reader at it), in the Jobs console and in the 做这几页的题 panel. The reader outline lists recordings and their parts only, no longer a 英文原句 / 中文对照 entry under every part.
- **Coverage strength instead of a question count.** 创建题组 asks for 精简 / 标准 / 完整 and says before running what it means (about how many questions, how many sections, how many rounds, the estimated tokens and calls). Longer and more important sections get more questions: one cheap call per ~20 sections rates their importance with a reason you can read on the draft page. The server enforces it: a planning call sees only its assigned sections and each section's quota, and what comes back is checked against them. The 30-question limit is gone for the total (a custom number up to 500; each round is still at most 30 questions); only the original language of a bilingual transcript counts as material.
- **Long runs you can pause.** A run executes its rounds one after another on the same draft; pause between rounds, continue, stop and keep what you have, or let it run to the end (自动补到完整, on by default for 标准 and 完整). A run interrupted by a restart comes back as "Interrupted" with Continue from the next round. The time limit applies to each round, not to the whole run, and you can set a spending cap. The Jobs console shows 「第 3/12 轮 · 覆盖 31% · 已用 … · 预计还要 …」 and the rounds.
- **One action for what is missing.** 「为没覆盖的部分补题」 replaces 继续补齐 N 题 and 补 N 题 (draft page, home, Jobs console, also for archived tasks): it targets exactly the uncovered sections, reuses what failed parts had already planned, keeps approved questions and never changes the requested count; its estimate is shown before it starts.
- **No batch is dropped silently.** A malformed or cut-off review reply is asked again (a cut-off one only for the checks that are missing) instead of dropping the whole batch; a part that still failed keeps its written questions and is retried in the fill rounds; every "why no questions" reads the same everywhere and is the real reason, not a raw English error.
- **Questions count once per document.** The 资料 row and the reader count the same questions: all versions of a document, the same recording imported separately, and the single recordings of a merged one ("含旧版本 / 同一录音的其他资料 / 分录音资料"). A material whose questions are only in drafts says 「还没发布 · 草稿里有 N 题」. Fixed a bug that could count another material's questions for a recording.
- **Jobs console.** Selecting finished tasks, archiving and deleting in bulk work as designed (the tooltip is whole, the selected rows are readable in every accent, Esc and keyboard work); a task interrupted by a restart says 已中断 instead of 失败; the header no longer squeezes the task name.
- **Install from GitHub works.** The DSH plugin market installs from the GitHub repository, which has no built interface; it is now built on install. The repository is described and tagged `dsh-plugin` so it can be found there. The recommended install is still the release package.
- **Update check every 6 hours** while the plugin changes quickly (it was 12).

## 2.6.1 — 2026-10-05

A fix release for 2.6.0.

- **"Suggest a focus" works on more models.** A model that lists a "minimal" reasoning level but whose provider only accepts off/low/medium/high/… used to fail with `Invalid option … reasoning_effort`. When a provider refuses the level, StudyHub now asks again once with the nearest level it accepts, and remembers it for that model.
- **The Jobs console fills the window again.** With the usage line shown (audio imports), the panels were pushed into a short strip at the bottom with a large empty block above them.
- **Failed calls say why, and what happens next.** Each failed line in the log now carries the reason and whether the step was retried (and how that went). Only a rate limit is retried by itself; for anything else the line says so and how to go on: top up the missing questions from the draft, or Continue an audio import.
- **The parallel timeline reads as a story.** Every call is a fresh sub-agent, so one lane per pool slot meant nothing. Lanes are now one per file (audio) or per part (question runs), left to right in the order the work happened; a rate-limit wait sits in the lane it held up. A reused transcript is drawn as its own blue bar marked "reused", and the call says why it was reused: same audio content and same transcription model, mode and languages.
- **Live output.** A finished call can be opened again: the last ~8 KB are kept in memory and a sub-agent's full final reply is read from its DSH session. JSON is shown indented, also while it streams, and a model that is still thinking says so instead of "waiting for output".
- **Question-run parts open their sources.** Each part records the pages it covers; View in material opens the reader there, and a part that kept fewer questions than asked says why.
- **Material rows no longer say "no questions yet" when a draft has them.** They say "Not published yet · N questions in drafts" and offer to open the draft.
- **Page footnotes are footnotes.** A MinerU footnote that showed up as literal `<small><span …>` text in the reader is now a small muted footnote line, in already imported books too, with no new raw-HTML path.
- **View original page works on scanned books.** Pages of scanned books (image encodings such as CCITT, JBIG2 and JPX) drew blank in the preview because the browser-side PDF engine lacked the decoders the server side already had; small text PDFs were never affected, so it looked like a size problem. The decoders and Chinese character maps now load on demand, only when a page needs them (about 1.4 MB, nothing at reader start). If a page's image still cannot be drawn, the preview says so and offers View original PDF instead of showing a blank page.
- **Archive and batch delete in the Jobs console.** "Got it" now archives: the task leaves the list but stays as a read-only record (kept across restarts, newest 200 / 90 days). Finished tasks can be selected for Archive or Delete (with a confirmation that says what is and is not removed); an Archived filter lists them and they can be restored. Old finished jobs pruned beyond 100 are archived first instead of disappearing.

## 2.6.0 — 2026-10-05

- **A new Jobs console.** A Jobs entry in the sidebar gathers every background job (audio transcription, question generation and top-ups, PDF conversion, translation, tailored practice and more) on one page: the job list on the left, the selected job's full detail on the right — staged progress, a parallel timeline (one lane per slot, one bar per model call, rate-limit waits marked), calls in flight, a per-kind section (files, source parts, conversion detail) and a log. The page stays one screen tall and each list scrolls in its own panel; Full screen hides the list.
- **Instant controls.** Change concurrency, reasoning level and automatic back-off, or pause and resume, right from the console; changes apply from the next call and never interrupt one already running. Only actions the job really supports are offered; the others say why.
- **See what a sub-agent is doing.** Live output shows the last ~8 KB of a running proofreading or generation sub-agent (read only while the panel is open, never written to disk), with Open the full session in DSH when the host can open it. Transcription services that do not stream say so.
- **Compact job cards.** The audio page, home and PDF conversion keep one line per job — progress, what it is doing now, one primary button — aligned across cards; the detail lives in the console.
- **Tailored practice, one row per day.** The console shows each day's tailored practice: batches, tokens, questions generated and passed, how many were actually practised and how well, with pause-today and daily limits — so you can see whether it pays off.
- **Top-ups go back to the deck, with a higher pass rate.** Add questions from uncovered sources now fills the current deck's draft with its own settings instead of creating a new deck. Review findings are split into must-fix and suggestions; fixable problems (an answer-revealing hint, a weak distractor) are repaired before a card is dropped, and quote formatting is checked by the program. Short decks get bounded automatic top-up rounds that carry the rejection reasons, and failures explain the real cause. Writing and repair default to a lower reasoning level, usage is shown per stage and the estimate is calibrated on this library's history; default concurrency is higher with automatic slow-down on rate limits. Deck titles no longer carry "(N questions)", and a deck being topped up shows one card.
- **Faster, clearer audio transcription.** Proofreading runs as a sliding pool — a finished window is replaced at once — and the next file transcribes while the previous one is proofread. Concurrency is adjustable and backs off on rate limits. Every request is metered; Today follows your local day (the Gemini free quota keeps the Pacific day and says when it resets), and the usage console refreshes in milliseconds instead of seconds. Reasoning choices use the current model's own level names and say which level was used when the model lacks the one you picked.
- **Late data no longer shoves the page.** Source pickers, index badges, 为你推荐 recommendations and usage estimates reserve their space; recommendations no longer change the practice mode you already saw; the sidebar no longer flashes open on narrow reloads. Material names never show the host's attachment path, and derived materials say what they came from.
- **Reader.** The selection 译 chip stays next to the selection at any interface zoom, and transcript dividers render as a quiet rule.
- **A more consistent interface.** One paper card, half-step spacing and radius scales, motion with transform and opacity only, and shared buttons, badges, checkboxes, notices and progress bars.
- **Release packages.** Download links and bilingual setup guides now point to 2.6.0. The release includes the complete plugin, six capability plugins, retrieval extension, two setup guides and SHA-256 checksums.

## 2.5.15 — 2026-10-05

2.5.14 was withdrawn after a few problems were found in use. This release contains everything in 2.5.14 and fixes them.

- **Continue learning no longer loops.** After a round over one or two questions, Continue learning picks one destination in order: back to the original question after a prerequisite round (its unanswered state kept); the same scope while it has questions left; the next unfinished action in today's plan; otherwise the normal learning path. The button names its destination and autopilot follows it; repeating the scope is only Practise this scope again.

- **👎 now feeds 修题.** Rewrite tags (vague stem, weak options, wrong answer, unclear explanation, only asks what the source says) open the same fix box below with the issues prefilled, and the background assistant shows its progress; nothing is rewritten silently any more. Too easy and too hard only shape tailored practice; a bare 👎 is recorded only.
- **A lighter, foldable daily plan.** What to do today folds to one line with the minutes left and the next step, and remembers whether it is open. The home keeps one filled primary button, and the three tool links are one Adjust menu. When AI planning fails, the plan says why (quota, rate limit, key, timeout, network or an unusable answer) and offers Open model settings or Try again.
- **Full text in the inbox.** Hovering or focusing a message shows a card beside it with the full deck, question and reply; the list itself does not change.
- **Notices no longer cover buttons.** Page notices rise from the bottom instead of covering the actions at the top right of every page, and the notes editor reports unavailable browser storage once instead of on every keystroke.
- **A consistent interface.** Every page uses the same header and panels; buttons, icons, switches, tabs, progress bars and notices share one set of components; font sizes, weights, corners, layers and colours use shared design tokens, so a few texts change size slightly. The three exam formats share one start, timing, submit and resume flow, and timers read like "0:12"; audio import is split into smaller parts and its upload honours the host's chunk size.
- **Sturdier styles.** The former 4,500-line stylesheet is split into tokens, base, shell and feature sheets; every sheet sits in an ordered cascade layer instead of fighting with `!important`; unused rules are gone and guard checks stop them coming back.

## 2.5.13 — 2026-10-04

- **More questions survive the first pass.** Text defects are now fixed without a model call: missing hints, misconceptions, topics or explanations, hints that give the answer away, a wrong question kind, and formulas without their delimiters, including those in the bound answers and options. Questions flagged only for wording are reworded once inside the run in one batched call per part, then reviewed again; answers, options and citations never change. Each group plans a few reserve knowledge points (at most three) and uses them when a part comes up short, instead of rerunning the whole pipeline. A run where every question passes makes the same model calls as before. The real-model first-pass rate has not been measured yet.
- **Formula notation: automatic, plain text or LaTeX.** More options in the generate form now has a Formula notation choice. Automatic picks LaTeX for maths and chemistry material and plain text otherwise. LaTeX writes formulas as `$…$` and chemistry as `$\ce{…}$` (H₂SO₄, SO₄²⁻, 5√2 render properly, also in options). Plain text writes Unicode (H₂SO₄, H⁺, x², 5√2). The choice is kept on the draft for supplementation and repair. Ambiguous text such as "SO42−" is not guessed at; it goes back to the model. Questions generated earlier are not rewritten.
- **Why a question was dropped.** "Incomplete question format" is split into its real causes: formula format, a stem that asks what the source says, missing fields, option structure and an unmatched knowledge point. The dropped-question and failure lists no longer show empty rows.
- **Results reach the chat that asked.** A generation started from the main chat now reports its final result to that chat once, after every batch, the review and the final draft save are done. Success, failure and cancellation all report; UI-started jobs and intermediate saves do not wake the chat.
- **Archive before deleting materials.** A source must be archived before it can be permanently deleted from the archive, with a second confirmation. Archived sources can be restored and keep question references and history. Deletion is refused while any page is still used by a deck, draft, study record or generation job.
- **Tidier deck maintenance and extension updates.** The Manage deck page has a clearer header, one organise panel (deck order, merge, split by topic with a selection counter) and compact question rows. Updating the search extension keeps its result on screen, including whether DSH needs a restart, and Check for updates also rereads the extension status.
- **Release packages.** Download links and bilingual setup guides now point to 2.5.13. The release includes the complete plugin, six capability plugins, retrieval extension, two setup guides and SHA-256 checksums.

## 2.5.8 — 2026-10-03

- **A big selection no longer loses most of its questions to "the quoted text was not found".** Asking for 25 questions over 36 pages of a converted book kept only 4: the check that each question quotes its source only forgave spaces, so real quotes were refused when they differed by a hyphenated line end, markdown or table markup, curly quotes and dashes, an elided "…", a quote running over a page break, or a page id the model garbled; and one bad quote in the plan failed a whole group. Now the comparison forgives those harmless differences (an invented quote, a changed number or a different order is still refused), a citation points at the page that really holds its quote, a big selection is cut into groups of whole consecutive pages (at most 60,000 characters and 10 questions each, each part checked against only its own pages), the plan keeps the questions it could ground, and a card whose quote still cannot be found gets one repair call that is told the exact quotes and the allowed pages. The draft, the job card and the home card now say how many parts passed and why the others did not ("5 个部分的引用在资料里找不到"), and 继续补齐 tops it up.
- **The step path for a big book is a better starting point.** A step is named from its usable chapter names (a one-letter index heading or a cut-off word is no name; with none, the title is the page range, "Pages 69–137"). Index, colophon, about the author, acknowledgments, contents, copyright, dedication, preface and appendix steps are optional and unchecked by default, with a tag that says so. Each step shows its pages, is cut into balanced parts of at most 20 pages and 15 suggested questions, and the brief for the chat tells the AI the page numbers, how to get page ids for a custom range, to keep each generate call small, and to check a job with the new read-only `job.status` instead of promising to report later.
- **“帮我想想” says why it failed.** The line "generation did not finish" now says whether no model is set (with a link to the model settings), the call failed (with its short error), or the answer was not in a form StudyHub could use (with the answer to look at); it reads more reply shapes, asks once more with the exact format, and has a "Try again" button. - Application errors, background progress, provider wrappers and task notifications follow each request’s interface language. Concurrent English/Chinese requests remain isolated; original sources, questions, notes and provider evidence are preserved.
- First-time users follow the browser’s preferred language; an explicit existing choice takes priority. New generation requests default to the interface language unless a content language is configured.
- English documentation and separate English/Chinese browser setup guides accompany the complete package and six standalone components. Existing web users continue installing only plugins through DSH’s plugin manager.

## 2.0.2 — 2026-10-01

- Added desktop/web setup guidance, official Windows and Apple silicon installers, and Linux/browser-only startup.
- Complete packages declare independently switchable workbench, runtime, materials, bank, learning, generation and audio components. Disabled capabilities stay disabled and saved data remains.
- Clarified model provider setup, eligible API-key Coding Plans, and the distinction between subscriptions and separately billed APIs.

## 2.0.1 — 2026-10-01

- Clarified audio task windows, timing and completed history; each child agent has one entry. This fixed display, without changing cross-recording queuing or fixing the reported host-level lack of overlapping child-agent execution.
- Isolated background work per runtime/component and introduced explicit APIs, grants and acyclic dependencies. Frontend features load on demand and can retry locally.
- Preserved old fields and extension data while narrowing storage reads and reusing unchanged shards. Storage benchmarks improved; actual answer writes did not yet show a clear speedup.

## 2.0.0-alpha.1 — 2026-10-01

- Introduced separately installable capability plugins, public APIs, original source files and versioned selections, reviewed incremental deck additions, and complete backups retaining original files.
- Existing libraries with absent optional fields remain readable. Audio runs independently and publishes through the materials API when available.

Earlier 1.x release details, validation records and limitations are preserved in the [complete Chinese history](CHANGELOG.zh-CN.md).
