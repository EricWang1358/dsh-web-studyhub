- **Coverage runs of multiple-choice questions are now written in one pass by default (出题方式 under 高级生成控制: 「快速铺题（默认）」 or 「逐题精出」).** The sections of each round's plan are packed into portions of at most about 9,000 characters and 12 questions (a section is never cut); one call per portion writes every section's full cards, told the number per section and never a total. The program then checks each card without a model: its quote must stand in its section, exactly one option is correct, no second card on the same quote or objective, at most the section's quota, and the options are shuffled by the program. A section left with no card is asked again once, alone. A card whose correct option is more than 25% longer than the longest wrong one is sent back once for its options to be rewritten (one call per portion) and dropped if it still stands out. The review judges at most 7 cards per call, each from its quote and about 350 characters on each side, never the whole material; a card it fails is dropped. Cards on the same objective from portions written at the same time are merged afterwards. The draft keeps the same records as before: each card's section, the plan's targets and what became of each, sections still short as plan-short failures, rounds and round limit, failures in words, and token usage; every call is a step in the 任务 console. The forecast of a one-pass run is a range (the plan is the upper end). Other question types, case papers, runs by a number of questions and the rewriting of failed targets in a top-up still use the staged pipeline, as does any run when 「逐题精出」 is chosen. Not verified: runs of the product code against a real model (only the recorded prototype measurements and fake-model tests), and PDF material; the token estimate still prices the staged pipeline, so it overstates a one-pass run.
