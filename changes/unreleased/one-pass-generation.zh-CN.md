- **按覆盖强度出的单选题，默认改为一次写完（「高级生成控制」里的「出题方式」：「快速铺题（默认）」或「逐题精出」）。** 每轮计划的小节按顺序装进一份份资料，每份最多约 9,000 字、12 道题，小节从不切开；每份只调用一次模型，按每个小节各自的题数写出完整的题，从不告诉模型总题数。写题要求用情景题：挑学生必须会用的内容（规则连同它的条件或例外、容易混淆的两件事、原因与后果、讲顺序的步骤），用一个短小具体的情景让关键条件决定答案，解析分四步讲清。之后由程序逐题核对，不用模型：引文必须出现在它所属的小节里，正确选项恰好一个，同一句引文或同一考点不出第二道，每个小节不超过它的题数，选项顺序由程序打乱。一道题都没有的小节单独再问一次。正确选项比最长的错误选项长出 25% 以上的题，整份资料一起送回改写一次选项，仍然偏长就舍去。审阅每次最多看 7 道题，每道只带它的引文和前后各约 350 字原文，不带整份资料；审阅不通过的题直接舍去。同时写出的几份资料里考同一考点或同一句引文的题，最后由程序合并去重；再用一次调用把整轮的题按「考同一事实」分组，每组只留第一道。模型回复读不成 JSON 时先再问一次，仍不行才放弃这一步。草稿里记录的内容与原来一样：每道题所属的小节、计划的考点和每个考点的去向、仍然缺题的小节（记为 plan-short 失败）、轮次与轮次上限、用文字说明的失败原因、每次调用的 token 用量；每次调用都是「任务」控制台里的一步。快速铺题的题数预估改为一个范围（计划题数是上限）。其他题型、案例题、按题数出题、补题时重写已失败的考点，仍走逐题精出流程；选了「逐题精出」时所有出题都走原流程；续出沿用草稿当时的出题方式，旧版本留下的草稿续出仍走逐题精出。未验证：产品代码接真实模型的运行（只有原型的实测记录和模拟模型测试），以及 PDF 资料；token 预估仍按逐题精出计算，会高估快速铺题的用量。
