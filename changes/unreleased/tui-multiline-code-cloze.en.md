- **Blanks inside code blocks now open a multi-line input in the terminal (TUI).** A blank that sits inside a fenced code block (``` or ~~~ in the card text) gets a multi-line box: `Enter` inserts a newline, `Ctrl+S` goes to the next blank and submits the card on the last one (the same step `Enter` takes in a normal blank), `Tab` moves to the next blank and `Esc` leaves the box. Normal blanks stay single-line. The revealed answer and the "yours vs expected" view keep the code's indentation, wrapped lines keep it too, and no literal `**` appears inside code. An answer that differs from the reference only in indentation, trailing spaces or line endings is no longer shown as a mismatch. (#1460)
  - Not verified: tested with in-process terminal tests (Chinese 100x28 and plain ASCII 80x24) and the real grader, not typed in a live terminal window. `Ctrl+Enter` also submits on terminals that report it, but the hints only mention `Ctrl+S` because Windows console sends a plain line break for it.
