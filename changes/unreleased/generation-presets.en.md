- **创建题组 now offers three ways to write a deck, 出题方式: 「快问」 (Quick), 「情境题」 (Scenario, the default) and 「逐题精出」 (Step by step).** They are the main path's one choice in place of 覆盖强度. 「情境题」 is standard coverage written in one pass in the scenario style: the same as the default before. 「快问」 is lean coverage written in one pass with one short question per point. 「逐题精出」 is standard coverage written by the staged pipeline. Each preset is a cell of two settings that can also be chosen apart, under 更多选项 › 出题方式与题量: 覆盖强度 (精简 / 标准 / 完整 / 自定义, the same levels and densities as before, with 自动补到完整) and the new 出题深度 (快问 / 情境题 / 逐题精出). A combination that is no preset is shown as 「自定义」 on the main path, with both halves named. A typed number of questions or 自动补到完整 chosen by hand opens 更多选项, so nothing you set is hidden. With any other question type ticked, the depth does not apply (other types are always written by the staged pipeline): the presets are switched off and say why, and only 覆盖强度 counts.
  - **Rough cost beside each choice.** Once materials are chosen, the main path shows each preset's cost relative to 「情境题」, as 「约 ×0.6」, and in brackets how many questions it plans; the chosen one's count stays beside the button. With 更多选项 open, a table shows the same for all nine combinations, and the form's own cell is marked. Each ratio is the upper end of the token estimate of that combination for the chosen materials, divided by the default's; it is never a fixed multiple. A hover card explains that the ratio is rough and depends on the model. It also explains two limits: 「逐题精出」 plans fewer questions per 10,000 characters, so a whole run can cost less while each question costs more; and the saving of 「快问」 is assumed, not measured. With no material chosen, no ratio is shown. With a typed number of questions, the main path reads 「自定义」 with that number (for example 40 questions × 情境题), and no ratio or table is shown: every ratio is the estimate of a coverage level, not of the number you typed.
  - **The write style is a real setting.** In 设置 › 高级生成控制, one 出题深度 control replaces 出题方式; it saves both the strategy and the write style. A library saved on 「逐题精出」 reads as 逐题精出. A library with 采纳审阅建议 on and no saved strategy also reads as 逐题精出. Saved values stay valid. A choice on the form applies to that run only. A one-pass draft records its write style, so continuing or topping it up keeps it. A one-pass draft from before this change is treated as 情境题. A staged draft records no style. The style is used on every one-pass write call: the first write, the second ask after a reply that is not JSON, the second ask for a section left empty, and the fill-round rewrite of a portion. 深度定制 always uses 逐题精出. After a failed run, 按原资料重新设置 puts back the depth that run used; a single-choice job from before this change did not record it, and the notice says so.
  - Not verified: the token estimate prices 「快问」's write output at 1/1.15 of 「情境题」's. That factor comes from the prototype measurement of the two prompts and has not been measured in the product. No run against a real model has checked the ratios or the 「快问」 question counts.
